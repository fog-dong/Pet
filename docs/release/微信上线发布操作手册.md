## 1. 服务器与域名（先把 `https://pet.jiangker.cn` 打通）

详细命令在 [../../deploy/README.md](../deploy/README.md)（300 行，含 compose、`.env`、Nginx、GitHub Actions），这里只列卡点顺序：

1. **ICP 备案**：域名必须已完成工信部备案，且备案主体与小程序主体一致或可解释。未备案的域名微信后台**存不进合法域名**。
2. **HTTPS 证书**：微信要求 `https`，证书链要完整（`fullchain.pem`）。用 certbot 签一次，或复用你现有证书。自签证书在开发者工具里能勾「不校验」蒙过去，**真机和审核一定过不去**。
3. **数据库**：一个 PostgreSQL 库 + 一个有建表权限的用户。建表不用手写——服务启动时自动执行 `server/migrations/001_init.sql`，会建 **16 张表**（users / hospital_state / pets / adoptions / pets_cases / config / leaderboard / assist_pairs / assist_daily / ad_events / ad_daily / track_events / sync_pending / habitat_state / habitat_claims / orders）。
4. **起服务**：`/root/docker/pet-game/` 放 `docker-compose.yml` + `.env`，`.env` 四个必填真值：

   | 键 | 填什么 | 注意 |
   |---|---|---|
   | `HOST_PORT` | `18766` | 反代指向它；**不要再写 `PORT=`** |
   | `DATABASE_URL` | `postgres://pet:真密码@host.docker.internal:5432/pet` | 用户在宿主机，容器内用 `host.docker.internal` |
   | `WX_APPID` / `WX_SECRET` | 小游戏 AppID / AppSecret | **生产必须配**；不配则走开发 openid，登录态是假的 |
   | `JWT_SECRET` | 长随机串 | 换掉会让全部旧 token 失效 |

   `WX_SECRET` 与 `JWT_SECRET` 属于密钥，只进服务器 `.env` 和 GitHub Secrets，**永远不进 Git 仓库**。
5. **Nginx 反代**：`pet.jiangker.cn:443` → `127.0.0.1:18766`。

**看到这两条才算第 1 步完成**（在自己的电脑上跑，不用等微信后台）：

```bash
curl https://pet.jiangker.cn/health
# 期望：HTTP 200，body 里有健康状态字段

curl -X POST https://pet.jiangker.cn/api/login -H 'Content-Type: application/json' -d '{"code":"dev"}'
# 期望：HTTP 200，body 形如 {"code":0,"msg":"ok","data":{...token...},"serverTime":1730000000000}
```

如果 `/health` 通、`/api/login` 报 5xx，先查容器日志（`docker logs pet-api`）和 `DATABASE_URL`。

## 2. 服务器域名白名单（微信公众平台）

入口：**微信公众平台 → 我的小程序 → 开发管理 → 开发设置 → 服务器域名**（登录账号需是该小程序的开发者/管理员）。

| 栏位 | 要填 | 本版是否需要 |
|---|---|---|
| **request 合法域名** | `https://pet.jiangker.cn` | ✅ **必填**。客户端唯一网络出口是 `net/NetHttp.ts` 的 `wx.request` |
| uploadFile 合法域名 | —— | ⚪ 不需要：全项目无 `wx.uploadFile` |
| downloadFile 合法域名 | —— | ⚪ **不需要**。代码里只有 `wx.cloud.downloadFile`（云存储下载，走微信自己的域名，不占这一栏），且本版 `CLOUD_ENV` 保持占位、云开发整体不启用 |
| socket 合法域名 | —— | ⚪ 不需要：无 `createWebSocket` |

操作要点：

1. **修改次数有上限**（平台限制，历史上为每月 5 次，以后台页面实时提示为准），改之前想清楚，别反复试。
2. 只填 `https://` 开头、不带路径、不带端口、不带尾斜杠的**根域名**。填 `https://pet.jiangker.cn/api/` 会报错。
3. 域名必须已备案，否则保存时报「该域名不符合规范」。
4. 保存后**在开发者工具里必须重新登录 + 重新编译**，白名单才会生效。
5. 校验方法：开发者工具 → 详情 → 本地设置，**不要**勾「不校验合法域名」。勾着能跑，不代表线上能跑——审核和真机都是校验态。

## 3. 隐私与合规配置

### 3.1 三份协议 H5 + 客服 URL（要改代码并重建）

当前代码里是合法占位域名 `example.com`，**审核点开会是别人的网站或打不开**，必须替换。

改法只有一处文件：`assets/scripts/config/LegalConfig.ts`，它把占位域抽成了一个常量：

```ts
export const PLACEHOLDER_HOST = 'example.com';   // ← 换成你的真实协议托管域名，如 'legal.jiangker.cn'
```

四个 URL 会跟着变（路径写死在代码里，别让运营给你别的 path）：

| 用途 | 替换后必须能打开的页面 |
|---|---|
| 隐私政策 | `https://<你的域名>/privacy` |
| 用户协议 | `https://<你的域名>/agreement` |
| 未成年人保护 | `https://<你的域名>/minors` |
| 微信客服 | `https://<你的域名>/customer-service` |

注意两点：
- 代码里有守卫 `isLegalDocsConfigured()`：URL 以 `https://` 开头**且不含 `example.com`** 才算配好。填 `https://example.com.你的域名` 这类 trick 会被判未配。
- 协议页必须是**能直接访问的 H5**，不要需要登录、不要跳转小程序。
- 客服 URL 建议用公众平台「微信客服」功能开通后官方下发的链接，别自己搭。
- 改完 → 重新执行第 5 步构建上传。

### 3.2 后台「用户隐私保护指引」（不改代码）

入口：**微信公众平台 → 设置 → 基本设置 → 服务内容声明 → 用户隐私保护指引**（或「开发管理 → 隐私相关」，两版后台都见过）。

要申报的采集项，**按刚从代码里扫出来的真实平台 API 清单填**（下表就是 `assets/scripts` 里 `wx.*` 的全部调用点，一条不多一条不少）：

| 采集项 / 权限 | 本项目真实调用点 | 是否要申报 |
|---|---|---|
| 用户 OpenID | `wx.login`（3 处：`net/Net.ts` 登录链路）+ `POST /api/login` | ✅ **必须申报**，这是唯一的身份采集 |
| 微信昵称、头像 | **代码里不采集**：全项目无 `wx.getUserProfile` / `wx.getUserInfo` 调用；服务端 `users.nickname` 默认空串，排行榜显示的是 `nickname ?? displayId` | ⚪ 不申报（勾了反而对不上实际行为） |
| 相册（写入）、摄像头、麦克风、位置 | **一处都没有**：无 `saveImageToPhotosAlbum`、无 `chooseImage`、无 `getLocation` | ⚪ 全部不申报 |
| 设备信息 | **代码里没有主动读取**：无 `getSystemInfo` / `getDeviceInfo` / `benchmarkLevel` 命中。画质档位由远程配置的 `quality=low` 驱动（`config/Quality.ts`），低端动效裁剪靠 `AudioConfig` 的 `essential` 字段，全程不读设备标识 | ⚪ 不申报主动采集 |
| 网络请求 | `wx.request`（1 处，`net/NetHttp.ts`）指向 `pet.jiangker.cn` | 属第 2 步域名栏，不在隐私采集项里 |
| 分享 | `wx.shareAppMessage`（2 处，`net/Share.ts:18`，好友助力用） | ⚪ 不涉及个人信息采集 |
| 广告标识 | `wx.createRewardedVideoAd`（2 处，`net/Ad.ts`） | 若第 4 步接了真广告位，按平台要求申报广告相关项 |
| 本地存储 | Cocos `sys.localStorage`（存档 `pet_save_v1`）+ `wx.setStorageSync` | 本地缓存，非个人信息上传 |

原则：**勾了才允许调；没调的别勾**。申报与实际调用不一致（多报或漏报）都是这个类目的常见拒审理由。本项目刻意做成「只拿 OpenID」的最小采集面，就是为了让这一栏好过。

### 6.2 「有没有内购」怎么答（你最关心的问题）

**代码事实**：`net/Pay.ts` 的 `createOrder()` 固定返回 `{ code: 'PAY_UNAVAILABLE' }`，源码注释明确禁止调用 `wx.requestMidasPayment` 或任何真实虚拟支付；服务端 `/api/createOrder`、`/api/payCallback` 同样是不可用态（iOS 侧另有 `3002 PAY_UNAVAILABLE` 红线）。全项目无商品定价、无发货、无补单逻辑。

所以：

| 问题 | 你的选择 | 为什么这么答 |
|---|---|---|
| 是否包含虚拟支付/内购 | **否 / 无内购** | 代码里真的点不出付费入口，UI 也没有任何商品卡 |
| 变现方式 | **仅广告（激励视频）** | 与 `AdConfig` + `net/Ad.ts` 一致 |
| 类目 | **游戏** 类目下按后台可选项选最贴近的（本项目是休闲/模拟经营向的宠物养成），**不要**选「角色扮演」等需要额外版号材料的大类目 | 类目要能被截图证明：审核员看到的是大厅 + 接诊 + 小屋 |
| 资质材料 | 后台要求什么交什么（通常至少《计算机软件著作权登记证书》；**一旦涉及虚拟支付才会要版号**）。具体清单以你提交页面实时提示为准 | 平台政策会变，我不替你猜 |

**审核员追问时的话术**（照抄即可）：

> 本小游戏为纯单机养成 + 广告变现（激励视频），不含任何形式的虚拟支付、内购商品、代币充值或第三方支付跳转；代码层面的支付接口固定返回不可用，界面内无可购买项、无价格展示。 iOS 端同样不提供付费能力。游戏内全部奖励来自观看激励视频广告与玩法结算。

**不要**为了「以后要接内购」在提审版本里留隐藏入口或写「联系客服充值」的话术——那是明确违规，且会连累主体。
