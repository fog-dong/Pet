# 历史清理操作单（git-filter-repo）

| 项目 | 内容 |
|---|---|
| 关联事件 | SEC-2026-10-30-01（见《口令泄露处置记录.md》） |
| 前置 | **旧凭据已吊销并验证失效**；未吊销前不得执行本单 |
| 性质 | 可选、破坏性、需协调；改写全部 commit hash |
| 执行边界 | 全部命令由仓库所有者亲自执行；AI 不代为执行 force push |
| 影响 | 远端所有分支与 tag 被重写；任何已有 clone 必须重新 clone，旧 clone 的 push 会被拒 |

## 0. 执行前必须确认

- [ ] 旧凭据已吊销，`git ls-remote origin` 用旧凭据已被拒（401）。
- [ ] 已通知所有 clone 过仓库的机器/协作者（本项目目前仅作者一台机器，成本低）。
- [ ] 已备份：远端无需额外备份，但本地保留一份完整 clone 作为回滚点。
- [ ] 选好方案（见 §2），且确认要删/改的路径与提交范围。

## 1. 备份与安装

```bash
# 1.1 备份 clone（放到仓库外，别在 pet/ 目录里操作）
git clone --mirror https://github.com/fog-dong/Pet.git pet-backup.git

# 1.2 安装 git-filter-repo（需要 Python 3.8+）
py -m pip install --user git-filter-repo
git filter-repo --version      # 能打印版本即可

# 替代安装：scoop install git-filter-repo / winget install git-filter-repo（若已配置）
```

## 2. 两个方案

### 方案 A（推荐）：只替换口令字符串，保留文档

```bash
# 2.1 在仓库外写替换表达式文件，一行一条；不要把该文件提交进仓库
#     文件内容形如：<旧值>==>***REMOVED***
#     放到例如 %TEMP%\replace.txt，用编辑器写入，避免留在 shell 历史

# 2.2 在仓库根执行
cd /c/Users/15181/Desktop/项目/pet
git filter-repo --force --replace-text "/c/Users/15181/AppData/Local/Temp/replace.txt"

# 2.3 复核：历史里是否还能检出旧值（期望 NO_HIT）
git grep -nI "<旧值>" $(git rev-list --all) -- . || echo "NO_HIT"
```

优点：`docs/plan/架构质检-W11.md` 的其余内容与提交历史结构保留（hash 仍会变）。
注意：`--replace-text` 是按字节替换，替换后会重新计算所有受影响 blob 的 hash。

### 方案 B（不推荐）：整份文件从历史移除

```bash
git filter-repo --force --invert-paths --path docs/plan/架构质检-W11.md
```

代价：W11 报告从所有历史中消失（当前工作区文件仍在，但会变成“未被任何历史包含”的新文件），跨文档引用失效。只有在方案 A 无法满足时才用。

## 3. 推送（破坏性）

```bash
# 3.1 filter-repo 默认会删掉 origin 远端，需要重新添加
git remote add origin https://github.com/fog-dong/Pet.git
git remote -v

# 3.2 覆盖远端全部分支与 tag
git push --force --all origin
git push --force --tags origin

# 3.3 清理本地残留对象
git reflog expire --expire=now --all
git gc --prune=now --aggressive
```

- 本项目约定禁止 force push，**本单是唯一例外**，且必须有本次事件记录作为授权依据。
- 不能用 `--force-with-lease`（它会因远端与本地历史不同而拒绝），全量重写只能用 `--force`。

## 4. 收尾

- [ ] 在仓库外重新 `git clone` 一份，确认 `git log --oneline -S "<旧值>"` 无命中。
- [ ] 确认 `git log --oneline | head` 的提交数与内容符合预期（顺序与提交信息不变，hash 全变）。
- [ ] 旧的工作目录若继续使用，需要 `git fetch --all && git reset --hard origin/main`（会丢弃未提交改动，执行前先 `git status`）。
- [ ] 在《口令泄露处置记录.md》§4 勾选「已清理」，并在 §1 更新状态。
- [ ] 通知任何其他 clone 过的机器重新 clone。

## 5. 回滚

- 本地：从 §1.1 的 `pet-backup.git` 恢复。
- 远端：若已 force push，理论上只能再从备份 mirror push 回去（同样需要 force）；因此备份必须先做。

## 6. 明确不做

- 不使用 `BFG Repo-Cleaner`（与 filter-repo 二选一，避免两套工具混用）。
- 不为了“看起来干净”而重写与本次事件无关的提交内容。
