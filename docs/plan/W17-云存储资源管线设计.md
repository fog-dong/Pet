# W17 云存储资源管线设计

> 状态：W17 设计 + 最小实现（客户端 `CloudResManager` + `getConfig` 下发清单）。
> 边界：本阶段不改玩法、不接真实 CDN 管控台；无网络/无清单时必须保持占位并可正常游玩。
> 依据：00 §16 执行边界、09 §5 云存档、10 §3.8 `config` 集合；本文件新增 `resource_manifest` 配置键。

## 1. 目标

1. **包体可控**：高频小资源进分包，低频大资源放云存储，按需下载，主包不因美术/音频增长而膨胀。
2. **首屏不阻塞**：清单随 `getConfig` 异步到达；资源未就绪显示占位，下载失败不白屏、不卡死。
3. **可版本化**：清单与单文件都带版本；客户端按 `key + version + size` 判断是否需要重新下载。
4. **可回滚**：清单在 `config` 集合内按版本发布，回滚=切回上一版 active，客户端下次启动自动收敛。

## 2. 资源分类与归属

| 分类 | 典型内容 | 大小/频率 | 归属 | 加载方式 |
|---|---|---|---|---|
| 宠物立绘 | `pets/{name}.png` 静态立绘 | 单张 100–400KB，高频 | 优先 **art 分包**；新增/高清立绘走云存储 | 分包 `bundle.load`；缺失时云下载 |
| 动作帧 | 待机/生病/康复/开心/休息帧序列 | 单套 1–6MB，中低频 | **云存储** | 首次展示时下载，本地缓存 |
| 环境音效 | 诊所底噪、雨声、候诊室 | 单条 200KB–1MB，低频 | **云存储** | 首次进入场景时下载 |
| 动物叫声 | 猫/狗/兔/鸟的轻叫、治疗成功叫声 | 单条 20–120KB，中频 | **云存储** | 触发时下载（首帧可静音） |
| UI 音效 | 点击、金币、翻页、确认 | 单条 5–40KB，高频 | **art 分包内 `audio/ui/`** | 随分包加载，零网络等待 |
| 活动素材 | 节日皮肤、活动横幅 | 单套 1–10MB，极低频 | **云存储** | 活动开启时下载，活动结束可清 |

判定规则：

- **单文件 ≤ 100KB 且每次会话必用** → 分包（UI 音效、图标）。
- **单文件 > 100KB 或非每次会话必用** → 云存储（动作帧、环境音、动物叫声、活动素材）。
- 任何新增资源必须先登记清单或分包，禁止在业务代码里写裸路径（见 §6）。

## 3. 存储方案

### 3.1 服务端

- 原文件统一放微信云开发**云存储**，目录约定：
  - `pet-res/pets/{name}_v{n}.png`
  - `pet-res/actions/{pet}/{state}_v{n}.png`
  - `pet-res/audio/pets/{species}_{cue}.mp3`
  - `pet-res/audio/ambient/{scene}.mp3`
  - `pet-res/activities/{activityId}/{file}`
- 清单由运营生成（MD5 + size + version），写入 `config` 集合 `configKey='resource_manifest'` 的 `payload`，`status='active'`。
- 客户端只读清单；不直连存储目录列表（避免额外权限与枚举成本）。

### 3.2 客户端

```
getConfig → payload.resource_manifest
    → CloudResManager.setManifest()   // 只存内存 + 本地清单副本，不下载
按需 ensure(key)
    → 命中本地索引且 version/size/MD5 匹配 → 直接返回本地路径
    → 未命中/过期 → wx.cloud.downloadFile(fileID)
        → 写入 USER_DATA_PATH/cloudres/{key}_v{version}.{ext}
        → 记录索引 { path, size, version, lastUsed }
        → 超过 LRU 上限时按 lastUsed 淘汰
```

- 本地根目录：`wx.env.USER_DATA_PATH/cloudres/`。
- 索引：`sys.localStorage['pet_cloud_res_index_v1']`；清单副本：`['pet_cloud_manifest_v1']`。
- 校验：优先 `getFileInfo(digestAlgorithm:'md5')`；平台不支持时退回 `stat.size === manifest.size`。
- 上限：**32MB** / 条目 **30 天**未访问可淘汰；单次下载超时 15s。
- 禁止把资源写进包内目录或存档命名空间；缓存目录独立，清理不影响存档。

## 4. 分包策略

| 位置 | 内容 | 预算 |
|---|---|---|
| 主包 | 脚本、首屏 UI、Boot/Lobby 必要资源 | ≤ 4MB（硬约束） |
| `cases` 分包 | 病例配置与诊断页资源 | 随首屏加载，≤ 2.5s 超时 |
| `art` 分包 | 静态宠物立绘、UI 音效、通用图标 | 按页引用计数 |
| `ui` 分包 | 通用 UI 贴图 | 按页引用计数 |
| 云存储 | 动作帧、动物叫声、环境音、活动素材 | 按需，不占总分包 30MB |

原则：**“每次会话必用 + 小”进分包；“低频/大/可运营替换”进云存储**。新增资源先算体积再决定归属，不得先塞主包。

## 5. 版本管理

### 5.1 清单结构（`config.payload`）

```json
{
  "version": 3,
  "files": [
    {
      "key": "pet_bichon",
      "path": "cloud://<env>.pet-res/pets/bichon_v2.png",
      "kind": "image",
      "md5": "9f2c0f5d0c1f4a0f8f4c2f7a1b3d5e6c",
      "size": 184320,
      "version": 2
    },
    {
      "key": "pet_cat_soft",
      "path": "cloud://<env>.pet-res/audio/pets/cat_soft_v1.mp3",
      "kind": "audio",
      "md5": "1a2b3c4d5e6f708192a3b4c5d6e7f809",
      "size": 48213,
      "version": 1
    }
  ]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `version` | int | 清单版本，单调递增；仅用于诊断与灰度，不参与单文件命中判断 |
| `files[].key` | string | 逻辑键，客户端唯一引用；`pet_{artName}` 约定用于立绘 |
| `files[].path` | string | 云存储 fileID 或 HTTPS URL；扩展名决定资源类型 |
| `files[].kind` | `image` / `audio` | 与扩展名双重校验 |
| `files[].md5` | string | 文件 MD5（小写）；为空时退回 size 校验 |
| `files[].size` | int | 字节数；下载后必须匹配 |
| `files[].version` | int | 单文件版本；变化即视为需要重新下载 |

### 5.2 发布与回滚

1. 上传新文件到云存储（文件名带 `_v{n}`，旧文件保留至少 2 个版本）。
2. 新建 `config` 文档：`configKey='resource_manifest'`、`version=清单版本`、`payload=上述 JSON`、`status='active'`；同键旧文档置 `archived`。
3. 灰度沿用 `grayTags` / `grayPercent`；`getConfig` 已实现按 openid 分桶。
4. 回滚：把上一版文档置 `active`，客户端下次 `getConfig` 收敛；本地旧缓存按 LRU 自然淘汰，不强制删除，避免回滚期二次下载。

### 5.3 客户端增量判断

- 命中条件：`本地记录.version === entry.version && 本地记录.size === entry.size && 文件存在`。
- 任一不满足 → 删除旧文件并重新下载（不做二进制 diff，资源粒度已足够小）。
- 清单中移除的 key 不再被引用；对应本地文件由 LRU/过期清理回收。

## 6. 客户端接入点

| 位置 | 行为 |
|---|---|
| `BootCloud.loadQuality()` | `getConfig` 返回后调用 `CloudResManager.setManifest(configs.resource_manifest)`；不 await 下载 |
| `Lobby` 回厅 `refreshQuality()` | 再次拉配置时同步刷新清单，运营改清单后下一次回厅生效 |
| `PetAssetManager.loadPetFrame()` | 先 `art` 分包；缺失时 `CloudResManager.loadSpriteFrame('pet_{name}')` |
| `PetVisual` | 下载期间保持“加载中…”占位；失败保持占位并记 `pet_cloud_missing`，不抛错 |
| 音频（W17-3） | 触发时 `CloudResManager.ensure(key)` 取本地路径，再交给播放器；失败静音 |

降级矩阵：

| 场景 | 行为 |
|---|---|
| 未同意隐私 / 云端关闭 | 不初始化 `Net`，`CloudResManager` 始终空清单，全部走本地分包/占位 |
| 清单缺失或格式非法 | 记录 `cloud_res_manifest_invalid`，保持空清单，不重试轰炸 |
| 下载失败/超时 | 返回 null，调用方占位；同一 key 连续失败 3 次后本次会话不再重试 |
| 磁盘写入失败 | 返回 null，不写索引，不破坏已有缓存 |
| `Quality.low` | 不改变资源正确性，仅影响动效与非必要音频（见 W17-3） |

## 7. 运维操作（提审前人工）

1. 云存储上传文件，记录 fileID、MD5、size。
2. 云开发控制台新建 `config` 文档（`resource_manifest`），`status='active'`，`grayPercent=100`。
3. 微信开发者工具清缓存重编译，确认 Console 无新增红色报错；冷启动后观察 `cloud_res_manifest_*` 埋点。
4. 灰度验证：先 `grayPercent=10`，确认下载成功率后再全量。

## 8. 验收清单

- [ ] 无清单/断网时，Boot → Lobby → 单局全流程可玩，宠物位显示占位而非白屏。
- [ ] 清单命中且资源已缓存时，不再发起 `downloadFile`。
- [ ] 单文件版本变化后，旧缓存被替换，索引 `version`/`size` 更新。
- [ ] 缓存总量超过 32MB 时，按 `lastUsed` 淘汰最旧文件。
- [ ] 业务代码中没有硬编码资源 URL/路径；所有 key 可在清单或分包常量中检索到。
- [ ] `tsc --noEmit` ×3 通过；云函数 `getConfig` 白名单包含 `resource_manifest`。
