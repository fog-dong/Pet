## 2. 云开发控制台准备

1. 创建云环境：测试环境与正式环境分开；环境 ID 只记录在本地备忘，不写入仓库与文档。
2. 运行配置：11 个函数统一 5 秒超时、256MB 内存；`leaderboard` 若数据量大再单独上调。
3. 环境变量（仅 `login` 需要，但建议全部函数统一配置）：
   - `SESSION_SECRET`：32 位以上随机串，用于 HMAC 签名 token；缺失时 `login` 抛 `SESSION_SECRET_MISSING`，客户端会走本地兜底。
   - 变量只在控制台配置，不写进代码、`.env`、文档或提交记录。
4. 数据库集合与索引（先建集合与普通索引，再建唯一索引，详见《集合与索引冻结》）：
   - 核心：`users`、`hospital_state`、`pets_cases`、`pets`、`adoptions`、`ad_events`、`orders`、`config`、`leaderboard`。
   - 辅助：`assist_pairs`、`assist_daily`、`track_events`、`delivery_logs`（W8 起 `assist_logs` 只读历史，不再写入）。
   - W8 必须到位：`assist_pairs._id = targetId_helperId_date`、`assist_daily._id = targetId_date`、`ad_events._id = openid:adSessionId`、`track_events._id = openid:batchId` 均靠主键去重，不需要额外唯一索引；`leaderboard` 的 `uniq_type_period_openid` 唯一索引与 `idx_type_period_score` 组合索引仍需创建；`track_events` 建议配 30 天 TTL。
   - 权限：客户端全部关闭直读直写，只允许云函数服务端身份读写。
5. 若 `config` 集合为空，`getConfig` 返回空配置，客户端继续用本地默认值（含 `quality=high`），不阻塞进厅。

**榜单写入说明**：W7 只实现了读取与分页，`leaderboard` 集合暂无服务端写入方；控制台看到「暂无排行」属正常。W8 接入结算写入后再验收真实榜单。

## 5. 客户端切换联调

1. 本地临时把 `assets/scripts/config/EnvConfig.ts` 的 `CLOUD_ENV` 改成测试环境 ID，**联调后改回 `ENV_PLACEHOLDER` 再提交**。
2. 构建时注入正式 AppID（命令见《提审前人工操作单》§2），产物 `build/wechatgame/project.config.json` 核对 appid。
3. 真机 / 开发者工具确认：不再出现 `boot_cloud_offline_fallback`；结算后 `syncCaseResult` 返回 `code: 0`；断网结算会写入待补发队列，下次启动自动补发。
4. 助力验证：联网时点击「分享求助」→ `assist` 返回 `granted: true`；断网时本地到账并出现 `assist_pending`，次日联网启动后 `assist_flushed`；服务端返回 `1005` 时客户端直接提示「今日助力次数已用完」，不再本地发奖。
5. 埋点验证：大厅停留 20 秒后回 `track_events` 看批次；切到后台应立即出现最后一批。上报失败（断网）时队列整批回到队首，最多保留 200 条。
6. 广告验证：看完一条激励视频后 `ad_events` 出现 `isEnded=true`、`granted=true` 的记录；未看完的记录 `isEnded=false` 且不计入当日额度。

## 6. 回滚

1. 云函数：云开发控制台 → 函数详情 → 版本管理 → 回退到上一可用版本。
2. 客户端：`CLOUD_ENV` 改回 `ENV_PLACEHOLDER` 重新构建，走本地模式；不要删除云端集合与数据。
3. 数据库：`assist` 与 `adEvent` 的去重都靠集合主键 `_id`，回退函数版本即可回退行为，不需要回滚索引；`track_events` 属统计集合，回滚期间可只删函数、保留数据。
