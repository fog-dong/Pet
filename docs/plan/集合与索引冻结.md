## 1. 冻结规则

- 客户端不直连数据库；所有读写经云函数。
- 金额为整数分；时间为毫秒时间戳；软删除用 `status`。
- 唯一索引必须先于业务写入创建；稀疏唯一索引需在控制台确认空值行为。
- 集合与索引变更需服务端主程 + 制作人确认，并记录影响函数。

## 3. 冻结新增/调整集合

### 3.1 `pets`

| 字段 | 类型 | 必填 | 说明 | 索引 |
|---|---|---|---|---|
| `_id` | string | 是 | 文档 ID | 主键 |
| `petId` | string | 是 | 宠物唯一 ID | 唯一 `uniq_pet_id` |
| `openid` | string | 否 | 当前归属用户；未领养为空 | 组合 `idx_openid_status` |
| `breed` | string | 是 | 物种/品种 | 普通 `idx_breed` |
| `name` | string | 是 | 玩家命名或默认名 | — |
| `rarity` | enum | 是 | common/rare/epic | — |
| `storyId` | string | 是 | 专属故事 ID | — |
| `affection` | int | 是 | 长期好感度 | — |
| `status` | enum | 是 | in_hospital/adopted/released | 组合 `idx_openid_status` |
| `adoptedBy` | string | 否 | 领养人 openid | 普通 `idx_adopted_by` |
| `caseSessionId` | string | 否 | 来源病例单局 ID | 普通 `idx_case_session` |
| `careScore` | int | 是 | 领养时照料评分 | — |
| `createdAt` | int64 | 是 | 创建时间 | — |
| `updatedAt` | int64 | 是 | 更新时间 | — |

**约束：** `status=adopted` 时 `adoptedBy` 必填；`status!=adopted` 时 `adoptedBy` 必须为空；同一 `petId` 最多一条有效领养关系。

### 3.2 `adoptions`

| 字段 | 类型 | 必填 | 说明 | 索引 |
|---|---|---|---|---|
| `_id` | string | 是 | 文档 ID | 主键 |
| `adoptionId` | string | 是 | 领养关系 ID | 唯一 `uniq_adoption_id` |
| `cardId` | string | 是 | 图鉴卡展示 ID | 唯一 `uniq_card_id` |
| `openid` | string | 是 | 领养人 | 组合 `idx_openid_adopted_at` |
| `petId` | string | 是 | 关联 `pets.petId` | 唯一 `uniq_pet_id` |
| `adoptedAt` | int64 | 是 | 领养时间 | 组合 `idx_openid_adopted_at` |
| `isFirstAdoption` | bool | 是 | 是否首次获得该物种 | — |
| `sharedCount` | int | 是 | 自愿分享次数 | — |
| `status` | enum | 是 | active/released | 普通 `idx_status` |

**约束：** 不存 `petSpecies/petName/rarity/storyId/careScore`；展示时按 `petId` 读 `pets`。`cardId` 与 `petId` 一对一。`status=released` 时保留关系，不物理删除。

### 3.3 `ad_events`

| 字段 | 类型 | 必填 | 说明 | 索引 |
|---|---|---|---|---|
| `_id` | string | 是 | 文档 ID | 主键 |
| `idempotencyKey` | string | 是 | `openid:adSessionId` | 唯一 `uniq_idem_key` |
| `adSessionId` | string | 是 | 广告会话 ID | 普通 `idx_ad_session` |
| `openid` | string | 是 | 归属用户 | 组合 `idx_openid_created` |
| `adUnitId` | string | 是 | 广告位 ID | 组合 `idx_unit_created` |
| `scene` | string | 是 | 场景键 | 普通 `idx_scene` |
| `isEnded` | bool | 是 | 是否完整播放 | — |
| `reward` | object | 否 | `{ type, amount }`；W8 阶段恒为 `null` | — |
| `granted` | bool | 是 | 服务端判定是否授权发奖（W8 追加） | — |
| `dailyCount` | int | 是 | 事件发生时当日已授权次数；`isEnded=false` 记 0（W8 追加，W10-5 明确未看完恒 0） | — |
| `platformDate` | string | 是 | `yyyy-MM-dd` | 组合 `idx_date_unit` |
| `createdAt` | int64 | 是 | 事件时间 | TTL 候选 |
| `reconciled` | bool | 是 | 是否已对账 | 普通 `idx_reconciled` |

**约束：** `_id = idempotencyKey`（`openid:adSessionId`）为主键，插入冲突即重复上报，直接返回首次结果；`idempotencyKey` 字段仍保留唯一索引作为第二道约束；`isEnded=false` 也写记录但不发奖、不占每日额度；`adSessionId` 不再单独唯一。

### 3.4 `leaderboard`

| 字段 | 类型 | 必填 | 说明 | 索引 |
|---|---|---|---|---|
| `_id` | string | 是 | 文档 ID | 主键 |
| `type` | enum | 是 | reputation/collection/weekly | 组合唯一 `uniq_type_period_openid` |
| `period` | string | 是 | `all` 或 `2026-W44` | 组合唯一；组合 `idx_type_period_score` |
| `openid` | string | 是 | 用户 | 组合唯一；组合 `idx_openid_type` |
| `score` | int | 是 | 榜单分值 | 组合 `idx_type_period_score`（降序） |
| `rank` | int | 否 | 服务端名次 | — |
| `updatedAt` | int64 | 是 | 更新时间 | 组合 `idx_type_period_updated` |

**约束：** 只由服务端写入；同一 `type + period + openid` 唯一；前 N 查询按 `score` 降序、`updatedAt` 升序；周榜历史保留可归档。

### 3.5 `assist_pairs`（W8 取代 `assist_logs`）

| 字段 | 类型 | 必填 | 说明 | 索引 |
|---|---|---|---|---|
| `_id` | string | 是 | `targetId_helperId_yyyy-MM-dd` | 主键（天然唯一） |
| `targetId` | string | 是 | 被助力方 openid（取自上下文） | — |
| `helperId` | string | 是 | 助力方 ID（客户端传，不得等于 `targetId`） | — |
| `date` | string | 是 | 北京时间 `yyyy-MM-dd` | — |
| `resourceType` | enum | 是 | medicine/bed/heart | — |
| `nonce` | string | 是 | 客户端幂等随机串 | — |
| `createdAt` | int64 | 是 | 写入时间 | — |

**约束：** 去重靠 `_id` 主键冲突，不做“先查后写”；事务内先按主键读本集合，命中即返回 `ALREADY_ASSISTED`；未命中且未超每日上限才写入本行，超限请求**不写**任何记录（W11-1 起不再有“先插入再删除”的补偿路径）。

### 3.6 `assist_daily`（W8 新增）

| 字段 | 类型 | 必填 | 说明 | 索引 |
|---|---|---|---|---|
| `_id` | string | 是 | `targetId_yyyy-MM-dd` | 主键（天然唯一） |
| `targetId` | string | 是 | 被助力方 openid | — |
| `date` | string | 是 | 北京时间 `yyyy-MM-dd` | — |
| `count` | int | 是 | 当日已成功助力次数 | 仅 `_id` |
| `createdAt` | int64 | 是 | 首次创建时间 | — |
| `updatedAt` | int64 | 是 | 最近累加时间 | — |

**约束：** 计数与 `assist_pairs` 行的写入必须在同一个 `db.runTransaction` 里完成（W11-1 起与 `adEvent` 统一为事务模型）：事务内先判 pair 是否已存在，再读 `count` 判上限，未超限才写 `count + 1` 与本行；超限直接返回 `1005 TODAY_ASSIST_LIMIT` 且不落任何文档。**禁止**使用 `inc(1)` / `inc(-1)` 加减与“先写再回滚”——并发下会整批判超限并整批回退。

### 3.7 `track_events`（W8 新增）

| 字段 | 类型 | 必填 | 说明 | 索引 |
|---|---|---|---|---|
| `_id` | string | 是 | `openid:batchId` | 主键（天然唯一，重复上报回放首次结果） |
| `openid` | string | 是 | 归属用户（取自上下文） | 组合 `idx_openid_date` |
| `batchId` | string | 是 | 客户端批次 ID | — |
| `events` | array | 是 | `[{ event, props, at }]`，单批最多 60 条 | — |
| `count` | int | 是 | 本批通过校验的事件条数 | — |
| `platformDate` | string | 是 | 北京时间 `yyyy-MM-dd` | 组合 `idx_openid_date`、普通 `idx_date` |
| `createdAt` | int64 | 是 | 落库时间 | TTL 候选（建议 30 天） |

**约束：** 事件名限 `[A-Za-z0-9_]{1,40}`；每条最多 8 个属性、属性名限 `[A-Za-z0-9_]{1,24}`、字符串值截断到 64 字符；不存 openid 以外的身份标识，也不存设备号与位置信息。

### 3.8 `ad_daily`（W10-5 新增）

| 字段 | 类型 | 必填 | 说明 | 索引 |
|---|---|---|---|---|
| `_id` | string | 是 | `openid_yyyy-MM-dd` | 主键（天然唯一） |
| `openid` | string | 是 | 计数归属用户（取自上下文） | — |
| `date` | string | 是 | 北京时间 `yyyy-MM-dd` | — |
| `count` | int | 是 | 当日已发奖次数（不含未看完的广告） | 仅 `_id` |
| `createdAt` | int64 | 否 | 首次创建时间 | — |
| `updatedAt` | int64 | 是 | 最近累加时间 | — |

**约束：** 与 `assist_daily` 同构，但计数与 `ad_events` 行的写入必须在同一个 `db.runTransaction` 里完成：事务内先按主键读 `ad_events`，命中即重复上报（回放首次结论、不占额度），未命中才读改写 `count` 并落行。**禁止**用 `where().count()` 先查后写——12 个并发上报会全部读到同一个旧值并集体越上限。上限取 10（新用户 24h 内 5），超限请求记 `granted=false` 且不增加 `count`。

## 5. 幂等键映射

| 业务 | 集合 | 唯一键 | 重复行为 |
|---|---|---|---|
| 单局结算 | `pets_cases` | `caseSessionId` | 返回历史结果 |
| 广告发奖 | `ad_events` | `idempotencyKey` | 与 `ad_daily` 计数同事务：重复上报回放首次奖励与计数 |
| 广告计数 | `ad_daily` | `_id = openid_date` + 事务内读改写 | 超当日上限记 `granted=false`，`count` 不增加 |
| 下单 | `orders` | `clientOrderId` | 返回原订单 |
| 支付回调 | `orders` | `transactionId` | 直接应答成功，不重复发货 |
| 助力 | `assist_pairs` | `_id = targetId_helperId_date` | 与 `assist_daily` 计数同事务：返回 `ALREADY_ASSISTED` |
| 助力计数 | `assist_daily` | `_id = targetId_date` + 事务内读改写 | 超 5 次直接返回 1005，不写 pair、不改 `count` |
| 存档 | `users`/`hospital_state` | `openid + revision` | 返回 1004 + 最新 revision |

## 6. 建库顺序

1. `users` → `hospital_state` → `pets_cases`
2. `pets` → `adoptions`（先 pets，保证关系可校验）
3. `ad_events` → `orders` → `config` → `leaderboard`
4. `assist_pairs` → `assist_daily` → `track_events` → `delivery_logs`
5. 先建普通索引，再建唯一索引；唯一索引创建前先清理重复数据。
6. 权限：客户端全部关闭直读直写；仅云函数服务端身份可读写；`config` 可对客户端只读开放（若采用直读）。

## 7. 迁移与兼容

| 场景 | 处理 |
|---|---|
| 旧设计把宠物状态放在 `pets_cases.affection` | 新增 `pets` 时按 `caseSessionId` 回填；`pets_cases.affection` 保留为单局快照 |
| 旧 `adoptions` 含展示字段 | 展示字段迁入 `pets` 或按 `petId` 联表读取；`adoptions` 只保留关系字段 |
| 旧 `ad_events.adSessionId` 唯一 | 改为 `idempotencyKey` 唯一；历史数据回填 `openid:adSessionId` |
| 排行榜 | 首次上线可全量重算；之后增量更新 |

**要求：** 迁移脚本可重入；迁移前备份；迁移后抽样校验 `pets` 与 `adoptions` 一对一。

## 8. 验收

- 9 个核心集合与 4 个辅助集合可按本文直接创建。
- `pets.petId`、`adoptions.adoptionId/cardId/petId`、`ad_events.idempotencyKey`、`orders.clientOrderId/transactionId`、`leaderboard.type+period+openid` 唯一索引生效。
- 重复写入返回明确错误或历史结果，不产生重复奖励/发货。
- `adoptions` 不含展示字段，图鉴可联表取到物种、命名、稀有度、故事与照料评分。
- 前 N 榜单查询走 `leaderboard` 组合索引，无全表扫描。
