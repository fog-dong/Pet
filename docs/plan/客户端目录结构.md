# 客户端目录结构

| 项目 | 内容 |
|---|---|
| 版本 | v1.0 |
| 日期 | 2026-10-29 |
| 负责人 | 客户端 + 架构 |
| 状态 | 冻结（W1–W4） |
| 依赖文件 | 00-项目总览与执行边界.md、08-客户端架构与状态机.md、接口冻结清单.md |

> **说明**：本文冻结 `assets/scripts/` 下 7 个目录的职责、依赖方向与禁止项。W1 只落骨架文件，不实现玩法。

## 1. 目录总表

```text
assets/scripts/
├── core/      # 启动、状态机、事件总线、通用基类
├── ui/        # 页面管理、弹窗、UI 基类
├── game/      # 单局流程与玩法编排
├── net/       # Net / Ad / Pay，唯一平台出口
├── cache/     # 本地快照、登录态、配置缓存
├── track/     # 埋点队列与上报
└── config/    # 配置加载、版本校验、本地兜底
```

| 目录 | 职责 | 允许依赖 | 禁止 |
|---|---|---|---|
| `core/` | `GameFSM`、事件总线、启动流程、通用类型 | 无业务依赖 | 依赖 `ui/game/net`；持有业务数据 |
| `ui/` | `UIManager`、页面基类、弹窗层级、遮罩 | `core` | 直接调 `wx`；持有业务数据；做发奖判定 |
| `game/` | `CaseFlow` 单局编排、页面流转、状态同步 | `core/ui/net/cache/config/track` | 直接调平台 API；直接写数据库 |
| `net/` | `Net.call`、`Ad.showRewarded`、`Pay.createOrder` | `core` | 拼业务参数；做奖励计算；出现第二套请求库 |
| `cache/` | 存档快照、登录态、配置缓存、重试队列持久化 | `core` | 作为唯一数据源；缓存敏感明文 |
| `track/` | 埋点队列、批量上报、失败重试 | `core` | 采集 openid 以外的个人信息；阻塞玩法 |
| `config/` | 配置拉取、版本校验、本地兜底、灰度标签 | `core/net` | 运行中改结构；把默认值静默上线 |

## 3. 依赖方向

```text
game  →  ui / net / cache / config / track  →  core
config → net → core
track  → core
cache  → core
ui     → core
```

**硬规则：**

- 依赖只能向左/向下，禁止 `core → ui/game/net`、`ui → game`、`net → game`。
- `game` 是唯一可以同时依赖 UI 与网络的层；页面不得自行发请求。
- `net` 不得 import `game/ui`，避免循环依赖。
- 跨模块通信优先用 `core` 的事件总线，不直接持有对方实例。

## 4. 平台 API 边界

| 能力 | 唯一出口 | 业务层禁止 |
|---|---|---|
| 云函数 | `net/Net.ts` | `wx.cloud.callFunction` |
| 激励视频 | `net/Ad.ts` | `wx.createRewardedVideoAd` |
| 虚拟支付 | `net/Pay.ts` | `wx.requestMidasPayment` |
| 隐私授权 | `net/Privacy.ts` | `wx.requirePrivacyAuthorize`、`wx.onNeedPrivacyAuthorization`、`wx.openPrivacyContract` |
| 客服会话 | `net/Support.ts` | `wx.openCustomerServiceChat` |
| 本地存储 | `cache/` | 业务层直接 `wx.setStorageSync` |
| 埋点 | `track/Track.ts` | 业务层直接调第三方 SDK |

**例外：** 启动阶段的版本检查可在 `core` 内通过 `Net` 完成，但不得直接调 `wx`。

## 5. 页面与场景

- 页面用 `UIManager` 的显式栈管理，不用场景切换代替页面。
- 页面栈与 03/08 一致：`Boot → Login → Lobby → CaseIntro → Diagnosis → Treatment → Recovery → Adoption → Result → Lobby`。
- 栈深超过 6 时替换栈顶，不继续压栈。
- `TreatmentPage` 禁止手势返回；退出需二次确认。
- 页面 `onDestroy` 必须解绑事件、释放资源引用；广告/支付回调不得持有已销毁页面。

## 6. 文件规范

- 头部：`// STATUS: scaffold, API frozen by architect on 2026-10-29`。
- 单文件 ≤150 行；超出按职责拆分。
- 类/函数英文命名，注释中文；禁止裸 `any`。
- 不硬编码 appid、广告位、价格、密钥。
- 业务实现后补对应冻结接口编号（如 `// API: syncCaseResult`）。

## 7. 验收

- 7 个目录存在且职责无重叠；`net` 是唯一平台出口。
- W1 骨架可编译，`tsc --noEmit` 通过。
- 页面栈与 03/08 一致，状态机白名单外切换被拦截。
- 业务层无 `wx.cloud.callFunction`、`wx.createRewardedVideoAd`、`wx.requestMidasPayment`。
- `Pay.createOrder` 在 W1–W4 固定返回 `PAY_UNAVAILABLE`。
