## 1. 设备矩阵

| 档位 | 示例设备 | 重点观察 |
|---|---|---|
| 低端 | 4GB RAM 安卓（骁龙 6 系及以下） | 内存 ≤250MB、FPS ≥30、加载不黑屏 |
| 中端 | 6GB RAM 安卓 | 内存 ≤200MB、FPS ≥45、场景切换无卡顿 |
| 高端 | iPhone 12 及以上 | FPS ≥55、动效完整 |
| 异常 | 低电量模式 / 弱网（3G） | 网络失败可降级、队列补发正常 |

iOS 与 Android 各至少 1 台；同一台设备至少覆盖「冷启动 → 完整一局 → 领养 → 回大厅 → 再看图鉴」一遍。

## 2. 性能读数（开发构建专有）

1. 用开发构建（构建面板勾选「开发构建」，`DEBUG` 为真）运行，屏幕出现引擎自带 profiler 浮层，显示 FPS 与 DrawCall。
2. 浮层每帧刷新；release 构建（未勾选开发构建）不得出现该浮层，提审包必须确认无此行。
3. JS 内存不在游戏内读数：开发者工具用「调试器 → Memory」，真机用 vConsole「内存」页签。（W9-1 已移除游戏内自定义面板，避免调试代码打进发布包。）
4. 记录各场景稳态数值：Boot、Lobby、CaseIntro、Diagnosis、Treatment、Recovery、Adoption、Result。
5. 判定线：FPS 低端 ≥30、中端 ≥45；DrawCall ≤120；JS 内存低端 ≤250MB、其余 ≤200MB。

## 3. 分包与内存

| 用例 | 步骤 | 预期 |
|---|---|---|
| 主包体积 | 构建产物 `build/wechatgame` 主包目录 | ≤4MB（当前 3.3MB 级） |
| 分包加载 | 冷启动进大厅 | `game.json` 含 `subpackages: cases`，无 `boot_cases_bundle_missing` |
| 分包卸载 | 大厅 → 对局 → 回大厅循环 5 次 | 内存不单调上涨；`Res.releaseUnused` 在每次切场景后执行 |
| 配置兜底 | 删除/改名 cases 分包后启动 | 仍能进大厅，使用内置 2 例兜底，不崩溃 |

## 4. 画质降级（远程配置 quality=low）

1. 云开发控制台把 `getConfig` 返回的 `configs.quality` 改为 `low`。
2. 冷启动后确认：诊断页热区不再脉冲；大厅角色不再呼吸缩放；开发者工具「网络/云函数」面板里 `getConfig` 返回的 `configs.quality` 为 `low`。
3. 改回 `high` 后冷启动，动效恢复。
4. quality 缺省或非法值时按 `high` 处理。

## 5. 诊断与治疗玩法

| 用例 | 步骤 | 预期 |
|---|---|---|
| 听诊 | 完成一局听诊病例 | 命中/误点反馈正确，误点扣时，星级与结算页一致 |
| 拍片 | 拖动标记框到病灶 | 容差内命中，全部找齐后自动结束 |
| 化验 | 试剂拖到样本 | 匹配成功连线，3 次错误直接结束 |
| 重试 | 诊断失败后用广告/道具重试 | 只允许一次重试，星级按最好一次记录 |
| 治疗 | 选药/床位/时间 | 床位不足给出替代路径，不卡死 |
| 康复 | 等待或加速 | 加速走广告占位，结束后好感度到账 |

## 6. 网络与存档

| 用例 | 步骤 | 预期 |
|---|---|---|
| 云端离线 | `CLOUD_ENV` 保持占位符 | 直接进大厅，单局可玩，无报错弹窗 |
| 弱网结算 | 飞行模式完成一局 | 结算页提示「网络不可用，结算将在下次启动补发」 |
| 补发 | 恢复网络后冷启动 | `syncCaseResult` 队列清空，`pending_case_flushed` 有记录 |
| 存档冲突 | 手工改小本地 revision 后完成一局 | 提示「云端存档已更新，本地结算已同步」，不覆盖服务端 |
| 登录失败 | 云函数未部署 | 进大厅不被阻塞，仅领养/榜单等会话入口不可用 |

## 7. 广告与支付占位

1. 五个广告点位逐个触发：`extra_check`、`accelerate`、`double_reward`、`extra_inspection`、`free_slot`。
2. 每个点位确认：每日上限生效、超限按钮置灰且文案说明原因、播放失败有兜底提示。
3. `free_slot` 用完时，领养页仍保留「分享求助」和「等待 10 秒」两条免费路径。
4. 任何支付入口只能返回 `PAY_UNAVAILABLE`，不得引导站外支付。

## 8. 社交与合规

| 用例 | 步骤 | 预期 |
|---|---|---|
| 主动分享 | 点击「分享求助」 | 仅在点击后调用 `wx.shareAppMessage`；无被动/自动分享 |
| 助力限次 | 连续分享求助 | 每日上限 5 次，同一好友每天只 +1，超出有文案提示 |
| 领养 | 好感达标且有空位 | 领养成功，图鉴状态变为「已领养 · 日期」 |
| 领养位满 | 三者任选 | 分享/广告/等待均可腾位，不存在「必须分享」 |
| 未成年保护 | 无支付门槛、无诱导文案 | 分享文案符合 06 §5.2，不出现「求助力」「拉 3 个群」 |

## 9. 记录与产出

1. 每个设备一份记录：机型、系统版本、微信版本、各场景 FPS/DrawCall/内存截图。
2. 引擎 profiler 浮层截图（FPS / DrawCall）与 vConsole 内存截图，加 `Track` 记录（`pending_case_flushed`、`save_conflict`、`share_click`、`assist_received`）。
3. 发现的问题写入项目 issue，标注档位与复现步骤；阻断级问题（崩溃、卡死、内存超限）不得带入提审。
