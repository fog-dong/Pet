## 2. 我实际跑到了什么

用项目自带的 CDP 回归脚本跑完整主链路（游客态、390×844、无头 Chrome + SwiftShader）：

- 16 张一镜到底截图：大厅四个 TAB → 寻访 → 接诊 → 诊断 → 治疗 → 康复 → 领养 → 结算 → 小屋 → 送养，全部可达。
- 18 条断言：**PASS 16 / FAIL 2**。
  - `C05` 治疗多选断言失败：截图显示"导尿/住院/加速"选择态正常，判断为脚本读取时序问题，**不是产品缺陷**。
  - `C11` 控制台报错 5 条：2 条 Cocos meta 弃用警告、2 条 AudioContext 自动播放限制、**1 条 404 资源请求**。404 必须查清。
- 功能盘点：20 个病例（猫/狗/兔/鹦鹉）、拍片刮雾 + 听诊节奏 + 化验连线、治疗分配、康复计时、领养门槛、图鉴、小屋养成、后院种植合成、送养审核、寻访抽卡、成就、排行榜入口、云存档。
- 硬数字：主包 3.54 MB（3,716,567 B，上限 4 MB，安全）；微信构建总计 8.05 MB；9 条 mp3；7 个广告位占位；`leaderboard` 集合**全仓无写入方**；无新手引导、无每日任务、无登录奖励。

**结论：功能侧不用再加系统了，再加只会稀释品质。**

## 3. 为什么"差点意思"：六个根因

### 3.1 单局是"选择题"，不是"抢救"

治疗页现在是三行 chip：药品 / 床位 / 时间 → 点"开始治疗"。选错就清空重选，**零成本、无限次**；危重病例也只是"必须 3/3 全对"，没有时间压力。

玩家的真实心理是"我在填表"，不是"我在救它"。

**改法（治疗 2.0）**：病例给 3 个并发病症（脱水 / 感染 / 疼痛），每个病症要"药 + 护理"；玩家只有 4 个行动点，选完进入 3 秒实时结算，宠物心率/体温/精神三条状态条随用药变化，错药立刻恶化并给一次补救窗口；危重病例加 60 秒倒计时；失败不是重来，而是**转院**（扣口碑、退一半药、图鉴记"未救回"）。代价要落在情感上，而不是数值上。

### 3.2 情绪最高点是"进度条"

康复页是全游戏的情绪顶点，实际呈现是：约 90px 的小图 + 一条进度条 + "还需 10 秒" + 一个写着"看广告加速 50%（广告暂未开放）"的灰按钮。

结算页只有数字和星星，宠物不在场。

**改法（康复/结算 2.0）**：康复改成 3 次护理互动（喂药/换水/抚摸），每次一个叫声 + 尾巴 + 心情飘字；姿态三段式"蜷缩 → 抬头 → 站起摇尾"；结算页宠物居中先播"蹭手"2 秒，再逐颗出星、滚动金币、翻图鉴卡。

### 3.3 首 30 秒没有"它需要你"

冷启动顺序：3 秒合规页 → 手动勾选隐私协议 → 大厅（静态前台 + 两个等宽大按钮）→ 街头寻访（抽卡）→ 接诊。第一次心跳发生在 40–60 秒之后。

IAA 用户 30 秒内看不到"一只受伤的动物"，就会走。

**改法（首局脚本化）**：首次启动跳过抽卡，直接进病例：一只发抖的幼猫在纸箱里；30 秒内完成第一次听诊；首局治疗只给 2 个选项；首局结束必得图鉴卡并引导领养。

### 3.4 没有声音，也没有"手感"

只有 9 条音效（猫/狗/兔/鸟叫、治疗成功、康复 tick、喂食/洗澡/抚摸）。**没有 BGM，没有 UI 音，没有环境音**。大厅、诊断、结算全程接近静音。

同时缺少反馈层：没有屏幕震动、没有成功粒子爆发、没有数字滚动、没有连击音、没有转场镜头。已知文字碰撞：听诊页"连击 ×2"压住"不错，接住了"；启动页"适龄提示：8+"压住底部按钮（实测截图）。

**改法（反馈预算）**：每次点击 0.96 缩放 + 1 个 UI 音；每次成功 1 次粒子 + 1 个正向音；每个数值变化 200ms 滚动；每个场景切换 200ms 淡入 + 轻微推镜；危重时心跳声随倒计时加速。BGM 三条即可（大厅/诊疗/结算），成本远低于重做美术。

### 3.5 美术与 UI 没有统一语言

同一款游戏里，英短是 3D 毛绒质感，布偶是写实渲染，橘猫是扁平卡通；眼睛高光、胡须粗细、爪垫配色都不统一，AI 生成痕迹明显。UI 是通用奶油色圆角卡片，缺少"诊室/病历/器械"的符号系统；按钮权重几乎一样，每屏没有唯一主行为。

**改法**：锁定"黏土玩具"一种语言，20 只宠物统一光照方向、描边、色温、透明底；UI 引入三个母题——病历夹（米白纸 + 金属夹）、听诊器（管线分隔）、金属托盘（按钮底）；每屏只保留 1 个珊瑚色主按钮，其余降为次级。

### 3.6 有系统，没有"今天要做什么"

成就、图鉴、后院、送养都在，但玩家进大厅看不到目标：没有每日任务、没有 7 日目标、没有登录奖励、没有"下一只可领养"的进度。后院有 2 小时计时，但没有"回来收"的理由提示。

**改法**：大厅加"今日救助目标"三条（完成 1 例 / 护理 1 次 / 收 1 次菜），完成给一次免费寻访；图鉴顶部做"救助进度 12/20"；医院升级从按钮改成可见的"诊室扩建进度"。

## 7. 如果只做三件事

1. **治疗 2.0 + 危重倒计时**：把"选择题"变成"有代价的决策"。
2. **康复与结算演出**：把"等待"变成"回报"，这是玩家愿意截图分享的瞬间。
3. **首局 30 秒脚本 + BGM**：把"路过"变成"留下"。

## 8. 明确不要做（防范围蔓延）

- 不加新系统（后院/成就/送养已经够，缺的是把它们串成目标）。
- 不做 3D、不做骨骼动画、不做 Live2D。
- 不做多人、公会、PVP。
- 不做复杂剧情树与全语音。
- 不在提审前重做大厅布局（W27 已做过一轮，边际收益低）。

## 9. 风险

1. **美术统一是最大成本项**：20 只宠物重绘至少 5–8 人日；若预算不足，优先统一光照与描边，不动模型。
2. **治疗 2.0 会改结算与数值**：需要同步改 `CaseScore`/`Treatment`/`Result` 与配置表，建议先做灰度开关。
3. **广告接入依赖平台审核**：广告位创建到生效有延迟，Sprint 2 必须提前 3 天申请。
4. **支付合规**：iOS 不得出现任何购买入口与价格文案，审核会逐屏看。
5. **首局脚本改动会影响所有回归用例**：需要同步更新 `verify-mainchain-browser.js` 的入口假设。
