## 2. 后端通路收口（决策-6d：本版只留自建 HTTP，且已落源码）

### 2.1 拍板结论与代码落地

你选的是**只保留通路 A**（Axum HTTP 自建后端），13 个云函数整体不部署，`CLOUD_ENV` 保持 `ENV_PLACEHOLDER` 作为备用。这条决定在代码侧有一个前置条件必须补：

> W24 之前 HTTP 基址**只有运行时覆盖位** `pet_api_base_v1`（`wx.setStorageSync` 写入）。覆盖位不会进提审包——审核员与线上玩家拿到的是干净环境，`resolveApiBase()` 返回空串，`isCloudEnabled()` 因 `CLOUD_ENV` 是占位也返回假，**整个包退化成纯本地模式**：排行榜空、助力无效、离线收益领不到。这是提审被拒的高频原因，而且单看代码不会发现。

所以 `config/EnvConfig.ts` 做了两处改动（`e034052`）：

1. 新增源码常量 `API_BASE_URL = 'https://pet.jiangker.cn'`，`resolveApiBase()` 变成「覆盖位 > 源码默认」；域名是公开信息，不违反「不硬编码密钥 / AppID / 广告位 / 价格」。
2. 新增哨兵 `API_BASE_DISABLED = 'off'`：有了源码默认值之后，「清掉覆盖位」不再等于关闭通路，必须显式写 `off`。它同时是故障回滚位（《云托管自定义域名绑定指南》两处回滚步骤已同步改写）和三套浏览器用例的隔离位——用例打的是本地 mock，绝不能请求真线上。

重建后的产物实测确认已生效：`assets/main/index.js` 里能检索到 `pet.jiangker.cn`，即提审包第一次请求就会打向自建后端。

### 4.2 前两轮修掉的真实缺陷（保留备查）

1. **`PetQuota.consume` 跨天计数不归零**（`assets/scripts/cache/PetQuota.ts`，W23）：原先在 `Save.mutate` 内部先写 `pettedDay` 再读 `used(dayKey)`，而 mutate 拿到的就是同一份存档对象，导致昨天用满 3 次会带进今天变成第 4 次。浏览器用例 `B04` 首次跑出 `count=4` 暴露此问题，改为在 mutate 前算好 `next` 后为 `count=1`。
2. **`AgeSystem.getAgeText` 未使用参数**（W23）：scaffold 配置（含 `noUnusedLocals`）报 TS6133，删掉多余的品种参数；「年龄文案与品种无关」现在由函数签名本身保证。
3. **`recoverTick` 指向不存在的分包路径**（W24-2）：见 §1.2 C 项——写了也永远命中不了，反而让人以为分包里有音频。
4. **提审包退化为纯本地模式**（W24-4）：见 §2.1，这是本轮最有价值的一条，代码单看完全正常，只有把「覆盖位不进包」和「`CLOUD_ENV` 是占位」两件事放在一起才看得见。
