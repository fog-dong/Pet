## 1. 类目与资质

- [ ] 类目选择「游戏」，二级类目按平台当期要求填写（本作为休闲向模拟经营，**不以「医疗/健康」类目申报**）。
- [ ] 软著/版号/备案材料按平台当期政策准备齐全（IAA 与 IAP 的要求不同，提交前向平台确认）。
- [ ] 小游戏名称、图标、简介与实际玩法一致，不含「宠物医院诊断」等易被理解为真实医疗服务的表述。
- [ ] 提审账号、体验路径与真机包一致，无需额外白名单才能进游戏。
- [ ] **AppID 已替换**：`build-templates/wechatgame/project.config.json` 当前为 `touristappid`（游客占位），提审包必须是正式 AppID。

## 2. 医疗表述（虚构声明）

- [x] 游戏内提供明确免责声明：**「本游戏为虚构的宠物医院模拟玩法，所有诊断、用药与治疗均为游戏设定，不构成任何医疗或兽医建议。」**（文案常量 `MEDICAL_DISCLAIMER_TEXT`，唯一来源 `assets/scripts/config/LegalConfig.ts`）
- [x] 免责声明双入口：`game/CaseIntro.ts` 每次接诊的病例页左下固定展示；`ui/AboutPanel.ts`（大厅「关 于」）常驻展示，游客模式同样可达。
- [ ] 全部文案不含真实药品名、剂量、器械型号、真实诊疗流程建议。
- [ ] 不出现「治愈率」「疗效」等医疗承诺；星级、评分只表示游戏内表现。
- [ ] 不引用真实病例、真实宠物照片、真实医院名称。

## 3. 动物伦理

- [ ] 整体叙事为「救助 → 治疗 → 领养」，不展示虐待、遗弃过程细节、血腥或真实痛苦。
- [ ] 危重状态以卡通化、图标化表达（当前为色块 + 状态图标），无写实伤口。
- [ ] 「失败」只表示本局未完成，不出现死亡、安乐死等表述。
- [ ] 图鉴与分享卡不包含真实宠物影像与病历。

## 4. 隐私与协议

- [ ] 提供《隐私政策》《用户协议》有效链接（当前为**占位，待替换**），并在小游戏后台「用户隐私保护指引」中同步配置。
- [x] 首帧后、进大厅前弹隐私窗：`ui/PrivacyDialog.ts` 展示协议正文 + 勾选框，未勾选时「同意并进入」置灰（`LEGAL_VERSION` 变更后自动重弹）。
- [x] 点「暂不同意」不退出游戏：切到说明页 `PRIVACY_GUEST_TEXT`（云端存档/排行榜不可用，本地病例照玩），提供「重新阅读协议」与「仅体验基础内容」两个按钮；后者进大厅并记 `privacy_guest_mode`。
- [x] 游客模式只关云端：`Net.init` 只在同意后由 `core/BootCloud.ts` 的 `startCloudSync()` 调用，`Profile.refresh`/排行榜/助力在游客模式一律短路（`PrivacyState.isGuest()`），本地单局、图鉴、广告与本地存档不受影响；大厅「隐私与协议」可补同意，同意后立刻接回云端。
- [x] 同意前不发起任何云端调用：隐私门在 `Net.init`/`syncCloud` 之前，游客模式下所有 `Net.call` 入口都以 `Net.ready` 短路，埋点只留在本地队列。
- [x] 平台隐私 API 只经 `net/Privacy.ts` 出口（`requirePrivacyAuthorize`/`onNeedPrivacyAuthorization`/`openPrivacyContract`），旧基础库与开发者工具环境静默降级。
- [x] 同意状态记录在本地独立键 `pet_privacy_v1` 的 `privacyAccepted`/`acceptedVersion`/`guestMode`，不写入云端存档结构。
- [ ] 采集范围最小化：仅 openid（云端上下文获取）、本地存档与匿名埋点；不采集手机号、位置、通讯录、相册。
- [ ] 首次启动不静默上传设备信息；埋点不含敏感字段。
- [ ] 提供账号注销/数据删除路径说明（客服受理即可，需写入隐私政策）。
- [ ] 未成年人个人信息处理条款与平台要求一致（游戏内说明见 `config/LegalConfig.ts` 的《未成年人保护说明》，正式条款待运营补充）。

## 5. 支付

- [ ] 本次提审版本**不含真实支付**：`Pay.createOrder` 与云函数 `payCallback` 固定返回 `PAY_UNAVAILABLE`。
- [ ] 无站外支付引导、无二维码、无客服转账话术。
- [ ] iOS 端不出现任何付费引导或价格展示（当前无内购 UI）。
- [ ] 若后续开放内购，需单独提交资质与价格公示，不在本次范围。

## 6. 广告

- [ ] 当前为本地占位（`net/Ad.ts` 不调用真实广告 API），提审包若接真实广告需替换并回归。
- [ ] 广告点位有明确标识与关闭路径；无虚假关闭按钮、无诱导点击。
- [ ] 每日频控生效（双倍 5 次、免费领养位 3 次、其余按点位），超限置灰并说明原因。
- [ ] 广告失败有兜底路径，不阻塞玩法。
- [ ] 不对未成年用户推送诱导性广告内容。

## 7. 分享与助力

- [ ] 分享仅由用户点击按钮触发（`net/Share.ts` → `wx.shareAppMessage`），无自动/被动分享、无分享后才能继续。
- [ ] 分享文案符合 06 §5.2（第一人称、落点在宠物），不含「求助力」「拉群解锁」等诱导话术。
- [ ] 助力每日上限 5 次、同一好友每天 1 次（由云函数 `assist` 主键去重 + 原子计数校验）。
- [ ] 领养、治疗等核心流程不存在「必须分享」前置；分享/广告/等待三条免费路径并存。
- [ ] **政策风险提示**：分享换好感（+1）属于激励分享，平台对「分享得奖励」有收紧趋势；若审核质疑，优先降级为纯展示分享，保留广告与等待路径。

## 8. 未成年人保护

- [ ] 无付费门槛，不以付费解锁核心玩法。
- [ ] 按平台要求接入实名与防沉迷能力（小游戏平台统一能力，需在后台开启）。
- [x] 游戏内展示适龄提示与健康游戏忠告：`core/Boot.ts` 在启动页底部常驻 `AGE_RATING_TEXT`（「适龄提示：8+」，数值由 `AGE_RATING` 单一常量驱动）+ `HEALTH_GAME_NOTICE_TEXT`（忠告全文），进大厅前至少驻留 3 秒（`SPLASH_MIN_MS`）；`ui/AboutPanel.ts` 关于面板同样展示。自绘行保留作为截图保底，后台适龄自选必须与 `AGE_RATING` 同一数值（仍为人工项）。
- [ ] 无抽奖、盲盒、概率公示类玩法。
- [ ] 文案无诱导消费、无「限时充值」类表达。

## 9. 内容与素材

- [ ] 字体、音效、图标有授权或为原创；无侵权素材。
- [ ] 无违规词、敏感形象、政治/宗教元素。
- [ ] 无第三方商标、真实品牌露出。

## 10. 客服与运营

- [ ] 小游戏后台配置客服入口，明确响应时效与投诉处理流程。
- [x] 游戏内提供「关 于 / 联系客服」入口：`ui/AboutPanel.ts`（大厅常驻按钮）经 `net/Support.ts` 调用 `wx.openCustomerServiceChat`；URL 未配置、基础库不支持或调用失败一律回显 `CUSTOMER_SERVICE.fallbackText`（「客服系统配置中，可通过公众号留言反馈。」），不崩溃、不静默。
- [ ] 退款与投诉口径与支付现状一致（当前无支付，需说明无付费内容）。
