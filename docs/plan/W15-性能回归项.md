## 1. 画质档位：远程控制 + 运行时切换

### 1.1 现状（W15-3 改动后）

| 环节 | 实现 |
|---|---|
| 远程配置 | `getConfig` 返回 `configs.quality`（`high` / `low`）；W15-3 前白名单漏了 `quality`，实际恒为空，本轮已补入（冻结清单 v1.10），未知值按 `high` 处理（`Quality.set`） |
| 启动拉取 | `BootCloud.syncCloud()` 登录成功后 `await loadQuality()`（`core/BootCloud.ts:80`） |
| 返回大厅再拉 | `Lobby.start()` 非游客分支 `void refreshQuality()`（`ui/Lobby.ts:49`）→ 运营改 `quality` 后**下一次进厅即生效，无需重启** |
| 生效方式 | `Quality.subscribe` 发布订阅；`CharacterView.onEnable` 订阅后按 `currentMood` 重放（`game/CharacterView.ts:38-45`）；`Auscultation.onEnable` 订阅并调 `view.applyQuality()`（`game/Auscultation.ts:33-40`） |
| 退订 | 两个视图均在 `onDisable` 退订，切场景不残留回调 |
| low 档行为 | 关闭角色呼吸缩放（`CharacterView.ts:110`）与异常点循环脉冲（`AuscultationView.ts:123`）；已播放的循环动效在切换瞬间停止并复位缩放 |

### 1.2 人工验证步骤（真机/开发者工具均可）

1. 确认 `config` 集合存在 `configKey='quality'`、`status='active'` 的文档，`payload` 为字符串 `'low'`（`grayPercent=100` 或按灰度设置）。
2. 不重启，从单局返回大厅；观察角色不再呼吸缩放、听诊异常点不再脉冲（若在单局中切换，需回大厅再进单局生效）。
3. 把该文档 `payload` 改为 `'high'`（或新建 v2 并切 active），再次回大厅并进入单局，呼吸与脉冲恢复。
4. 断网/后端失败时保持当前档位，不弹错（`loadQuality` 失败只记 `boot_config_failed`）。

> 边界：`quality` 在单局中途变更时不会立刻刷新当前场景，最迟下一局生效；这是有意的低成本实现，避免每帧检查远程值。

## 2. 分包生命周期（cases / art）

| 分包 | 加载 | 释放 | 现状 |
|---|---|---|---|
| `cases` | `Boot` 首屏加载（带 2.5s 超时）；`Lobby.start` 再次 `Res.loadBundle` 持有到离厅 | `Boot` 加载后立即 `Res.release`；`Lobby.onDestroy` 释放；`SceneFlow.goState` 场景切换后 `Res.releaseUnused` 卸载 | 循环正确：大厅持有 → 进单局销毁大厅释放 → 再回大厅重新加载 |
| `art` | `CharacterView.showPet` 首次显示时 `warmArtBundle()` | 不释放（`ArtBundle.ts` 注释：宠物立绘在大厅、病例、康复三处连续使用，加载后常驻） | 当前 art 仅 1 张 1×1 占位图，产物 10,488 B；接入真实美术后需复评常驻内存 |

补充：单局内不再重复加载 `cases`，因为 `CaseConfig` / `CharacterConfig` 已在内存缓存；`cases` 内 3 个 JSON 为配置数据，体积极小。

## 3. 首屏超时集中

- 唯一常量：`assets/scripts/config/BundleConfig.ts:8` `BUNDLE_TIMEOUT_MS = 2500`。
- 唯一使用点：`core/Boot.ts:61` `withTimeout(loading, BUNDLE_TIMEOUT_MS)`；业务层不再各写超时。
- 超时分支：`Boot` 记录 `boot_cases_bundle_slow`，继续走内置 `resources` 兜底加载配置；分包晚到后 `Res.release` 归还引用，由下次场景切换回收；**不 await 分包完成才进厅**。
- 兜底后仍保证启动页驻留 `SPLASH_MIN_MS=3000`，不会因超时白屏或卡死。
