## 一、客户端生产代币风险 — 通过（修复后）

### 1.1 客户端写入点盘点

| 位置 | 行为 | 性质 |
|---|---|---|
| `assets/scripts/cache/Save.ts:47/61/121` | `addCoins` / `addHearts` / `recordStars` 写本地缓存 | 本地展示账本，非发放依据 |
| `assets/scripts/game/CaseSettle.ts:64-67` | 单局结算先本地加币/加心/记星 | 本地乐观展示；云端以 `syncCaseResult` 返回值为准 |
| `assets/scripts/game/Result.ts:140` | 广告翻倍在本地再加一次 `reward.coins` | 仅本地；服务端 `adEvent` 不发币（`reward` 恒 `null`，见 v1.3） |
| `assets/scripts/game/CloudPayload.ts`（W15-1 改） | 只提交 `level / beds / adoptionSlots` | 白名单快照，不含 `resources` |
| `cloudfunctions/saveGame/index.ts:80-89`（W15-1 改） | 只写 `hospital_state` 与 `users.revision` | **不再写 `users.resources`** |
| `cloudfunctions/syncCaseResult/settle.ts` | 事务内重算星级/奖励并按服务端配置写 `users.resources` | 唯一的服务端发放入口 |

### 1.2 修复前的阻塞路径

`saveGame` 把 `snapshot.resources` 合并进 `users.resources`，而客户端快照由本机存档生成 → 修改本地存档即可把云端金币/爱心/药品改成任意值。该路径与 W12-B 同源，属于「客户端计算结果被当作发放依据」。

### 1.3 修复内容

- 服务端：`saveGame` 删除 `UserDoc.resources` 与资源合并，事务内仅写 `hospital_state` 与 `users.revision`；`validate.ts` 保留对 `resources` 的形状校验（老客户端传畸形值仍返回 1002），但校验通过也不落库。
- 客户端：`buildSaveSnapshot` 只提交 `level / beds / adoptionSlots`，不再上传本地资源数值。
- 回归：新增 `scripts/verify-save-security.js` 用例 [15]——预置云端 `coins=100/hearts=5/健胃药=3`，提交被篡改为 `999999` 的快照，断言医院状态正常写入、资源三项保持不变、同 revision 重放仍返回 1004 且资源不变。

### 1.4 警告（不阻塞）

| 项 | 说明 | 建议时点 |
|---|---|---|
| 本地/云端双账本未对账 | 客户端 `Save` 只增不减地自算，`syncCaseResult` 返回的 `resources` 未回写本地 | W16 若做经济系统再对齐；提审前不影响合规 |
| 广告翻倍只加本地 | `Result.ts:140` 的翻倍不进云端账本，杀进程后失效 | 已知 W4 遗留，属体验问题 |
| 医院状态无上界 | `beds / adoptionSlots / reputation` 只校验非负整数，可被改成极大值 | 仅影响本人展示与列表展示，不产生代币；可在下次改动时补上限 |

## 三、云函数入参校验 — 警告

### 3.1 openid 来源

12 个云函数（`adEvent` / `assist` / `createOrder` / `getConfig` / `getProfile` / `leaderboard` / `login` / `payCallback` / `pendingMonitor` / `saveGame` / `syncCaseResult` / `trackEvent`）中，11 个业务函数全部从 `cloud.getWXContext().OPENID` 取身份，无任何函数接受客户端传入的 openid 作为身份；`pendingMonitor` 为每日定时触发器，不提供服务端接口、只读统计。

### 3.2 逐函数校验

| 函数 | 关键校验 | 判定 |
|---|---|---|
| `saveGame` | `revision` 正整数；快照白名单 + 类型/非负校验；`revision <= current` 返回 1004；resources 校验后忽略 | 通过（W15-1 修复） |
| `syncCaseResult` | `caseSessionId` / `caseId` 非空且 ≤ 长度上限；诊断/治疗结构校验；时长范围；奖励由服务端重算；2002 写 `sync_pending` | 通过 |
| `assist` | `friendOpenid` 非空且非本人；`resourceType` 白名单；`nonce` 非空；幂等键与每日额度在事务内判定 | 警告（见 3.3） |
| `adEvent` | ID 非空、scene 白名单、`isEnded` 布尔；按北京时间自然日频控；`_id=openid:adSessionId` 幂等 | 通过 |
| `trackEvent` | 事件名与属性白名单；`_id=openid:batchId` 批幂等；单批条数上限 | 通过 |
| `login` | `channel` / `scene` / `version` 校验；openid 只从上下文取 | 通过 |
| `getConfig` | 只读；`configKey` 白名单；只返回 `active` 版本 | 通过 |
| `getProfile` | 只读；只查上下文 openid；领养列表上限 50 | 通过 |
| `leaderboard` | `type` / `period` 白名单；越界分页拒绝；不返回他人 openid（`maskId`） | 通过 |
| `createOrder` | 仅校验 SKU 存在；固定返回 `3002 PAY_UNAVAILABLE`（`cloudfunctions/createOrder/index.ts:32`） | 通过 |
| `payCallback` | 报文形状校验；固定返回 `3002 PAY_UNAVAILABLE`，不发货、不更新订单（`cloudfunctions/payCallback/index.ts:25-41`） | 通过 |
| `pendingMonitor` | 无客户端入口；只读统计；老化输出 `pending_aging` 日志 | 通过 |

### 3.3 警告（不阻塞）

| 项 | 说明 | 风险 |
|---|---|---|
| `assist` 的 `friendOpenid` 可伪造 | W7 无关系链，客户端传本地占位好友 ID，服务端只校验「非空且非本人」；`nonce` 无长度上限 | 可被构造以刷「被助力」次数，但额度为 5 次/日且事务内计数；关系链接入后必须换成分享票据解出的真实 openid（已在冻结清单备注） |
| `trackEvent` 属性值无长度上限 | 仅做白名单键校验，单批条数有上限 | 可写入较长字符串，属存储成本问题 |
| `saveGame` 医院状态字段无上界 | 见 1.4 | 仅影响本人/列表展示 |

以上均为已登记的历史偏差（W2/W4/W7），不构成提审阻塞；本轮不扩大改动范围。
