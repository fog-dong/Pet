## 1. 预览前置：四处占位替换

| 位置 | 当前值 | 替换为 | 是否入库 |
|---|---|---|---|
| `build-templates/wechatgame/project.config.json` + 构建参数 `appId=` | `touristappid` | 正式小游戏 AppID | **不入库**，只在本地构建注入 |
| `assets/scripts/config/EnvConfig.ts` 的 `CLOUD_ENV` | `ENV_PLACEHOLDER` | 测试云环境 ID | **不入库**（本地临时改，提交前回滚） |
| `assets/scripts/config/AdConfig.ts` 的 7 个 `AD_UNIT_PLACEHOLDER` | `AD_UNIT_PLACEHOLDER` | 微信后台激励视频广告位 ID | 可入库（ID 非密钥） |
| `assets/scripts/config/LegalConfig.ts` 的 3 个 `url: ''` | 空串占位 | 运营提供的真实 H5 地址 | 可入库 |

核对方式：

1. 协议链接三项填好后，`legalUrlsReady()` 必须返回 `true`；若正文或采集范围有改动，`LEGAL_VERSION` 同步递增（会触发重新弹窗，属预期）。
2. `EnvConfig.ts` 的 `CLIENT_VERSION` 递增一次，便于真机日志区分包次。
3. 广告位未申请下来时**可以先进预览**：占位 ID 下 `Ad` 返回 `AD_UNAVAILABLE`，既不降级也不发奖（见《11-IAA 广告系统》硬规则），不会污染存档。

## 2. 云函数部署（11 个）

1. 按《W7-云函数部署操作单》§2 建环境（含 `SESSION_SECRET` 环境变量）、§3 顺序上传 11 个函数：`login` → `getConfig` → `saveGame` → `syncCaseResult` → `leaderboard` → `assist` → `adEvent` → `createOrder` → `payCallback` → `getProfile` → `trackEvent`，全部选「上传并部署：云端安装依赖」，不勾选上传触发器。
2. 部署前确认 `cloudfunctions/*/index.js` 与 `index.ts` 同步：`npm run build:cloud` 输出 `stamped 11 cloud function builds`。
3. 集合与索引按《集合与索引冻结》§6 顺序建库；`assist_pairs`、`assist_daily`、`ad_events`、`track_events` 都靠自定义 `_id` 主键去重，**不需要**再建唯一索引，但需按下表建普通索引。
4. 部署后逐条跑《W7-云函数部署操作单》§4 的云端测试，W8 新增的四条重点看：
   - `assist`：同一天同一好友第二次调用返回 `ALREADY_ASSISTED`；第 6 次返回 `code: 1005` + `TODAY_ASSIST_LIMIT`，且 `assist_pairs` 里那条记录已被回滚删除。
   - `getProfile`：返回只含当前 openid 的 `users` / `hospital_state` / `pets`，入参不带任何 openid 字段。
   - `adEvent`：同一 `openid:adSessionId` 重复调用返回首次记录（`replay`），`isEnded=false` 的记录 `granted` 恒为 `false`。
   - `trackEvent`：同一 `openid:batchId` 重复上报返回首次 `accepted`，不产生第二行。

## 3. 构建与包体核对

```bash
unset ELECTRON_RUN_AS_NODE
CocosCreator.exe --project <工程路径> --build "platform=wechatgame;appId=<正式AppID>;startScene=0b556a8f-2609-451f-a9e7-30d58d1553da"
```

期望：控制台出现 `build success in … ms!`，且

1. `build/wechatgame/game.json` 的 `subpackages` 同时含 `{"name":"cases","root":"subpackages/cases/"}` 与 `{"name":"art","root":"subpackages/art/"}`。
2. 主包（`build/wechatgame` 去掉 `subpackages/`）≤4MB；W8-5 收口时为 3,400,622 B。
3. release 构建（未勾选开发构建）下不出现引擎 profiler 浮层，产物扫描无 `DebugPanel`/`DebugText`（W9-1 起游戏内不再有自定义面板）。
4. 总分包 ≤30MB，当前 art 仅 1 张 1×1 占位图，属预期。

## 4. 预览二维码与网络排查

1. 开发者工具导入 `build/wechatgame`，AppID 用正式值，点「**预览**」生成二维码（不要用「真机调试」测性能，那条链路自带调试开销）。
2. 「调试基础库」切到 2.32.3 及以上——`requirePrivacyAuthorize` / `onNeedPrivacyAuthorization` / `openPrivacyContract` 需要该版本线；更旧的机子上这些接口不存在，代码按「不支持」静默降级，自研弹窗仍然照常生效（不会卡进厅）。以官方文档为最终口径。
3. 二维码加载不出来或真机白屏，按顺序处理：
   - 关闭系统代理与抓包工具（Clash / Charles / Fiddler），开发者工具「设置 → 代理」选「**不使用代理**」。
   - `ipconfig /flushdns`，必要时把 DNS 换成运营商默认；公司网络常拦截 `servicewechat.com` 与云开发网关。
   - 手机与电脑同一 Wi-Fi，且手机未开 VPN。
   - 仍失败：降级到稳定版开发者工具 **1.05**（新版工具在 Windows 上有预览二维码渲染失败回归），复现一次再判断是否代码问题。
4. 真机能起但登录/存档失败：先查 `CLOUD_ENV` 是否指到已部署的环境、11 个函数是否全部部署成功、数据库权限是否按《W5-部署操作单》§7 设置；不要改代码绕过。
5. 分包 `cases` 约 8.6KB、`art` 约 1.9KB，不会触发 2.5s 分包预算；若日志出现 `boot_cases_bundle_slow` 或 `boot_cases_bundle_missing`，说明是网络或代理问题，不是包体问题。

## 5. 真机必测项

### 5.1 隐私合规（W8-5 落地，W9-4 补游客模式）

- [ ] 首次进入：启动页出现「隐私保护与用户协议」，**同意前不进大厅、不碰云端**，日志有 `privacy_dialog_show`。
- [ ] 未勾选时「请先勾选协议」按钮为置灰且点不动；勾选整行（880×60）都能切换。
- [ ] 勾选后按钮文案变「同意并进入」，点击进大厅并记 `privacy_agree`；支持隐私接口的机子会同步平台授权。
- [ ] 点「暂不同意」**不退出游戏**：切到说明页（文案来自 `LegalConfig.PRIVACY_GUEST_TEXT`），「重新阅读协议」回正文，「仅体验基础内容」进大厅并记 `privacy_guest_mode`。
- [ ] 游客模式大厅：顶部提示游客文案；`login`/`getProfile` 无请求（日志与抓包确认）；「排行榜」只给提示不开面板；领养页「求助助力」返回游客提示且爱心/床位不增加；单局玩法、图鉴、看广告、本地存档照常。
- [ ] 游客在大厅点「隐私与协议」→ 弹窗是同意态（可勾选），点「同意并进入」后立即补 `login`+`getProfile`，排行榜恢复。
- [ ] 游客模式下杀进程重进：仍会弹一次隐私窗（未同意不缓存放行），属预期。
- [ ] 同意过再杀进程重进：不再弹窗（本地 `pet_privacy_v1`）。
- [ ] 手改 `LEGAL_VERSION` 重新构建：再次弹窗（版本变化重弹）。
- [ ] 大厅右侧常驻「隐私与协议」入口可打开只读弹窗，正文可滚动、「平台隐私指引」能打开或不支持时给提示。
- [ ] 刘海机型（含 iPhone 灵动岛 / 安卓挖屏）标题与两个按钮不被遮；小屏（iPhone SE）正文可滚动、文字不裁剪；勾选框与按钮热区不小于 44×44。
- [ ] 同意前不产生任何云端请求（抓包或日志确认 `login` 在 `privacy_agree` 之后）。

### 5.2 分包与美术回退（W8-4，W9-3 接入）

- [ ] 首次进入病例介绍/领养页会触发 `warmArtBundle()`：日志有 `art_bundle_ready`（ art 到位）或 `art_bundle_fallback`（回退色块），两者都不阻塞首屏；首屏只等 `cases` 分包。
- [ ] 日志确认 art 分包路径为 `subpackages/art/`；`releaseArtBundle()` 只减引用，真正卸载由场景切换的 `Res.releaseUnused()` 完成，art 不常驻。

### 5.3 数据链路与幂等（W8-1 / W8-2）

- [ ] 大厅进入后 `getProfile` 成功：只看到本机微信号自己的档案与领养列表；换另一台设备登录不串数据。
- [ ] 看广告中途退出（`isEnded=false`）：不发奖，`ad_events` 有记录且 `granted=false`。
- [ ] 同一次广告重复上报（弱网重发）：`ad_events` 只有一行。
- [ ] 广告次数达当日上限后按钮置灰；新用户 24h 内上限 5 次生效。
- [ ] 助力第 6 次：客户端提示今日已达上限（`1005`），**不走本地兜底发奖**。
- [ ] 断网时看广告：`adEvent` 进本地 pending 队列（上限 20 条，按 `adSessionId` 去重），下次启动云端同步时自动补报，不重复计数。

### 5.4 埋点（W8-3）

- [ ] 切后台（Home 键）触发 flush：回到前台后云端 `track_events` 出现该批次。
- [ ] 队列攒到 50 条提前上报；断网持续操作 200 条上限后丢最旧、不死循环。
- [ ] 弱网失败批次回队首，下次重试；服务端参数拒绝（如 1002）直接丢弃不重传。

## 6. 日志与证据

1. 每轮预览记录：机型、微信版本、基础库版本、构建时间、`CLIENT_VERSION`、首屏耗时、是否出现 `boot_*` 埋点。
2. 性能数据用开发构建（勾选开发构建）的引擎 profiler 浮层记录 FPS / DrawCall，内存用 vConsole「内存」页签读数；内存目标 ≤200MB，低端机 ≤250MB。
3. 结论落到 `docs/release/真机预览记录-<日期>.md`，阻断级问题按《架构质检-W7》的分级写「阻塞/警告」。

## 8. 禁止事项

- 不把正式 AppID、云环境 ID、`SESSION_SECRET` 写回仓库或提交 `build/`、`project.config.json`、`project.private.config.json`。

- 不为了预览临时打开广告降级发奖或改支付通路；iOS 端保持 `PAY_UNAVAILABLE`。
- 未在真机验证过的合规项，不得在《提审检查清单》里勾成完成。
