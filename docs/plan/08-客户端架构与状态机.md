> **说明**：本文为 Cocos Creator 客户端的架构规划，不含已实现工程代码。所有类名、接口、事件名均为**建议**，需主程评审后定稿。原则：服务端权威、弱网可玩、配置外置、最小依赖。

## 1. 目标与范围

- 给出可直接搭工程骨架的模块划分、页面栈、状态机与接口约定。
- 明确“哪些逻辑必须在服务端、哪些可在客户端表现”，避免后期返工。
- 定义弱网重试、资源释放、埋点与异常兜底的最低标准。
- 输出模块职责表、GameFSM 白名单、伪代码、常见坑与验收标准。

不包含：具体小游戏实现（见 04）、广告 SDK 细节（见 11）、支付时序（见 12）、性能指标全表（见 15）。

## 2. 技术栈与约束

| 项 | 选型 | 约束 |
|---|---|---|
| 引擎 | Cocos Creator 3.x（建议） | 锁定小版本，禁用未验证插件 |
| 语言 | TypeScript | 开启严格模式，禁止 `any` 泛滥 |
| 渲染 | 2D | 不引入 3D 物理与重型后处理 |
| 平台 | 微信小游戏 | 主包与分包按平台限制规划 |
| 后端 | 微信云开发 | 客户端不直连数据库，只调云函数 |
| 配置 | 远程配置 + 本地兜底 | 配置外置，支持灰度与回滚 |

**硬约束：**

- 客户端不做发奖判定；所有资源、订单、助力结果以服务端返回为准。
- 客户端不硬编码数值；数值来自配置表，配置带版本号。
- 不引入第二套网络库、第二套状态管理；最小依赖，减少包体与冲突。

## 3. 模块职责表

| 模块（建议名） | 职责 | 不该做的事 |
|---|---|---|
| `Boot` | 启动、检查更新、拉配置、登录 | 不做业务逻辑 |
| `UIManager` | 页面打开/关闭、页面栈、弹窗层级、遮罩 | 不持有业务数据 |
| `GameFSM` | 全局状态与合法流转、状态进入/退出钩子 | 不直接操作 UI 节点 |
| `NetworkClient` | 请求封装、超时、重试、错误码映射 | 不拼业务参数 |
| `RetryQueue` | 弱网失败请求排队、幂等重放 | 不做奖励计算 |
| `CacheStore` | 本地缓存（存档快照、配置、登录态） | 不作为唯一数据源 |
| `ConfigService` | 配置加载、版本校验、热更、灰度为服务端下发 | 不在运行中改结构 |
| `AssetManager` | 分包/图集加载、引用计数、释放 | 不跨页持有无用引用 |
| `EventBus` | 模块间解耦事件 | 不传递大对象、不做跨局持久 |
| `AudioManager` | BGM/SFX、静音、切后台处理 | 不阻塞主流程 |
| `Analytics` | 埋点上报、失败重试、批量发送 | 不采集敏感信息 |
| `CaseFlow` | 单局流程编排（接诊→结算） | 不直接写云存档 |
| `EconomyView` | 资源展示与变更动画 | 不本地扣减后不校准 |

## 4. 页面栈

页面栈与 03 保持一致，采用**显式栈**管理，禁止用场景切换代替页面。

```text
Boot → Login → Lobby → CaseIntro → Diagnosis → Treatment → Recovery → Adoption → Result → Lobby
```

| 页面（建议） | 类型 | 是否入栈 | 返回策略 | 资源包 |
|---|---|---|---|---|
| `BootPage` | 全屏 | 否 | 不可返回 | 主包 |
| `LoginPage` | 全屏 | 否 | 不可返回 | 主包 |
| `LobbyPage` | 全屏 | 栈底 | 不可返回，仅退出 | 主包 |
| `CaseIntroPage` | 全屏 | 是 | 可返回大厅 | 病例包 |
| `DiagnosisPage` | 全屏 | 是 | 仅失败/退出可返回 | 小游戏包 |
| `TreatmentPage` | 全屏 | 是 | 不可返回，防误触 | 病例包 |
| `RecoveryPage` | 全屏 | 是 | 可跳过 | 病例包 |
| `AdoptionPage` | 全屏 | 是 | 可返回 | 图鉴包 |
| `ResultPage` | 弹层/全屏 | 是 | 关闭回大厅 | 主包 |
| 通用弹窗（设置/奖励/确认） | 弹层 | 否 | 关闭 | 主包 |

**规则：**

- 栈深超过 6 时禁止继续压栈，改为替换栈顶。
- `TreatmentPage` 为关键页，禁止手势返回；退出需二次确认。
- 所有页面 `onShow/onHide` 必须处理广告与切后台恢复。

## 5. GameFSM 状态机

### 5.1 状态白名单

| 当前状态 | 允许进入 | 说明 |
|---|---|---|
| `Boot` | `Login`, `Fatal` | 启动检查 |
| `Login` | `Lobby`, `Fatal`, `Offline` | 登录成功/失败 |
| `Lobby` | `CaseIntro`, `Adoption`, `Offline` | 大厅入口 |
| `CaseIntro` | `Diagnosis`, `Lobby` | 接诊确认 |
| `Diagnosis` | `Treatment`, `Diagnosis`（重试）, `Result`（放弃） | 小游戏 |
| `Treatment` | `Recovery`, `Treatment`（重试）, `Result`（失败退出） | 资源分配 |
| `Recovery` | `Adoption`, `Result` | 康复护理 |
| `Adoption` | `Result`, `Recovery`, `Lobby`（查看图鉴） | 领养/跳过 |
| `Result` | `Lobby`, `CaseIntro`（下一例） | 结算 |
| `Offline` | `Login`, `Lobby` | 断网恢复 |
| `Fatal` | 无 | 需重启 |

### 5.2 伪代码（建议）

```text
enum GameState { Boot, Login, Lobby, CaseIntro, Diagnosis, Treatment, Recovery, Adoption, Result, Offline, Fatal }

const WHITELIST: Record<GameState, GameState[]> = {
  Boot:       [Login, Fatal],
  Login:      [Lobby, Offline, Fatal],
  Lobby:      [CaseIntro, Adoption, Offline],
  CaseIntro:  [Diagnosis, Lobby],
  Diagnosis:  [Treatment, Diagnosis, Result],
  Treatment:  [Recovery, Treatment, Result],
  Recovery:   [Adoption, Result],
  Adoption:   [Result, Recovery, Lobby],
  Result:     [Lobby, CaseIntro],
  Offline:    [Login, Lobby],
  Fatal:      []
}

transition(next):
  if next not in WHITELIST[current]: logWarn(); return false
  await exit(current)
  await enter(next)
  current = next
  analytics.track("fsm_transition", { from, to })
  return true
```

**硬规则：**

- 所有状态切换必须走 `transition()`，禁止直接赋值。
- 状态进入失败（如配置未就绪）回退到上一个稳定态，不进入半初始化状态。
- 广告播放、支付、切后台期间压入 `Paused` 子标记，但不新增全局状态，避免状态爆炸。

## 6. 网络与弱网重试

### 6.1 请求约定（建议）

```text
request<T>({ name, data, idempotencyKey?, timeoutMs = 8000, retry = 2 })
  → { code, msg, data, serverTime? }
```

| 错误类型 | 处理 |
|---|---|
| 超时/断网 | 进入 `RetryQueue`，指数退避（1s/2s/4s），最多 2 次 |
| 登录态失效 | 静默重登一次，失败则回 `Login` |
| 业务错误（资源不足等） | 直接返回 UI，不重试 |
| 服务端 5xx | 重试 1 次后提示“稍后再试” |

### 6.2 重试队列

```text
enqueue(req):
  if req.idempotencyKey is empty: req.idempotencyKey = uuid()
  queue.push(req)
  persistQueue()            // 切后台不丢
  scheduleFlush()

flush():
  while online and queue.notEmpty:
    req = queue.peek()
    res = send(req)
    if res.code == OK or res.code is nonRetryable: queue.pop(); apply(res)
    else: backoffAndRetry(req)
```

**要求：**

- 所有写操作必须带 `idempotencyKey`，服务端去重（见 09）。
- 重试队列持久化到本地，冷启动后继续发送。
- 结算、支付、助力三类请求禁止静默丢弃，必须给用户明确状态。

## 7. 缓存与配置

| 缓存项 | 存储 | 失效策略 |
|---|---|---|
| 登录态 | 本地 Storage | token 过期或登出 |
| 存档快照 | 本地 Storage | 服务端版本号更新时覆盖 |
| 配置表 | 本地 + 内存 | 版本号变化时全量替换 |
| 图鉴/领养列表 | 内存 | 页面关闭释放，写操作后刷新 |
| 埋点队列 | 本地 Storage | 上报成功后删除 |

**配置原则：**

- 配置只增字段不轻易改类型；改结构必须升版本号。
- 客户端校验配置版本，低于最低版本强制更新。
- 配置缺失时使用本地兜底值，但上报告警，不静默使用默认值上线。

## 8. 资源管理与释放

| 策略 | 说明 |
|---|---|
| 分包 | 按页面划分：主包（Boot/Lobby/通用）、病例包、小游戏包、图鉴包 |
| 引用计数 | 每个资源包按页面引用计数，归零释放 |
| 释放时机 | 页面 `onDestroy` 后延迟 1 帧释放，避免动画引用 |
| 纹理 | 图集合并，单图 ≤1024，避免运行时大图 |
| 常驻资源 | 仅保留 UI 通用图集、字体、音频总线 |
| 预加载 | 只预加载下一页面，禁止全量预加载 |

**常见坑：**

- 页面关闭后事件未解绑，导致重复回调与内存泄漏。
- 广告 SDK 回调持有已销毁页面引用。
- 切后台再回前台，音频与计时器未恢复或重复计时。
- 分包加载失败未兜底，卡在 Loading。
- 频繁 `instantiate/destroy` 造成卡顿，需对象池。

## 9. 埋点与异常

| 事件（建议） | 触发 | 关键字段 |
|---|---|---|
| `page_view` | 页面打开 | page, from, caseId |
| `fsm_transition` | 状态切换 | from, to, duration |
| `case_start` | 接诊 | caseId, difficulty |
| `diagnosis_result` | 诊断结束 | type, stars, mistakes, duration |
| `treatment_result` | 治疗结束 | result, resourceUsed, adUsed |
| `adoption_result` | 领养 | cardId, adopted |
| `share_click` | 分享点击 | scene, cardId |
| `network_error` | 请求失败 | name, code, retryCount |
| `client_error` | 异常捕获 | message, stackHash |

**要求：** 埋点失败不阻塞玩法；批量上报；不采集 openid 以外的个人信息；异常上报做哈希脱敏。

## 12. 验收标准

- 主程可仅凭本文在第 1 周搭出可运行骨架：Boot → Lobby → 占位单局 → Result。
- 状态机在白名单外的切换 100% 被拦截，并有单测覆盖。
- 断网 10 秒内完成一次请求、恢复后自动重放，不重复发奖。
- 页面反复进出 20 次，内存无持续增长（真机验证）。
- 广告播放、切后台、来电中断后均能恢复到正确页面与状态。
- 配置版本变更可在不发版情况下生效，并可回滚。
- 客户端无任何本地发奖逻辑（代码评审确认）。

## 13. 风险与待验证假设

| 风险/假设 | 说明 | 验证方式 |
|---|---|---|
| 分包策略满足主包限制 | 主包可能超限 | 构建后检查包体（见 15） |
| 弱网重试不重复发奖 | 依赖服务端幂等 | 联调用例 |
| 配置热更稳定 | 结构变更可能导致崩溃 | 灰度 + 版本校验 |
| 状态机覆盖全部异常 | 广告/支付回调可能绕过 | 异常注入测试 |
| 低端机资源释放及时 | 图集过大可能 OOM | 真机矩阵测试 |

> **数据说明**：本文不含真实性能数据；包体、内存、帧率目标见 15，需以真机实测为准。
