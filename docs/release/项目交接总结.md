## 一、项目是什么

一款竖屏微信小游戏：玩家经营一间宠物救助医院，**街头寻访抽到流浪动物 → 接诊 → 诊断小游戏（拍片 / 化验连线 / 听诊节奏）→ 治疗资源分配 → 康复 → 领养 → 进小屋长线养成（喂食洗澡抚摸、美容剪指甲、种植后院、老年小毛病衰减）→ 送养**。变现只有激励视频广告，**无任何内购**。

| 项 | 值 |
|---|---|
| 引擎 | Cocos Creator 3.8（TypeScript 严格模式，禁裸 `any`） |
| 平台 | 微信小游戏（竖屏，`networkTimeout.request = 8000`） |
| 后端 | 自建 Axum（Rust）+ PostgreSQL，12 个 `POST /api/*` 路由 |
| 备用后端 | 13 个微信云函数（源码保留，本版**不部署**，决策-6d） |
| 提审包 | `build/wechatgame-release`，主包 3.51 MB / 分包 3.83 MB / 整包 7.34 MB |
| 合规面 | 适龄 8+、三份协议入口 + 客服、医疗免责句、最小权限（只采 OpenID） |

## 六、你要在 `pet.jiangker.cn` 上部署什么

**只有一套东西要部署：`server/` 这个 Rust 服务 + 一个 PostgreSQL。** 完整命令在 [../../deploy/README.md](../../deploy/README.md)，要点：

1. **服务**：镜像 `registry.cn-hangzhou.aliyuncs.com/jiangker/pet-api:latest`（由 `.github/workflows/api-image.yml` 构建推送），容器内监听 **3000**，宿主机映射 **`HOST_PORT=18766`**，Nginx 把 `https://pet.jiangker.cn:443` 反代到 `127.0.0.1:18766`。
2. **数据库**：一个 PG 库，用户需有**建表权限**——服务启动时自动执行 `server/migrations/001_init.sql`，建 **16 张表**：
   `users` / `hospital_state` / `pets` / `adoptions` / `pets_cases` / `config` / `leaderboard` / `assist_pairs` / `assist_daily` / `ad_events` / `ad_daily` / `track_events` / `sync_pending` / `habitat_state` / `habitat_claims` / `orders`
3. **配置种子**：启动时若 `config` 表里没有 `active` 的 `cases` / `quality`，自动从 `server/seed/cases.json` 灌入（与客户端 `cases.json` 同构）。**客户端和服务端两边病例表必须同版本**，改了客户端表要同步 `seed/`。
4. **环境变量**：`DATABASE_URL`、`WX_APPID`、`WX_SECRET`、`JWT_SECRET` 四个必填真值；`PENDING_MONITOR_SECS` 可选（默认积压监控周期）。
5. **12 个接口**（路径 = 冻结云函数名）：
   `POST /api/login` `/getConfig` `/getProfile` `/saveGame` `/syncCaseResult` `/leaderboard` `/assist` `/adEvent` `/claimHabitat` `/createOrder` `/payCallback` `/trackEvent` + `GET /health`。
   其中 `createOrder` / `payCallback` **按红线固定返回不可用**，不用为它们接任何支付回调。
6. **`WX_SECRET` 必须配**：不配则服务走「开发 openid」，每个客户端会被当成同一个用户，排行榜和存档全是假的。
7. **不需要部署**：13 个云函数、云存储、云数据库（本版 `CLOUD_ENV` 保持占位）。将来若切回云开发，才按《最终云函数部署操作单》走。

## 七、怎么验证前后端联调成功（三层，逐层做）

### 第 1 层：服务器自己活着（不依赖微信）

```bash
curl -i https://pet.jiangker.cn/health
# 期望 200。不通 → 查容器状态与 Nginx；502 → 容器没起来或 HOST_PORT 不对

curl -i -X POST https://pet.jiangker.cn/api/getConfig -H 'Content-Type: application/json' -d '{}'
# 期望 200 + {"code":...,"msg":...,"data":...,"serverTime":...}（未登录场景可能是业务码，只要不是 5xx 就说明路由与序列化通）
```

### 第 2 层：微信登录链路真通（关键）

```bash
curl -X POST https://pet.jiangker.cn/api/login -H 'Content-Type: application/json' -d '{"code":"<小程序 wx.login 拿到的真实 code>"}'
```

`code` 只能从小程序里取（在开发者工具控制台执行 `wx.login({success: r => console.log(r.code)})`，5 分钟内一次性有效）。
**期望**：`code: 0` 且 `data` 里有 token。这一步通 = `WX_APPID` / `WX_SECRET` 正确、`jscode2session` 拿到了真 openid。拿不到就去看容器日志里的微信返回码。

### 第 3 层：游戏内三条写链路（提审必拍 screenshots 的前置）

开发者工具导入 `build/wechatgame-release`，**取消勾选「不校验合法域名」**（否则本地永远"看着通"），然后：

| 验什么 | 操作 | 期望现象 | 说明什么 |
|---|---|---|---|
| 存档回读 | 大厅完成一局接诊→领养，杀进程重进 | 小屋住户与金币爱心不丢 | `saveGame` + `cloudsave` 通 |
| 排行榜 | 打开排行榜 TAB | **有你自己的一条记录** | `getProfile` + `leaderboard` 读通；这是提审截图的必备证据 |
| 好友助力 | 分享后回来看助力次数 | 次数 +1 且**重复点不加倍** | `assist` 服务端事务 + 幂等 |
| 离线收益 | 小屋领取 | 成功态或「今日次数已用完」两种之一 | `claimHabitat`；**未部署服务端时绝不能出金币**（红线） |
| 广告发奖 | 看完激励视频 | 发奖且当日次数 +1 | 仅在第 4 步替换真广告位后可验 |

排查顺序固定：**Network 面板看请求域名 → 看返回 `code` → 看容器日志**。返回 `code != 0` 是业务/数据问题（表没建、seed 没灌、幂等键重复）；根本没有请求 = 域名白名单没配或 `pet_api_base_v1` 覆盖位被写成了 `off`。

覆盖位提醒：`wx.setStorageSync('pet_api_base_v1','off')` 会把 HTTP 通路关掉回本地模式；`wx.removeStorageSync('pet_api_base_v1')` 回到源码默认 `https://pet.jiangker.cn`。**提审包里根本没有覆盖位**，走的就是源码常量。
