## 2. 云开发控制台准备

1. 创建云环境：测试环境与正式环境分开；环境 ID 只记录在本地备忘，不写入仓库与文档。
2. 运行配置：10 个函数统一 5 秒超时、256MB 内存；`leaderboard` 若数据量大再单独上调。
3. 环境变量（仅 `login` 需要，但建议全部函数统一配置）：
   - `SESSION_SECRET`：32 位以上随机串，用于 HMAC 签名 token；缺失时 `login` 抛 `SESSION_SECRET_MISSING`，客户端会走本地兜底。
   - 变量只在控制台配置，不写进代码、`.env`、文档或提交记录。
4. 数据库集合与索引（先建集合与普通索引，再建唯一索引，详见《集合与索引冻结》）：
   - 核心：`users`、`hospital_state`、`pets_cases`、`pets`、`adoptions`、`ad_events`、`orders`、`config`、`leaderboard`。
   - 辅助：`assist_logs`、`delivery_logs`。
   - W7 必须到位：`assist_logs` 的 `helperId + targetId + date` 唯一索引；`leaderboard` 的 `uniq_type_period_openid` 唯一索引与 `idx_type_period_score` 组合索引。
   - 权限：客户端全部关闭直读直写，只允许云函数服务端身份读写。
5. 若 `config` 集合为空，`getConfig` 返回空配置，客户端继续用本地默认值（含 `quality=high`），不阻塞进厅。

## 4. 部署后验证（控制台「云端测试」逐条执行）

| 函数 | 入参 | 期望 |
|---|---|---|
| `login` | `{ "version": "0.1.0", "channel": "dev" }` | `code: 0`，`data.token` 为非空字符串，`data` 中**没有 openid 字段** |
| `getConfig` | `{ "version": 0 }` | `code: 0`，`data.configs` 为对象；无配置时为空对象 |
| `saveGame` | `{ "revision": 1, "snapshot": { "state": {} } }` 连续两次 | 第一次 `code: 0`；第二次 `code: 1004` 且 `data.revision` 为当前最新 |
| `syncCaseResult` | 同一 `caseSessionId` 连续两次 | 两次返回一致，不产生重复奖励（当前为骨架，返回空结构） |
| `leaderboard` | `{ "type": "weekly", "page": 1, "pageSize": 5 }` | `code: 0`，`data` 含 `entries`、`self`、`total`、`page`、`pageSize`；榜单无数据时 `entries: []` |
| `leaderboard` | `{ "type": "friends", "page": 1, "pageSize": 5 }` | `code: 0`，`entries: []`、`total: 0`（关系链未接入） |
| `assist` | `{ "friendOpenid": "wx_friend_lin", "resourceType": "heart", "nonce": "n1" }` 连续两次 | 第一次 `granted: true`、`dailyCount` 递增；第二次 `granted: false`、`reason: "ALREADY_ASSISTED"` |
| `assist` | 连发 5 位不同 `friendOpenid` 后再发第 6 位 | 第 6 次 `granted: false`、`reason: "LIMIT"`、`dailyCount: 5` |
| `createOrder` | `{ "skuId": "any" }` | `code: 3002`、`msg: "PAY_UNAVAILABLE"` |
| `payCallback` | `{ "platformPayload": {} }` | `code: 3002`、`msg: "PAY_UNAVAILABLE"` |

**「token 而不是 openid」核对方法**：控制台测试 `login` 后查看返回 JSON，只出现 `token / isNewUser / serverTime / minVersion`；若出现 `openid` 字段即为泄露，立即回滚该版本。

**榜单写入说明**：W7 只实现了读取与分页，`leaderboard` 集合暂无服务端写入方；控制台看到「暂无排行」属正常。W8 接入结算写入后再验收真实榜单。

## 5. 客户端切换联调

1. 本地临时把 `assets/scripts/config/EnvConfig.ts` 的 `CLOUD_ENV` 改成测试环境 ID，**联调后改回 `ENV_PLACEHOLDER` 再提交**。
2. 构建时注入正式 AppID（命令见《提审前人工操作单》§2），产物 `build/wechatgame/project.config.json` 核对 appid。
3. 真机 / 开发者工具确认：不再出现 `boot_cloud_offline_fallback`；结算后 `syncCaseResult` 返回 `code: 0`；断网结算会写入待补发队列，下次启动自动补发。
4. 助力验证：联网时点击「分享求助」→ `assist` 返回 `granted: true`；断网时本地到账并出现 `assist_pending`，次日联网启动后 `assist_flushed`。

## 6. 回滚

1. 云函数：云开发控制台 → 函数详情 → 版本管理 → 回退到上一可用版本。
2. 客户端：`CLOUD_ENV` 改回 `ENV_PLACEHOLDER` 重新构建，走本地模式；不要删除云端集合与数据。
3. 数据库：索引回退前先确认无在跑事务；`assist_logs` 唯一索引回退会导致重复助力，需同步回滚 `assist` 函数版本。

## 7. 禁止事项

- 不在仓库、脚本、文档、截图中写入真实环境 ID、`SESSION_SECRET`、AppID、商户号。
- 不调用真实支付、不创建真实订单；`createOrder` / `payCallback` 保持 `PAY_UNAVAILABLE`。
- 不手改 `cloudfunctions/**/index.js`；不提交 `node_modules/`、日志、本地开发者工具配置。
- 不 force push；部署失败先看控制台调用日志，再决定回滚。
