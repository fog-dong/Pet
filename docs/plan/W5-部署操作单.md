> **说明**：本文只描述人工操作步骤。仓库内不出现真实环境 ID、appid、密钥；任何部署命令均由发布同学在微信开发者工具中手动触发，代码侧（含 Agent）不得调用部署命令。

## 1. 边界

- 本单只覆盖「测试环境」打通：创建环境、上传云函数、建集合与索引、冒烟校验。
- 不做真实支付接入（`createOrder` / `payCallback` 固定返回 `PAY_UNAVAILABLE`），不配置真实广告位。
- 不上线正式环境；正式环境另走发布流程。

## 2. 前置检查

1. 微信开发者工具已登录有云开发权限的账号，且已选择本小游戏 AppID（不是 `touristappid`）。
2. 仓库已执行 `npm run build:cloud`，`cloudfunctions/*/index.js` 与 `index.ts` 同步，首行为 `// GENERATED from index.ts by npm run build -- do not edit`。
3. 待部署函数共 10 个：`login`、`getConfig`、`getProfile`、`saveGame`、`syncCaseResult`、`leaderboard`、`assist`、`adEvent`、`createOrder`、`payCallback`。
4. 每个函数目录内 `package.json` 已声明 `wx-server-sdk` 依赖；不要在控制台手改云端依赖版本。

## 3. 步骤 A：创建云开发环境

1. 开发者工具 → 云开发 → 新建环境，命名如 `pet-test`，选择按量计费或测试套餐。
2. 记录环境 ID（形如 `pet-test-xxxxxx`），**只写在本地记事本，不写进仓库、不写进聊天记录**。
3. 确认环境状态为「可用」，记下数据库区域，后续建集合在同一环境。

## 4. 步骤 B：让客户端指向该环境（仅本地，不提交）

1. 本地把 `assets/scripts/config/EnvConfig.ts` 的 `CLOUD_ENV` 从 `ENV_PLACEHOLDER` 改为上一步的环境 ID。
2. **提交前必须改回 `ENV_PLACEHOLDER`**；该文件是唯一环境入口，禁止在其他文件出现环境 ID。
3. 若使用 CI 注入，则保持仓库内为占位符，由构建脚本替换，替换结果不得入库。

> 客户端行为：`CLOUD_ENV` 为占位符或 `wx.cloud.init` 失败时，`Net.init` 返回 false，Boot 直接走本地模式进大厅，单局可玩；领养/排行榜等需要会话的入口在 W5-2 起才依赖 token。

## 5. 步骤 C：上传云函数

对每个函数目录依次操作：

1. 开发者工具左侧 `cloudfunctions/<name>` 右键 → 「上传并部署：云端安装依赖」。
2. 等待部署完成后，在云开发控制台 → 云函数列表确认状态「正常」、运行环境 Nodejs 与 `package.json` 一致。
3. 逐个冒烟：控制台 → 云函数 → 测试，入参先用 `{}`，预期返回 `{ code, msg, data, serverTime }` 且不抛异常（`login` 返回 1001/1002 也属正常，说明鉴权与校验生效）。

建议顺序（被依赖的先上）：`login` → `getConfig` → `saveGame` → `syncCaseResult` → 其余。

## 6. 步骤 D：集合与索引

1. 按《数据库初始化清单》创建 9 个核心集合 + 2 个辅助日志集合。
2. 按《集合与索引冻结》建索引，重点是：
   - `users` 主键 `_id = openid`
   - `hospital_state` 主键 `_id = openid`，字段 `revision`
   - `pets_cases` 唯一索引 `caseSessionId`（`syncCaseResult` 幂等依赖）
3. 索引创建后等待状态变为「已生效」再跑冒烟。

## 7. 步骤 E：安全规则

1. 所有业务集合客户端读写权限设为「仅管理端」，客户端一律走云函数。
2. 关闭集合的「所有用户可读/可写」默认权限。
3. 不开启匿名登录直连数据库的能力。

## 8. 步骤 F：冒烟校验

| 用例 | 操作 | 预期 |
|---|---|---|
| 登录 | 客户端冷启动 | 日志出现 `login` 成功，无 `boot_login_failed` |
| 配置 | 冷启动后进大厅 | `getConfig` 返回 `code 0`；失败不阻塞进厅 |
| 存档 | 完成一局回大厅 | `saveGame` 返回 `code 0`，本地 `pet_cloud_rev_v1` 递增 |
| 结果上报 | 完成一局看结算页 | `syncCaseResult` 返回 `code 0`，无 `case_sync_queued` |
| 幂等 | 同一 `caseSessionId` 重放 | 返回历史结果，不重复发奖 |
| 冲突 | 手工把本地 revision 改小后重发 | 返回 1004，客户端提示「云端存档已更新，本地结算已同步」 |
| 断网 | 飞行模式完成一局 | 结算页提示「网络不可用，结算将在下次启动补发」，重连冷启动后队列清空 |

## 9. 步骤 G：回滚

1. 云函数回滚：控制台 → 云函数 → 版本管理 → 回退到上一可用版本。
2. 客户端回到本地模式：把 `CLOUD_ENV` 改回 `ENV_PLACEHOLDER` 重新构建，所有网络调用降级为本地流程，不阻断单局。
3. 集合数据不删除，只回滚代码；删除集合属高风险操作，需另行审批。

## 10. 禁止事项

- 不在仓库、日志、截图中出现环境 ID、AppID、密钥。
- 不使用 `wx.cloud.callFunction` 之外的通道调用云函数（业务代码只走 `Net.call`）。
- 不在 W5 阶段接入真实支付、真实广告位。
- 不由代码或自动化脚本执行部署；部署仅限人工在开发者工具内操作。
