## 1. 目标与范围

- 逐项确认仓库是否达到 Cocos Creator 可识别工程的最低条件。
- 区分“代码骨架可用”与“Cocos 工程可用”，避免把前者当成后者。
- 给出阻塞项、影响范围、解除条件与二次验证命令。

不包含：业务逻辑正确性、云函数部署、真机性能、微信开发者工具导入。

## 3. 阻塞项影响

| 阻塞项 | 影响 | 不阻塞的部分 |
|---|---|---|
| C1 无 `.meta` | Creator 首次导入会重新分配 UUID，脚本/预制体引用可能丢失 | `.ts` 内容编写、`tsc --noEmit` |
| C2 无 `settings/` | 无法保存项目设置、构建配置与平台参数 | 文档与代码骨架 |
| C3 无根 `tsconfig.json` | 编辑器与 IDE 无法按 Cocos 类型解析 | `tsconfig.scaffold.json` 的独立类型检查 |
| C4 无 `package.json` | Creator 可能不把目录识别为项目 | 云函数独立目录 |
| C9 未安装 Creator | 无法预览、构建、生成 `.meta` | 本地 TypeScript 开发 |

## 4. 解除条件

必须同时满足以下条件，才可把状态改为“通过”：

1. 用户按《环境安装报告》第 4 节完成 Dashboard 安装、登录与 Creator 3.8 LTS 安装。
2. 在仓库根目录用 Creator 打开工程一次，生成 `settings/`、`library/`、`temp/`。
3. `assets/scripts/**/*.ts` 全部生成同名 `.meta`，且未手工修改 UUID。
4. 根 `tsconfig.json` 存在，`"types"` 含 `"cocos"`；根 `package.json` 存在。
5. 第 5 节命令全部通过。

## 9. 风险与待验证假设

| 风险/假设 | 说明 | 应对 |
|---|---|---|
| 先写代码后补 `.meta` | 脚本引用可能在导入时错乱 | 安装后只做“打开工程 → 生成 `.meta`”，不手工改 UUID |
| 合并临时工程覆盖脚本 | 复制 `assets/` 时误删现有 7 个 `.ts` | 合并前备份，逐文件比对 |
| `.gitignore` 再次误伤 | 新增规则使用无锚点目录名 | 所有生成目录规则必须以 `/` 开头 |
| 克隆验证被跳过 | 只在本地看 `git status` | 必须 clone 到临时目录重复第 5 节命令 |
| 版本漂移 | 成员使用不同 Creator 3.x | 统一 3.8 LTS，升级需制作人确认 |
