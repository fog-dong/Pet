## 二、逐项详情

### 1. W13-B 积压监控 — 通过

- 数据来源说明：W13-2 的待同步队列在玩家手机 `sys.localStorage`，云端不可见；W14-1 增加服务端等价集合 `sync_pending`：`syncCaseResult` 返回 2002 时写标记（同局保留最早 `firstSeenAt`），清算成功时删除（`cloudfunctions/syncCaseResult/pending.ts:22-48`、`index.ts:116`、`:134`）。
- 只读：`pendingMonitor/index.ts` 只有 `count()` 查询，无 `add/set/update/remove`（grep 为空）；返回 `{ code: 0, data: { total, nearExpiry, expired } }`，不修改任何数据。
- 口径一致：TTL 7 天、剩余 ≤2 天算「即将过期」，与客户端 `PendingTtl` 同口径；`nearExpiry = count(≤ now-5d) - count(≤ now-7d)`，避免依赖 `and` 组合命令。
- 触发器：`config.json` 仅一个 `pendingMonitorDaily`，cron `0 0 9 * * * *`（7 段，UTC+8 每天 09:00）；`build:cloud` 产出 12 个函数、22 个文件并带 GENERATED 头。
- 操作单：`docs/plan/W14-积压监控操作单.md` 明确「上传云函数不等于上传触发器，必须右键上传触发器」；告警策略对象/指标/5 分钟/`>0`/持续 2 周期/每小时/群告警；并说明平台只有错误次数与运行时间两类指标，积压数量靠 `pending_aging` 日志检索。
- 覆盖边界已登记：服务端只能看到「打到云函数并返回 2002」的单局，纯网络失败与 1006 不会产生标记（W14-B）。

### 2. W13-C 游客升级补发 — 通过

- `startCloudSync()` 改为返回 `{ ready, done }`（`core/BootCloud.ts:41-54`）；`syncCloud()` 在 login 成功后 **`await flushPending()`** 再拉配置并 resolve `true`（`:61-87`）。
- 升级回调 `openPrivacyEntry` 改为传 `CloudSyncStart`（`ui/PrivacyDialog.ts:130-143`）；大厅 `onPrivacyClick` 调 `SyncBadge.finishUpgrade`（`ui/Lobby.ts:95-99`）：
  - 先显示「正在同步本地结算…」（`PRIVACY_SYNCING_TEXT`）；
  - `cloud.done` 后 `refresh()` 角标，再显示「已启用」或「云环境未配置，仍用本地存档」；
  - 不再等下一次启动，也不再出现「升级后第一轮补发被跳过」。
- 失败语义：login 失败 → `done(false)`，补发未执行、队列保留；2002 → `defer` 留队，`SyncBadge` 显示待同步条数；不误判成功。
- 其他两个触发点未受影响：启动 `core/BootCloud.ts:73` 仍调 `flushPending`（现为 await，顺序更确定）；结算成功 `game/Result.ts:101` 不变。

- 局限（W14-C）：从「关于」面板升级时，大厅角标不会立刻出现（角标由大厅持有），但补发已当场完成；金币不丢，仅提示要等下次进厅/重启。
