## 4. 上传步骤（云开发控制台，人工）

### 4.1 上传音频文件

云开发控制台 → 当前环境 → **存储** → 新建目录 `sfx/` → 上传 9 个文件。建议格式 **mp3（单声道、44.1 kHz、96–128 kbps）**，兽叫 0.6–1.2 s、提示音 0.1–0.3 s，单条控制在 60 KB 内。

上传后记下每个文件的 `cloud://<env>/<bucket>/sfx/xxx.mp3` 完整 fileID（控制台文件详情里可复制）。

### 4.2 生成清单字段

对每个文件算 `size`（字节）与 `md5`（32 位小写十六进制）：

```bash
# 本机执行，只读本地素材，不碰云端
md5sum sfx_cat_cry.mp3 && stat -c %s sfx_cat_cry.mp3
```

### 4.3 写 `config` 文档

数据库 → `config` 集合 → 添加记录，字段口径见《W17-云存储资源管线设计》§清单结构：

| 字段 | 值 |
|---|---|
| `configKey` | `resource_manifest` |
| `version` | `1`（每次改清单递增） |
| `status` | `active` |
| `grayPercent` | `100` |
| `payload` | 见下方 JSON |

```json
{
  "version": 1,
  "files": [
    { "key": "sfx_cat_cry",      "path": "cloud://<环境ID>/<桶>/sfx/cat_cry.mp3", "kind": "audio", "md5": "<32位>", "size": <字节>, "version": 1 },
    { "key": "sfx_dog_cry",      "path": "cloud://<环境ID>/<桶>/sfx/dog_cry.mp3", "kind": "audio", "md5": "<32位>", "size": <字节>, "version": 1 },
    { "key": "sfx_rabbit_cry",   "path": "cloud://<环境ID>/<桶>/sfx/rabbit_cry.mp3", "kind": "audio", "md5": "<32位>", "size": <字节>, "version": 1 },
    { "key": "sfx_bird_cry",     "path": "cloud://<环境ID>/<桶>/sfx/bird_cry.mp3", "kind": "audio", "md5": "<32位>", "size": <字节>, "version": 1 },
    { "key": "sfx_treat_success","path": "cloud://<环境ID>/<桶>/sfx/treat_success.mp3", "kind": "audio", "md5": "<32位>", "size": <字节>, "version": 1 },
    { "key": "sfx_recover_tick", "path": "cloud://<环境ID>/<桶>/sfx/recover_tick.mp3", "kind": "audio", "md5": "<32位>", "size": <字节>, "version": 1 },
    { "key": "sfx_feed",         "path": "cloud://<环境ID>/<桶>/sfx/feed.mp3", "kind": "audio", "md5": "<32位>", "size": <字节>, "version": 1 },
    { "key": "sfx_bath",         "path": "cloud://<环境ID>/<桶>/sfx/bath.mp3", "kind": "audio", "md5": "<32位>", "size": <字节>, "version": 1 },
    { "key": "sfx_pet",          "path": "cloud://<环境ID>/<桶>/sfx/pet.mp3", "kind": "audio", "md5": "<32位>", "size": <字节>, "version": 1 }
  ]
}
```

**校验规则（`CloudResManifest.ts:validEntry`，不满足就整条被丢弃，客户端静默无该音效）**：

- `key`：`[A-Za-z0-9_-]{1,64}`，且必须与 `AudioConfig.ts` 的 `cloudKey` **逐字相同**；
- `path`：必须 `cloud://` 或 `https://` 开头，长度 ≤ 512，扩展名音频限 `mp3/m4a/aac/ogg/wav`；
- `size`：非负整数，≤ 64 MB；`version`：≥ 1 的整数；
- `md5`：可留空；一旦填，必须是 32 位小写十六进制（**大写会被判非法并丢掉整条**）；
- 顶层 `version` 必须是 ≥ 0 的整数、`files` 是数组且 ≤ 500 条，否则整份清单被判非法。

### 4.4 生效路径

`getConfig` 的白名单已含 `resource_manifest`（`cloudfunctions/getConfig/index.ts:37`），**不需要改云函数**。客户端 `BootCloud.ts:101` 在拿到配置后调用 `CloudResManager.setManifest(...)`，不 await 下载；首次触发某 cue 时才 `wx.cloud.downloadFile` → 校验 size/MD5 → 写入本地缓存目录 → 记索引。

所以顺序是：**上传文件 → 写 config 文档 → 客户端重启**（清单本地缓存在 `pet_cloud_manifest_v1`，改清单后要么等 `getConfig` 下发新版本，要么清这个 key）。

## 5. 上传后验证

1. 云开发控制台确认 9 个文件存在、大小与清单 `size` 一致。
2. 客户端（真机或开发者工具，需已配好云环境）触发：接诊一只猫 → 听兽叫；完成一次治疗 → 听 `treatOk`；小屋喂食/洗澡/抚摸 → 声音应从**合成哔**变成真实音频（合成兜底只在解析不到真实素材时触发）。
3. 二次进入同一屏不再产生下载请求（`lookup` 命中要求版本一致 + 大小一致 + 文件仍在）。
4. 断网重进：仍按兜底/静默处理，不卡玩法。
