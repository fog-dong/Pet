# W17 动物行为与音效系统

> 状态：W17-3 设计 + 实现（五档行为状态机 + 六个音效触发点，全部走 W17-2 的资源管线）。
> 边界：不新增云函数、不新增集合、不改冻结接口；音频与动作帧只通过 `resource_manifest` 下发。
> 依据：00 §16 执行边界、08 §角色展示、10 §3.8.1 `resource_manifest`、W17-云存储资源管线设计.md §2。

## 1. 目标

1. **行为可分档**：同一只宠物按玩法阶段呈现不同状态（呼吸 / 萎靡 / 摇尾 / 跳跃 / 休息），不依赖新美术也能先跑起来。
2. **音效集中管理**：业务代码只传语义化的 cue，路径、云存储 key、音量、是否必要一律来自 `config/AudioConfig.ts`。
3. **缺资源不降级玩法**：没有动作帧、没有音频文件、没有网络、没有清单，宠物只显示静态立绘或占位块，页面照常可玩。
4. **低端机可控**：`Quality.low`（由 `getConfig` 的 `quality` 远程控制）关闭循环位移与非必要音效、不播帧序列。

## 2. 行为状态机

`PetState = 'idle' | 'sick' | 'recover' | 'happy' | 'sleep'`（定义在 `game/CharacterLook.ts`，是唯一口径）。

| 状态 | 语义 | 出现页面 | 静态姿态 | 循环位移 | 帧序列 key 前缀 |
|---|---|---|---|---|---|
| `idle` | 待机呼吸 | 大厅医生、听诊、图鉴大图 | 原尺寸 | 缩放 1.00→1.03，1.1s 一来回 | `pet_{name}_idle_` |
| `sick` | 生病萎靡 | 接诊页 | 缩放 0.94，不循环 | 无 | `pet_{name}_sick_` |
| `recover` | 康复中轻微摇尾 | 康复页进度中 | 缩放 0.97 | 绕 Z 轴 −4°→+4°→0°，各 0.5s | `pet_{name}_recover_` |
| `happy` | 领养后开心跳跃 | 康复完成、领养页（好感达标） | 原尺寸 | Y 轴 +12px→−12px，各 0.24s | `pet_{name}_happy_` |
| `sleep` | 休息 | 领养页（好感未达标） | 原尺寸 | 缩放 1.00→1.015，2.2s 一来回 | `pet_{name}_sleep_` |

位移上限（缩放 ≤1.06 / 旋转 ≤4° / 位移 ≤12px）是硬约束：角色是页面配角，不能和主操作抢注意力。

色调与状态绑定（`stateTint`）：`sick` 全灰、`recover` 按康复进度从灰到原色连续提亮、其余原色。康复完成切 `happy` 时自然回到全亮。

### 2.1 分层与职责

```
CharacterView（角标 + 标题 + 色调）
    └─ PetVisual（立绘/占位/阴影 + playState）
        └─ PetBehavior（状态 → 位移循环 + 帧序列播放，setTimeout 170ms/帧）
            └─ PetFrames（清单前缀 → SpriteFrame[]，命中即缓存）
                └─ CloudResManager（W17-2 管线：缓存 → 下载 → 解码）
```

- `PetVisual.apply(petId)` 与 `PetVisual.playState(state)` 是两个独立入口：只想要静态立绘的页面（图鉴 72px 缩略图、听诊小卡）不调 `playState`，因此不产生任何定时器。
- 帧序列与静态立绘共用 `showFrame` 同一条显示路径；帧未取到时画面停留在分包立绘，取到后由行为层接管换帧。
- 每次 `play()` 递增 token，晚到的异步帧序列若 token 已过期就丢弃，避免快速切页时旧帧盖住新状态。

### 2.2 帧序列清单约定

- key：`pet_{artName}_{state}_{01}`，序号两位补零，字典序即播放序；`artName` 是 `petId` 去掉 `pet_` 前缀（与分包 `pets/{artName}.png` 同名）。
- `kind` 必须是 `image`，单状态最多取 **8 帧**（超出直接忽略，防止清单误填大序列拖垮下载）。
- 只登记到 `resource_manifest`，不进分包：一套 3–6 帧约 1–6MB，超出 art 分包预算。

## 3. 音效触发点

`AudioCue` 共六个，全部在 `config/AudioConfig.ts` 里定义；业务侧唯一入口是 `game/Sfx.ts` 的 `Sfx.play(cue)`。

| cue | 触发时机 | 触发文件 | cloudKey | 分包路径 | 必要音效 | 音量 |
|---|---|---|---|---|---|---|
| `catCry` | 接诊页出现猫科病例 | `game/CaseIntro.ts` | `sfx_cat_cry` | — | 是 | 0.6 |
| `dogCry` | 接诊页出现犬科病例 | `game/CaseIntro.ts` | `sfx_dog_cry` | — | 是 | 0.6 |
| `rabbitCry` | 接诊页出现兔类病例 | `game/CaseIntro.ts` | `sfx_rabbit_cry` | — | 是 | 0.5 |
| `birdCry` | 接诊页出现鸟类病例 | `game/CaseIntro.ts` | `sfx_bird_cry` | — | 是 | 0.5 |
| `treatOk` | 治疗评分过门槛、进入康复前 | `game/Treatment.ts` | `sfx_treat_success` | — | 是 | 0.7 |
| `recoverTick` | 康复进度每越过 25%（25/50/75/100） | `game/Recovery.ts` | `sfx_recover_tick` | `audio/ui/recoverTick` | 否 | 0.35 |

- 品种 → cue 的映射只在 `AudioConfig.speciesCue()` 里；`pets.json` 出现未登记品种时返回 `null`，`Sfx.play(null)` 直接跳过。
- 里程碑用 `game/RecoveryMilestones.ts` 单独记账：广告加速一次跨过两档也只响一声，避免连响。
- 动物叫声按 W17-2 判定规则属"体积较大、非每次会话必用"，只走云存储；只有短促的进度提示音允许同时登记分包路径。

### 3.1 播放链与并发

```
Sfx.play(cue)
  → Quality.low && !essential → 直接返回
  → 已解析过 → 分包 AudioClip 走 AudioSource.playOneShot / 本地音频文件走原生播放器
  → 未解析过 → 先用 bundle.getDirWithPath 探一次分包里有没有这条音频
              → 有 → warmArtBundle 取分包 AudioClip
              → 没有/探测失败 → CloudResManager.ensure(cloudKey)
              → 拿到本地沙盒路径 → wx.createInnerAudioContext 播一次即销毁
              → 都拿不到 → 记 sfx_unavailable，该 cue 本会话不再重试
```

- 分包探测是必须的：`bundle.load` 一条不存在的路径会让引擎在控制台刷红色资源缺失错误，直接违反「Console 无新增红色报错」的验收口径。

- 原生播放器并发上限 4，超时 6s 强制回收，避免机型不回调 `onEnded` 时计数泄漏。
- 引擎 `AudioSource` 节点挂在当前场景下，切场景失效后自动重建，不跨场景常驻。
- 平台 API 只在 `net/AudioFile.ts` 内出现（AGENTS 硬约束 3）；`game/` 与 `ui/` 不碰 `wx`。

## 4. 降级矩阵

| 场景 | 行为表现 | 音效表现 |
|---|---|---|
| 无网络 / 未同意隐私 | 分包立绘 + 位移循环；分包也没有则占位块 | 分包音效可播，云音效静默 |
| `resource_manifest` 缺失或非法 | 无帧序列，只有位移；静态立绘不变 | 只有分包内音效，其余静默 |
| 清单有但下载失败（含超时） | 同上；单 key 本会话最多重试 3 次 | 同上；cue 解析失败后不再重试 |
| 图片解码失败 | 保留上一张已显示的帧或分包立绘 | — |
| 音频文件损坏 | — | `onError` 记 `cloud_audio_failed`，不重试 |
| `Quality.low`（远程 `quality=low`） | 只保留静态姿态（`sick` 0.94 / `recover` 0.97 / 其余原尺寸），不播帧序列 | 只播必要音效，`recoverTick` 静音 |
| 平台不支持 `createInnerAudioContext` | — | 云音效分支直接返回，不报错 |

任何一条降级路径都不产生未捕获异常，也不阻塞页面切换。

## 5. 埋点

沿用 `track/Track.ts`，新增事件：

| 事件 | 含义 |
|---|---|
| `sfx_unavailable` | cue 解析失败（分包与云存储都没有），属性 `cue` |
| `cloud_audio_failed` | 原生播放器报错 |
| `cloud_audio_destroy_failed` | 销毁实例异常（仅计数泄漏兜底告警） |

原有 `cloud_res_ready` / `cloud_res_failed` / `cloud_res_manifest*` 继续覆盖帧序列的下载侧。

## 6. 运营侧接入步骤（人工，不在代码内）

1. 出图：每只宠物每状态 3–6 帧透明 PNG（与分包立绘同构图，仅姿态差异）。
2. 上传云存储：`pet-res/actions/{artName}/{state}_{01}.png`、`pet-res/audio/pets/{species}_{cue}.mp3`。
3. 生成清单条目（`key` 用 §2.2 / §3 的约定，`md5` + `size` + `version` 逐条填），写入 `config` 集合 `configKey='resource_manifest'` 并置 `status='active'`。
4. 版本号递增发布；客户端下次 `getConfig` 自动收敛，旧缓存按 LRU 淘汰。
5. 需要低端机静音时，把 `configKey='quality'` 的 payload 设为 `low`（远程开关，不需要发版）。

## 7. 验收

- [ ] 接诊页：猫/狗/兔/鸟四种病例进入各响一次对应叫声；未登记品种不响且不报错。（需 §6 素材与清单到位后真机复验）
- [ ] 治疗页：过门槛后进康复前响一次 `treatOk`；未过门槛不响。（同上）
- [x] 康复页：进度每越过 25% 响一次，100% 时切 `happy` 跳跃；广告加速一次跨两档只响一声。
- [x] 领养页：好感达标 → 跳跃；未达标 → 休息缓慢呼吸。
- [x] 图鉴/听诊等只调 `apply` 的页面不新增定时器（无 `PetBehavior` 实例）。
- [x] 无清单 + 无云音效：以上页面全部照常渲染，Console 无新增红色报错。
- [ ] `configKey='quality'` 设为 `low` 后重进单局：无循环位移、无帧序列、`recoverTick` 静音。（需运营发布 quality 配置后复验）
- [x] `tsc --noEmit` ×3 全绿；微信开发者工具清缓存后重新编译，Console 无新增红色报错（人工步骤）。
