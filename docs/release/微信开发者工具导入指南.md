# 微信开发者工具导入指南

> 适用版本：Cocos Creator 3.8.0 + 微信开发者工具稳定版
> 结论先行：**导入 `build/wechatgame-release`，不要导入仓库根目录。**

## 一、故障现象

在微信开发者工具里打开 `C:\Users\15181\Desktop\项目\pet`（仓库根目录）后报：

```
Error: game.json: 未找到 game.json 文件，或者文件读取失败
File: game.json
```

## 二、根因

仓库根目录是 **Cocos 工程**，不是**小游戏运行目录**。小游戏的 `game.json` / `game.js` / `project.config.json` 只存在于 Cocos 构建产物里：

- 根目录没有 `game.json`（构建产物才有）；
- 根目录存在一个**本机私有**的 `project.config.json`（被 `.gitignore` 第 32 行忽略，内含真实 AppID），DevTools 看到它会误以为根目录就是一个可运行的小游戏项目，于是去找同目录的 `game.json` 并失败。

所以报错不是工程配置坏了，而是**导入路径选错**。

## 四、人工操作步骤

1. 打开微信开发者工具，选择左侧 **「小游戏」→「导入项目」**（不是「打开项目」，也不是「新建项目」）。
2. **目录**：选择
   `C:\Users\15181\Desktop\项目\pet\build\wechatgame-release`
   不要选整个 `pet` 仓库根目录，也不要选 `build` 上一级。
3. **AppID**：填入小游戏的正式 AppID（`wxf00c2f06e91cc917` 为本机已在用的值，仅手工填写，不写进仓库）。
   构建模板里默认是 `touristappid`（游客模式），只能预览，不能上传、不能调云函数。
4. 项目名称随意（默认 `Pet`），点击「导入」。
5. 导入后在「详情 → 本地设置」确认：
   - 编译类型为「小游戏」；
   - 云开发根目录能被识别（构建模板已写入 `cloudfunctionRoot: "../../cloudfunctions/"`，相对构建目录指回仓库的 `cloudfunctions/`）。
6. 首次使用云开发时，在工具栏「云开发」里选择或创建环境；环境 ID 与 `assets/scripts/config/EnvConfig.ts` 保持一致。

## 五、关于 miniprogramRoot

构建模板 `build-templates/wechatgame/project.config.json` 当前为：

```json
"miniprogramRoot": "./",
"appid": "touristappid"
```

`"./"` 与空字符串 `""` 的含义一致（都表示“项目根目录即小游戏根目录”），**不需要改成 `""`**，改了也不会影响 `game.json` 的查找——本次报错与 `miniprogramRoot` 无关，纯粹是导入目录错了一级。若后续想统一文案，可改为 `""` 并重建，但属于无收益改动。

## 六、重新构建（改了代码之后）

```bash
unset ELECTRON_RUN_AS_NODE
"C:/ProgramData/cocos/editors/Creator/3.8.0/CocosCreator.exe" \
  --project "C:/Users/15181/Desktop/项目/pet" \
  --build "platform=wechatgame;debug=false;outputName=wechatgame-release;startScene=0b556a8f-2609-451f-a9e7-30d58d1553da"
```

成功标志：日志出现 `build success in ... ms!`（该进程退出码 36 属已知现象，以日志为准）。
构建会**覆盖** `build/wechatgame-release/`，DevTools 无需重新导入，点「编译」即可。

## 七、注意事项

- `build/`、`temp/`、`library/` 均为生成物，**不进 Git**；DevTools 会往构建产物里写真实 AppID 和本地设置，重跑构建即恢复模板值，不会污染仓库。
- 仓库根目录的 `project.config.json` 只服务本机，**禁止提交**（已在 `.gitignore` 中）。
- 云函数上传、环境选择、真机预览都必须由人工在工具内操作，Agent 不执行部署命令。
- 提审时上传的也是这个目录（或工具内「上传」按钮的同一项目），上传前确认包体：主包 3,416,547 B、分包 10,488 B、合计 3.27 MB。
