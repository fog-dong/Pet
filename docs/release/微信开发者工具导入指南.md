# 微信开发者工具导入指南

> 适用版本：Cocos Creator 3.8.0 + 微信开发者工具 Stable 2.02.2608080
> 结论先行：**导入 `build/wechatgame-release`，不要导入仓库根目录。**

## 一、故障现象与根因

### 1.1 `game.json 未找到`

导入 `C:\Users\15181\Desktop\项目\pet`（仓库根目录）后报：

```
Error: game.json: 未找到 game.json 文件，或者文件读取失败
File: game.json
```

仓库根目录是 **Cocos 工程**，不是小游戏运行目录：`game.json` / `game.js` 只在构建产物里；根目录那个 `project.config.json` 是本机私有的（`.gitignore` 已忽略，含真实 AppID），DevTools 被它误导，去根目录找 `game.json` 就失败了。

### 1.2 `libVersion 字段需为 string`

已导入正确目录后仍可能报：

```
[ project.config.json 文件内容错误] project.config.json: libVersion 字段需为 string, string
(env: Windows,mg,2.02.2608080; lib: 3.17.6)
```

原因：Cocos 3.8 内置微信模板把 `libVersion` 写成占位值 `"game"`。旧版工具容忍这个值，新版 Stable 要求必须是**真实基础库版本号字符串**（如 `"3.17.6"`）。消息末尾重复的 `string` 是工具自身的文案 bug，不用管。

修复：`build-templates/wechatgame/project.config.json` 中已改为

```json
"libVersion": "3.17.6"
```

重建一次即生效。以后 DevTools 升级、默认基础库变化时，如提示版本不存在，在「详情 → 本地设置 → 调试基础库」选最新版，把模板里的值同步过来再重建。

### 1.3 云开发未开通时的 `Cloud API isn't enabled`

```
Error: SystemError (gameSDKScriptError) errCode: -1
errMsg: Cloud API isn't enabled, please call wx.cloud.init first
```

两类原因一起处理：

1. 客户端在 `Net.init` 成功前发起了 `wx.cloud.callFunction`。已在 `Net.call` 里加前置判断：未初始化直接返回断网错误码，不再触碰微信云 API。
2. 本机 AppID 还没开通「云开发」时，`project.config.json` 里的 `cloudfunctionRoot` 会让 DevTools 去探测云环境，同样抛这条错。**因此模板在没有云环境 ID 前不再输出 `cloudfunctionRoot`**；等开通云开发、拿到环境 ID 后，再把它加回模板并复制 `cloudfunctions/`（见第五节）。

## 三、人工操作步骤

1. 打开微信开发者工具，左侧选 **「小游戏」→「导入项目」**（不是「打开项目」，也不是「新建项目」）。
2. **目录**：选 `C:\Users\15181\Desktop\项目\pet\build\wechatgame-release`。
   不要选整个 `pet` 仓库根目录，也不要选 `build` 或它的上一级。
3. **AppID**：填正式小游戏 AppID（本机已记录在被忽略的根 `project.config.json` 中，`npm run wx:appid` 会读它自动注入产物；文档与仓库不出现明文）。
   仓库模板始终是 `touristappid`；每次重建后在本机执行 `npm run wx:appid` 注入正式 AppID（脚本只改产物，不改仓库）。只在此处手填，绝不写进仓库。
4. 项目名称随意（默认 `Pet`），点「导入」。
5. 若上次已导入过且仍报错：先 **关闭该窗口**，重新「导入项目」选同一目录；或在「工具 → 清缓存 → 全部清除」后重新编译。旧窗口可能缓存了修改前的 `project.config.json`。
6. 进入后确认「详情 → 本地设置」：编译类型为小游戏。云函数面板在开通云开发之前为空，属正常。

## 四、关于 miniprogramRoot

模板当前为 `"miniprogramRoot": "./"`。它与空字符串 `""` 语义一致（都表示“项目根目录即小游戏根目录”），**不需要改**；本次两类报错都与它无关。

## 五、重新构建与产物准备

```bash
unset ELECTRON_RUN_AS_NODE
"C:/ProgramData/cocos/editors/Creator/3.8.0/CocosCreator.exe" \
  --project "C:/Users/15181/Desktop/项目/pet" \
  --build "platform=wechatgame;debug=false;outputName=wechatgame-release;startScene=0b556a8f-2609-451f-a9e7-30d58d1553da"

# 构建成功后：注入本机正式 AppID（只改产物，不入库）
npm run wx:appid
# 等价写法（不依赖本机 project.config.json）：
# WX_APPID=<正式AppID> node scripts/apply-wechat-appid.js
```

- 成功标志：日志出现 `build success in ... ms!`；进程退出码 36 属已知现象，以日志为准。
- 构建会**清空并覆盖** `build/wechatgame-release/`，因此 AppID 注入必须在构建之后做；DevTools 已打开时先关窗再重开。
- **开通云开发并拿到环境 ID 之后**：把 `EnvConfig.CLOUD_ENV` 换成真实环境 ID，在模板里恢复 `"cloudfunctionRoot": "cloudfunctions/"`，再执行 `cp -r cloudfunctions build/wechatgame-release/cloudfunctions` 并重建。在此之前不复制、不配置，避免 DevTools 探测未开通的云环境。
- 包体现状：主包 3,419,177 B / 分包 10,488 B / 合计 3.27 MB（上限 4 MB）。

## 六、注意事项

- `build/`、`temp/`、`library/` 均为生成物，**不进 Git**；DevTools 写入的真实 AppID、基础库选择只留在本机产物里，重建即恢复模板值。
- 仓库根目录的 `project.config.json` 只服务本机，**禁止提交**（已含正式 AppID）。
- **AppSecret 不落盘**：本项目的 openid 由云函数 `cloud.getWXContext()` 提供，客户端与云函数都不需要 AppSecret；它只用于公众平台换取 access_token 等后台操作，请保存在密码管理器中，任何文件、提交、截图都不要出现。
- 云函数上传、环境选择、真机预览必须人工在工具内操作，Agent 不执行部署命令。
- 提审上传的也是这个目录；上传前确认包体不超限（当前合计 3.27 MB，主包上限 4 MB）。
