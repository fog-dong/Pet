## 1. 目标与范围

### 1.1 项目目标

在 12 周内做出可软测的微信小游戏 MVP，验证三件事：

1. “宠物医院 / 救助经营”是否有足够搜索需求与首局留存。
2. 3-5 分钟单局 + 轻长线经营能否同时支撑 IAA 与 IAP。
3. 买量成本能否被混合变现覆盖，模型是否值得放量。

### 1.2 范围边界

- **包含**：单局诊断/治疗、康复、领养、图鉴、轻社交、医院扩建、IAA、IAP、数据分析。
- **不包含**：实时多人、跨服战、公会战、重度 SLG、UGC 编辑器、宠物繁育、写实医疗。
- **平台**：微信小游戏，竖屏，单手操作。
- **技术栈**：Cocos Creator + 微信云开发。

### 1.3 成功定义

达到以下核心指标，视为 MVP 通过，可进入放量测试：

| 指标 | 目标 |
|---|---|
| D1 留存 | ≥35% |
| D7 留存 | ≥12% |
| D30 留存 | ≥5% |
| 综合 ARPDAU | ≥0.5 元 |
| LTV/CPA（30 日） | ≥1.2 |
| CPI | ≤1.5 元 |

未达标时，按第 10 节的否决阈值决定“优化、降级或换方向”。

## 2. 一句话定位

> **“开一家宠物医院，救治流浪猫狗，帮它们找到领养家庭。”**

这句话同时包含身份（院长/医生）、对象（猫狗）、冲突（救治）、情感（领养/回家）与搜索词（宠物医院、流浪猫狗、领养），用于统一产品、买量与美术表达。

## 3. 目标用户

### 3.1 核心用户

- 宠物兴趣人群：养宠、云吸猫狗、关注流浪动物救助。
- 女性休闲用户：喜欢治愈、收集、经营、装扮，但不排斥男性用户。
- IAA 轻度用户：单手、竖屏、3-8 分钟碎片时间，月均玩 7.5 款，忠诚度低。

### 3.2 非目标用户

- 硬核 SLG/MMO/竞技玩家。
- 追求写实医疗模拟、手术细节的用户。
- 需要长时间沉浸、复杂教程、双手操作的用户。
- 只接受纯超休单局、不愿经营长线的用户。

## 4. 核心循环

```mermaid
flowchart LR
  A[接诊] --> B[分诊]
  B --> C[诊断小游戏]
  C --> D[治疗资源分配]
  D --> E[康复护理]
  E --> F[领养 / 图鉴]
  F --> G[扩建医院 / 装修]
  G --> A
```

- **单局**：接诊 → 分诊 → 听诊/拍片/化验 → 用药/床位/时间分配 → 结算，3-5 分钟。
- **长线**：病例图鉴、好感度、医生团队、医院等级、领养故事、季节活动。
- **社交**：好友助力、领养分享、医院参观、救助站排行。

## 5. MVP 必做与暂不做

### 5.1 必做

| 模块 | MVP 范围 |
|---|---|
| 医院 | 1 家医院、3 个诊室（诊断/治疗/住院） |
| 病例 | 12-15 个高质量病例、20 个品种 |
| 诊断 | 听诊、拍片、化验 3 个小游戏 |
| 治疗 | 药品、床位、时间三类资源分配 |
| 长线 | 图鉴、好感度、领养、医院扩建、50 个装饰 |
| 社交 | 好友助力、领养分享、防刷 |
| 商业化 | 5 个激励视频点位、7 个 IAP SKU、支付/广告回调 |
| 数据 | D1/D7/D30、CPI、ARPDAU、分享率、助力率 |
| 活动 | 7 日留存活动、每日病例、登录奖励 |

### 5.2 暂不做

| 功能 | 暂不做原因 |
|---|---|
| 实时多人/公会战 | 与 MVP 验证目标无关，开发和服务器成本高 |
| 复杂剧情树/全语音 | 内容成本高，首局用短病例故事即可 |
| 重度 SLG 数值/装备强化 | 与女性休闲画像错配，学习成本高 |
| 付费随机抽宠物 | 合规与口碑风险，MVP 不做 |
| UGC 编辑器/宠物繁育 | 长周期系统，留到验证后 |
| 写实医疗/手术细节 | 审核与伦理风险，且破坏治愈标签 |

## 7. 商业化结构

- **总结构**：IAA 60% + IAP 40%。
- **IAA**：激励视频用于加速康复、诊断线索、缺药补给、临时加床、双倍金币、免费爱心；单日 6-10 次；插屏只在病例结算后。
- **IAP**：周卡 6 元、月卡 30 元、装饰包 30/68 元、专家医生 68 元、领养证书 30 元、救助基金/战令 68 元、爱心礼包 6/30 元。
- **原则**：不做“付费才能救活”；不做付费随机抽宠物；价格服务端配置；支付/广告回调服务端校验。

| 指标 | 目标 | 口径 |

| D1 留存 | ≥35% | 次日登录 / 新增 |
| D7 留存 | ≥12% | 第 7 日登录 / 新增 |

| 领养完成率 | ≥60% | 完成领养 / 进入领养页 |
| 单局时长 | 3-5 分钟 | 接诊到结算 |
| 首屏时长 | <3 秒 | 启动到可交互 |

## 9. 执行顺序与原则

1. **先验证，再扩内容。** 先做 1 个病例 + 1 个诊断小游戏 + 3 条素材，2 周内验证搜索、CPI、首局完成率；不要先做 30 个病例。
2. **先单局，再长线。** 单局不好玩，图鉴、领养、扩建都救不回来。
3. **先 Android + IAA，再 iOS 支付适配。** 虚拟支付政策不同，先用 IAA + Android 内购跑通模型。
4. **先自然量，再买量。** 分享/助力/社区是免费流量；买量只放大已验证的素材。
5. **先做窄，再做宽。** 任何新增功能必须替换 MVP 现有项，而不是叠加；范围变更需制作人确认。

## 10. 全项目 5 个最高风险与否决阈值

| 风险 | 触发信号 | 否决阈值 | 应对 |
|---|---|---|---|
| 搜不到 | 核心词无稳定下拉/自然结果；10 人测试 <4 人愿搜 | 2 周验证不通过 | 改名/换题材/换素材角度 |
| 买量成本过高 | CPI 持续 >2 元，D7 <10% | LTV/CPA <1.0 | 停止放量，降级为自然量产品 |
| 单局留存差 | D1 <30% 或首局完成率 <50% | 软测首周 | 回炉单局，砍长线内容 |
| 合规风险 | 医疗表述、动物伦理、诱导分享、支付政策 | 任一高风险未解决 | 上线前一票否决 |
| 内容产能不足 | 8 周内无法完成 12 个病例 | 第 8 周 | 缩减到 8 个病例或延后 2 周 |

## 15. 风险与待验证假设

1. 用户会主动搜索“宠物医院游戏/养猫游戏/救助流浪猫”，且搜索量足以支撑买量。
2. 救治前后对比素材能把 CPI 压到 1.5 元以内。
3. 3-5 分钟单局能同时满足 IAA 节奏与治愈叙事。
4. 女性用户愿意为装饰/证书/月卡付费，且不排斥广告。
5. 宠物医院题材可按休闲游戏类目过审，不触发医疗类合规问题。

## 16. 冻结口径（W1–W4 唯一执行口径）

> 本节为残余事项的最终结论。所有 Cursor 角色只读本节与三份冻结文件，不复制第二套说法；下游文档只能引用本节编号（F1–F8）。

| 编号 | 事项 | 冻结结论 | 阻塞范围 | 关闭时间 | 负责 |
|---|---|---|---|---|---|
| F1 | iOS 支付 | W1–W4 只做订单状态机与 `PAY_UNAVAILABLE` 占位；不调用 `wx.requestMidasPayment` 等真实虚拟支付接口；iOS 隐藏付费入口，不引导站外支付 | 阻塞 IAP，不阻塞单局与 IAA | W4 复核官方政策 | 服务端 + 客户端 |
| F2 | 宠物长期状态 | 冻结独立 `pets` 集合；`adoptions` 只存领养关系（`adoptionId/cardId/openid/petId/adoptedAt/status`），图鉴展示字段读自 `pets` 与病例记录 | 阻塞数据层，不阻塞 UI 骨架 | W1 | 服务端 |
| F3 | 包体与内存 | 主包 ≤4MB；总分包 ≤30MB；内存目标 ≤200MB，低端机 ≤250MB | 部分阻塞资源与分包方案 | W1 | 客户端 |
| F4 | `leaderboard` 索引 | 不阻塞客户端；服务端在 10 号文档补 `leaderboard` 集合与查询索引，W1 内完成 | 不阻塞 | W1 | 服务端 |
| F5 | 搜索/竞品数据 | 不阻塞编码；2 周搜索实验并行执行，结论回写 01，未回写前 01 数据只作假设 | 不阻塞 | W2 | 运营/买量 |
| F6 | 14 周计划人名与日期 | 不阻塞；先用 `TBD-角色` + 预估日期，W1 结束前替换为实名与确认日期 | 不阻塞 | W1 结束前 | 制作 |
| F7 | 其余残余项 | 统一进入 15 号文档检查清单，W2 前逐项关闭；未关闭项不得进入 W3 排期 | 不阻塞 W1 | W2 | 全组 |
| F8 | 口径唯一性 | 本节 + 三份冻结文件为唯一来源；其他文档只引用 F1–F8，不复制结论；变更需制作人确认并记录影响文件 | 全项目 | 持续 | 制作 |

**执行解释：**

- **F1 的边界**：`createOrder` 只做参数校验与状态机占位，返回 `PAY_UNAVAILABLE`，不创建真实订单、不返回支付参数；`payCallback` 同样返回 `PAY_UNAVAILABLE`，不得验签真实平台报文、不得发货。真实支付接入必须等政策复核与资质确认。
- **F2 的边界**：一只宠物只有一条 `pets` 记录、最多一条有效 `adoptions` 关系；`adoptions` 不再冗余 `petSpecies/petName/rarity/storyId/careScore` 等展示字段。
- **F3 的边界**：以构建产物为准，不以源码体积估算；分包超 30MB 时先砍非首屏资源，不允许突破主包 4MB。
- **F7 的范围**：包括但不限于 99 号报告中的 G1–G8 剩余项、真机兼容性、政策复核、素材授权与客服流程。
