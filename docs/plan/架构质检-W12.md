## 二、逐项详情

### 1. W12-1 事务冲突重试 — 通过

- 替身语义对齐（`scripts/mock-cloud-transaction.js:1-90`）：只在 `control.conflicts > 0` 时于 handler 执行前抛冲突，因此「重试耗尽」分支不会留下半写；非冲突异常一次性抛出、不重试；`times` 缺省 3；同文档读改写走串行队列，12 路并发用例不依赖微任务时序。
- 服务端显式传次数并把耗尽映射成业务错误码：`cloudfunctions/assist/settle.ts:31,58,94`、`cloudfunctions/adEvent/settle.ts:41,70,107` 均为 `runTransaction(handler, 3)`；`assist/index.ts:102`、`adEvent/index.ts:118` 命中冲突特征才返回 `1006 TRANSACTION_RETRY_EXHAUSTED`，其余异常原样上抛（不伪装）。
- 客户端把 1006 归入可重试：`net/AdEvent.ts:12-16`（`isRetryable` 含 1006，广告事件重新入队）、`net/AssistSync.ts:1` + 同文件补发分支（助力不出队）。
- 冻结口径已登记：`接口冻结清单.md:40` 新增 1006，`:242` 记 v1.5 变更（含补登 1005）。
- 实测（`npm run verify:idempotency`）：
  - `[10]` 预置 1 次冲突 → 第 2 次成功，`granted=true / dailyCount=1`，实际 2 次尝试；
  - `[11]` 预置 3 次冲突 → 返回 1006，且 `pair=0 计数=0`（无中间态）；
  - `[12]` 非冲突异常 → 不上报 1006、只 1 次尝试。
- 未声称：替身不模拟真实 SDK 的锁等待与冲突频率，真实云端仍需部署后压测一次；原 W11-R1 改判为「现场待验」（见 §四）。
