## 0. 结论摘要

- 已落地：`settings/v2/packages/project.json` 的 `general.designResolution` 改为 **720×1280 / policy=4（FIXED_WIDTH = Fit Width）**；构建产物 `src/settings.json` 已复核为该值。
- **前提核对**：指令里「W19 的代码侧改动只是项目设置 + Widget/SafeArea 复查，不需要重做 UI」经核对**不成立**。只改设置会让 8 处 1280 时代的横向绝对坐标直接出屏（可视半宽从 640 变成 360）。本轮在不改视觉语言、不改纵向节奏的前提下，把这 8 处改为区间 / 贴边派生，未重绘任何界面。

- 未声称：本文件不含任何真机结论；真机项集中在 §6。

## 3. 全屏面板 Widget / SafeArea 复查

口径：`SafeArea` 依赖同节点 `Widget`，缺 Widget 时 `updateArea()` 静默 return，所以顺序必须是「先四边 Widget、后 SafeArea」；`ui/SafeLayout.attachSafeArea()` 就是这个顺序。真需要避让的只有贴屏幕边的内容，居中面板不需要避让。

| 界面 | 全屏节点 | 安全区处理 | 本轮结论 |
|---|---|---|---|
| 隐私弹窗（gate / decline / read） | `PrivacyOverlay = 可视宽×高` + `BlockInputEvents` | 面板 `attachSafeArea`（Widget → SafeArea） | 通过 |
| 关于面板 | `AboutOverlay` 同上 | 面板 `attachSafeArea` | 通过 |
| 图鉴 / 排行榜 / 兜底弹窗 | 全屏遮罩 + 居中面板（580~620 高） | 不贴边，无需 SafeArea | 通过 |
| 启动页合规两行 | `BootSplashLegal` | `attachSafeArea` + `alignBottom` | 通过 |
| 大厅 | Canvas 四边 Widget（`_alignFlags=45`）自适应 | 两枚场景标签本轮改 `pinTopLeft` | 通过（本轮改动） |
| 接诊 / 诊断 / 治疗 / 康复 / 结算 / 领养 / Boot | 全屏根节点，内容全部运行时创建 | 无贴边元素，无需避让 | 通过 |
| 面板白底 | `addRect` 画的是 `panelW()×panelH()` 的 Graphics | Widget 四边拉伸不改 Graphics | **警告**：与 W10-3 §4.5 同一条边界，白底与撑大的节点框不一致，真机需目测白底是否仍留安全区边距 |

## 4. 化验双列为什么没有改成上下两列

W10-3 记录预判「需要改成上下两列，触摸判定与连线目标随之重算」。核对实现后不需要：

- 触摸命中是 `containsPoint(card, ui)` → `toLocal(card, …)`，以**卡片节点自身**为坐标系、半径 36 的圆，与列中心坐标无关（`game/LabView.ts:124-127`）。
- 配对连线是 `drawDrag / drawPair` 按**世界坐标**画在覆盖全屏的 Graphics 层上（`LabView.ts:84-121`），列位置改了它自动跟随。
- 因此只把列中心从 ±330 收到 ±230 即可，判定与连线逻辑零改动。

## 5. 纵向节奏：本轮未改（警告）

内容仍按 1280×720 时代的节奏从上到下排在 y∈[-330, 330]：

| 屏幕比例 | 可视高（设计单位） | 内容带占比 | 表现 |
|---|---|---|---|
| 16:9（iPhone SE 375×667） | 1281 | 52% | 居中，上下各留 ~310 |
| 19.5:9（iPhone 13 390×844） | 1558 | **42%** | 居中，上下各留 ~449 |
| 4:3（iPad 768×1024） | 960 | 69% | 居中，可接受 |

这不是裁切（不存在遮挡 / 出屏），是留白与信息密度问题。三个可选做法，需预览扫码看过实际观感后拍板：

1. **保持现状**：居中带 + 上下留白，改动最小；
2. **锚点重排**：标题贴 `topY()`、主操作按钮贴 `bottomY()`，中间内容不动（约 6 个屏、每屏 3–6 行改动）；
3. **竖屏信息架构重排**：按单手操作重排信息优先级（属独立模块）。

## 6. 真机 / 预览待验证清单（人工侧执行）

1. 设计帧是否生效：进入任意玩法屏，横向无裁切、左右各留 32 单位边距。
2. 微信右上胶囊是否压住「诊断倒计时 / 步骤」——两者在 720 帧下都贴左上（y=330 与 288），胶囊是右上方，理论上不冲突，需目测。
3. 治疗页：三组选项（3 枚 / 每枚 176×78）文字是否完整、点按热区是否够大；四枚选项时（化验多选项病例）是否仍不重叠。
4. 化验页：左右两列卡片（200 宽）在真机上的可点区域（半径 36）与拖拽连线落点是否与手指一致。
5. 隐私弹窗 / 关于面板：两枚 280×76 按钮是否左右分开、不重叠；白底是否仍与安全区留边（§3 最后一行）。
6. 大厅：金币 / 爱心两行是否贴左上且不被胶囊或安全区遮挡。
7. 接诊 / 康复：0.6 缩放的立绘是否仍可辨识，是否压到正文或按钮。
8. iPad 4:3（可视高 960）与 16:9 短屏：上下留白收敛后是否有元素贴边或重叠。
9. 低端机冷启动：`getVisibleSize()` 首帧是否拿到有效值（延续 W10-3 §6 第 6 条）。
