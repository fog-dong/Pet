## 1. 补齐提审必需内容（代码侧，提交前完成）

1. 医疗虚构声明：已写入《用户协议》正文第 1 条（`assets/scripts/config/LegalConfig.ts`），首次启动必经的隐私弹窗即可读到；独立的「关于」页与商店简介文案仍待运营补充（见检查清单 §2）。
2. 隐私政策 / 用户协议：游戏内弹窗、勾选同意、「不同意」说明态与大厅常驻入口已在 W8-5 落地；本步骤只剩把 `LegalConfig.ts` 的 3 个空 URL 换成正式 H5（`legalUrlsReady()` 需返回 `true`），并在小游戏后台「用户隐私保护指引」同步填写。
3. 客服入口：游戏内「关于/客服」入口，或后台客服消息承接方案二选一并在简介中说明（**尚未实现，仍是阻塞项**）。

> W8-5 后剩余阻塞项：客服入口、正式 AppID、真实广告位 ID、协议 H5 链接。隐私告知与同意链路已有代码证据，验证方法见《W8-真机预览操作单》§5.1。

## 2. 替换正式 AppID（本地操作，不入库）

1. 当前 `build-templates/wechatgame/project.config.json` 与构建产物均为 `appid: touristappid`（游客占位）。
2. 正式 AppID 只在本地构建时注入，例如：
   ```bash
   unset ELECTRON_RUN_AS_NODE
   CocosCreator.exe --project <工程路径> --build "platform=wechatgame;appId=<正式AppID>;startScene=0b556a8f-2609-451f-a9e7-30d58d1553da"
   ```
3. 构建后核对 `build/wechatgame/project.config.json` 的 `appid` 为正式值。
4. **不得把正式 AppID 写回 `build-templates/` 提交**；`build/` 已在 `.gitignore` 中，不提交。
5. 正式 AppID 就绪后，在开发者工具点「预览」生成二维码真机扫码（不是「真机调试」）。二维码加载失败时先关闭网络代理、执行 `ipconfig /flushdns`；仍失败则降级到稳定版开发者工具（如 1.05）。分包 `cases` 约 8.6KB、`art` 约 1.9KB，不会触发分包加载超时，排除此项干扰；完整排查顺序见《W8-真机预览操作单》§4。

## 3. 构建与包体核对

1. 使用 release（未勾选调试）构建，确认产物中无 DebugPanel 显示（`DEBUG` 为假）。
2. 核对主包 ≤4MB、总分包 ≤30MB，`game.json` 的 `subpackages` 同时含 `cases` 与 `art` 两个分包。
3. 确认 `cloudfunctions/*/index.js` 与 `index.ts` 同步（`npm run build:cloud`），无手改产物。

## 4. 微信开发者工具内操作

1. 导入 `build/wechatgame`，使用正式 AppID 与测试云环境。
2. 云开发 → 云函数：按《W7-云函数部署操作单》§3 的顺序逐个「上传并部署：云端安装依赖」（共 11 个，含 `getProfile`、`adEvent`、`trackEvent`）。
3. 云开发 → 数据库：按《数据库初始化清单》建集合与索引（含 `pets_cases.caseSessionId` 唯一索引）。
4. 小游戏后台：选择类目（游戏，非医疗健康）、上传图标与截图、填写简介（说明虚构医疗模拟与宠物救助主题）。
5. 后台开启实名与防沉迷能力；配置隐私保护指引与客服。
6. 广告位：广告位 ID 统一收口在 `assets/scripts/config/AdConfig.ts`。提审前把 7 个 `AD_UNIT_PLACEHOLDER` 换成微信后台创建的真实激励视频广告位 ID，并回归 `extra_check` / `extra_inspection` / `accelerate` / `double_reward` / `free_slot` 五个主点位（`extra_medicine` / `extra_bed` 也需指向真实 ID）。广告位 ID 不是密钥，可以入库；AppID、环境 ID、`SESSION_SECRET` 仍不入库。

## 5. 上传与提审

1. 先上传体验版，按《W6-真机测试清单》在中端 Android 与 iOS 各跑一轮，记录性能面板、广告加载/降级结果与助力到账结果。
2. 开发者工具 → 上传，填写版本号与版本说明（说明本次为 W7 提审准备版本）。
3. 后台 → 版本管理 → 提交审核；审核备注写明：
   - 本作为虚构宠物医院模拟，无真实医疗建议；
   - 无内购、无真实支付；
   - 分享为自愿行为，无强制分享与群诱导。
4. 确认提审包 `appid`、类目、隐私指引、客服入口四项与预期一致后再点提交。

## 6. 审核期与上线

1. 关注审核反馈，涉及医疗表述、分享诱导、隐私链接的整改按检查清单对应条目处理。
2. 通过后先灰度（平台允许的比例），观察崩溃率、广告失败率、`syncCaseResult` 失败率。
3. 异常时回滚：小程序后台回退上一版本；云端云函数回退上一可用版本；客户端 `CLOUD_ENV` 可回退占位符走本地模式。
