```bash
  --user-data-dir=%TEMP%/chrome-w204 --use-gl=swiftshader about:blank

# 4) 跑四套；主链路第 5 个参数换诊断变体，三条线各跑一轮（xray / auscultation / lab）
node scripts/verify-mainchain-browser.js 9448 localhost:8095 build xray
node scripts/verify-mainchain-browser.js 9448 localhost:8095 build auscultation
node scripts/verify-mainchain-browser.js 9448 localhost:8095 build lab
node scripts/verify-habitat-browser.js 9448 8095 w204
node scripts/verify-idempotency.js
node scripts/verify-casescore.js        # 纯函数口径回归，不需要浏览器
```

关键约定（踩过坑，写下来免得下次重犯）：

- 隐私门版本号必须与 `LegalConfig.LEGAL_VERSION`（当前 `1.0.1`）一致，写错会让游戏永远停在 Boot 场景，所有断言假红。
- 成员卡（`HabitatCard_*`）走 `TOUCH_START/TOUCH_END` + 位移阈值，不是 `Button`，必须成对派发触摸事件；普通按钮才能用 `emit('click')`。
- 脚本直发 `click` 会绕过 `Button.interactable`，所以置灰用例除了看 `interactable` 还要看互动谓词自身的余额守卫（L21c）。
- 站点端口与 CDP 端口都是参数，不要写死。
- `goState` 是异步翻页，旧页要下一帧才销毁，这期间连点会二次扣库存——C05b 就是为这条加的（治疗页已有 `submitting` 事务锁）。
- 领养门槛不能用「改组件 petId 再点按钮」验：`Adoption.adopt()` 读的是 `CaseSession.current.item.petId`，改组件字段拦不住真领养，只会把这一局真的领养掉。C08b 因此改从渲染层断言（门槛不达标时 `AdoptionView` 不画「领养它」，只画 `LockHint`）。
- 通关瞬间诊断组件会随页面销毁，页内计数读不到；脚本在拖拽前把 `onFinish` 包一层，把真实 `{ completed, found, total, stars }` 留在 `window` 上作证据（`probe=on` 就是这个包装生效的标记）。

2. `MOOD_FACTOR` 目前是常量 1，方案里的「心情分档影响产出」未上线。这条只影响服务端铸造速率，不影响客户端，但意味着心情当前只是情绪价值，不是经济价值。
