**必须提醒的一点（本轮新查清的事实）**：仓库里存在**两条后端通路**，而 `deploy/README.md` 显示你已经在跑自建那条：

- 通路 A：Axum HTTP 自建后端（Docker + Nginx 反代 `pet.jiangker.cn`，GitHub Actions 推镜像）；
- 通路 B：微信云开发 13 个云函数（`CLOUD_ENV` 仍是 `ENV_PLACEHOLDER`）。

`EnvConfig.isCloudEnabled()` 的判定是 **A 优先于 B**。所以：

1. **通路 A 已经能撑起小屋**：本轮查到 `server/src/handlers/claim_habitat.rs` 已实现 `/api/claimHabitat`，定价与云函数逐条一致（`COINS_PER_PET_HOUR=4`、`MAX_HOURS_PER_CLAIM=6`、`MAX_DAILY_CLAIMS=2`、领养只数上限 20、`1003 RATE_LIMITED`）。所以**只部署 A 也能正常领离线收益**，13 个云函数可以整体不传；
2. 如果你要 B 生效，必须把真实环境 ID **写进源码常量 `CLOUD_ENV`**——运行时 `wx.setStorageSync` 的覆盖位不会进提审包，审核员拿到的是干净环境；
3. 两条都部署时 A 优先，B 成为冷备；此时要注意**两套后端各自记自己的 `habitat_state.lastClaimAt`**，玩家在同一账号上混用会造成离线收益起算点错乱（要么少计，要么在两处各领一次）。**建议只启用一条**，另一条的开关位保持未配置。

### 4.2 本轮修掉的真实缺陷

1. **`PetQuota.consume` 跨天计数不归零**（`assets/scripts/cache/PetQuota.ts`）：原先在 `Save.mutate` 内部先写 `pettedDay` 再读 `used(dayKey)`，而 mutate 拿到的就是同一份存档对象，导致昨天用满 3 次会带进今天变成第 4 次。浏览器用例 `B04` 首次跑出 `count=4` 暴露此问题，改为在 mutate 前算好 `next` 后为 `count=1`。
2. **`AgeSystem.getAgeText` 未使用参数**：scaffold 配置（含 `noUnusedLocals`）报 TS6133，删掉多余的品种参数；「年龄文案与品种无关」现在由函数签名本身保证。

早前我报过「tsc ×3 全绿」，**当时并不成立**：`tsconfig.scaffold.json` 下 `AgeSystem.ts` 有 TS6133，只是根 `tsconfig.json` 不开 `noUnusedLocals` 所以没暴露。本轮已修正并三份实跑为 0 错误。此后按 scaffold 配置一起跑，不再只报根配置。
