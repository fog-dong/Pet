## 1. 为什么占位值也能跑通

| 开关 | 占位时行为 | 代码证据 |
|---|---|---|
| `isCloudEnabled()` false（`CLOUD_ENV = 'ENV_PLACEHOLDER'`） | `Net.init` 返回 false → `Net.ready` 恒 false → 10 个调用点全部短路走本地兜底，不发请求、不报错、不阻塞单局 | `config/EnvConfig.ts:16-17`、`net/Net.ts:36`；`grep -rn "Net.ready" assets/scripts` = 10 处（Profile / CloudSave×2 / AdEvent×2 / AssistSync / SyncCaseResult / AdoptionActions / LeaderboardPanel / Track） |
| `isAdConfigured(scene)` false | `Ad.showRewarded` 直接返回 `AD_UNAVAILABLE`，**不调 `wx.createRewardedVideoAd`**；`AdGateway` 对未配置场景不发奖、不消耗当日次数、不降级 | `net/Ad.ts:38`、`net/AdGateway.ts:51-55` |
| `legalUrlsReady()` / `customerServiceReady()` false（URL 含 `example.com`） | 自检判「未配置」：客服按钮直接预显示兜底文案，不会拿占位 URL 去调 `wx.openCustomerServiceChat`；协议正文走 `points` 常量，不依赖 URL | `config/LegalConfig.ts:91-102`、`net/Support.ts:16-17`、`ui/AboutPanel.ts:47-48` |
| `appid = 'touristappid'` | 只在开发者工具模拟器可跑，**不能生成真机预览二维码**（平台限制，不是代码问题） | `build-templates/wechatgame/project.config.json:15` |

## 3. 替换后自检（四条命令/断言，全部在本地跑）

1. `grep -rn "PLACEHOLDER\|example.com\|touristappid" assets/scripts/config/` —— 应只剩占位常量定义本身（`AD_UNIT_PLACEHOLDER`、`CLOUD_ENV_PLACEHOLDER`、`PLACEHOLDER_HOST`），不再有字段值仍是占位。
2. `grep -rn "Net.ready" assets/scripts --include=*.ts` —— 仍 10 处；填入真实 `CLOUD_ENV` 后 `isCloudEnabled()` 为 true，`Net.init` 才可能成功。
3. `npm run build:cloud && tsc --noEmit`（根 / scaffold / cloudfunctions 三份）。
4. Creator 构建发布包后：`grep -c AD_UNIT_PLACEHOLDER build/wechatgame-release/assets/main/index.js` = 0，`grep -c example.com build/wechatgame-release/assets/main/index.js` = 0（`project.config.json` 的 `touristappid` 也应为 0）。

说明：`legalUrlsReady()` 目前**没有运行时调用点**，它是给发布流程和后续 CI 用的自检入口（与 `customerServiceReady()` 不同，后者被 `net/Support.ts` 真实消费）。挂账为《架构质检-W9》W14 同类项，等 W10-5 一并决定是否接入启动自检埋点或删除。

## 4. 本轮明确不做

- 不伪造 `adUnitId` 去调真实广告接口（占位调真接口只会报错，且会绕过「不发奖不扣次数」保护）。
- 不把 `example.com` 当成「已配置」——自检函数显式把它判为未配置。
- 不生成预览二维码、不要求真机扫码、不上传云函数、不改域名白名单（`touristappid` 本来也无法真机预览）。
- 不碰 W10-2 之外新增的 config 结构；后续 W10-5 只允许补字段，不允许再造第二套配置入口。
