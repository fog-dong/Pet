# 云托管自定义域名绑定指南

| 项目 | 内容 |
|---|---|
| 版本 | v1.0（W23-5） |
| 日期 | 2026-11-03 |
| 负责人 | 制作人（人工在腾讯云 / 微信公众平台操作） |
| 状态 | **待人工执行**——本单全部为控制台点击与 DNS 解析，禁止由脚本或 Agent 代跑 |
| 关联文件 | `deploy/README.md`（当前自建部署）、`docs/plan/微信后台域名配置清单.md`、`server/README.md` |

> **先说清现状**：本项目**当前没有使用微信云托管**。生产后端是一台自建服务器上的 Docker 容器（`pet-api`，宿主机 `127.0.0.1:18766` → 容器 `3000`），由现有 Nginx 反向代理到 `https://pet.jiangker.cn`，CI 通过 GitHub Actions 推镜像 + SSH 拉起（见 `deploy/README.md`）。
> 本文写的是**两种情形**：第 2 节是「继续自建」时的域名与证书要点（你现在的状态）；第 3–5 节是「迁到微信云托管」时的自定义域名绑定步骤。别把两条路径混在一次操作里做。

---

## 1. 无论走哪条路，前置条件相同

| 前置 | 要求 | 不满足会怎样 |
|---|---|---|
| **ICP 备案** | 主域名 `jiangker.cn` 备案成功，且**接入商包含当前服务器/云托管所在地机房** | 微信「服务器域名」保存失败；平台侧备案核查会打回提审 |
| **HTTPS 证书** | 覆盖 `pet.jiangker.cn`，链完整、未过期、TLS ≥ 1.2 | 小游戏请求直接失败，报 `request:fail ssl hand shake error` |
| **DNS 可改** | 你能在域名解析商处增删 CNAME/A 记录 | 无法把域名指到新后端 |
| **健康检查路径** | 后端提供 `GET /health`，返回 `{"status":"ok",...}` | 云托管健康检查不通过，服务被判不存活、不接流量 |

证书建议直接用腾讯云「免费的 DV 单域名证书」申请 `pet.jiangker.cn`，签发快、支持自动续期，上传时选「已有证书」即可，避免手动拼证书链。

---

## 2. 情形 A：继续自建服务器（当前状态）——域名侧要做的事

这一节不是「云托管绑定」，而是把你已经在跑的链路核对齐，避免提审时才发现缺项：

1. **DNS**：`pet.jiangker.cn` 一条 **A 记录**指向服务器公网 IP（自建路径不需要 CNAME）。
2. **Nginx**：443 站点 `proxy_pass http://127.0.0.1:18766;`，80 站点 301 跳 https（完整配置见 `deploy/README.md` 第 5 节）。
3. **证书**：certbot 或腾讯云证书下载后放到 Nginx，注意用 **fullchain**（含中间证书），只配单张域名证书在部分安卓机上会握手失败。
4. **微信合法域名**：按《微信后台域名配置清单》第 2 节填 `https://pet.jiangker.cn`。
5. **验证**：`curl -v --tlsv1.2 https://pet.jiangker.cn/health` 必须 200。

---

## 3. 情形 B：迁到微信云托管——绑定前的选型判断

云托管的默认访问域名（形如平台分配的 `*.tcloudbaseapp.com` / 区域接入域名）**不能直接当小游戏合法域名用**：它是平台域名，随服务重建可能变化。所以对外仍要绑自己的 `pet.jiangker.cn`。

迁移动作本身要先决定：

- 数据库从自建 PostgreSQL 迁到云托管可访问的实例（同 VPC 或云数据库），连接串 `DATABASE_URL` 在云托管「服务设置 → 环境变量」里配，**不写进仓库**；
- `WX_APPID` / `WX_SECRET` / `JWT_SECRET` 同样只在控制台环境变量里填；
- CI 从「SSH + docker compose」改为「推镜像到镜像仓库 + 云托管发布」，`deploy/README.md` 第 7 节的 Secrets 需要相应替换。

## 4. 云托管自定义域名绑定步骤

> 控制台入口名称随版本微调，认准「自定义域名」四个字即可；操作全程在**腾讯云 / 微信云托管控制台**，与微信公众平台是两个地方，别混。

1. **准备镜像与服务**：云托管 → 选定环境 → 新建服务，镜像用现有 `pet-api`（容器内监听 `3000`，与 `deploy/docker-compose.yml` 一致）。协议选 **HTTP**，健康检查路径填 `/health`。
2. **配环境变量**：`DATABASE_URL`、`WX_APPID`、`WX_SECRET`、`JWT_SECRET`、`RUST_LOG`。值只留在控制台，不进仓库、不进截图。
3. **等服务状态为「运行中」且健康检查通过**，再用平台分配的默认域名先验一次 `/health` 与 `/api/login`——先用平台域名跑通，再绑自定义域名，出问题时能立刻区分是「应用问题」还是「域名/证书问题」。
4. **绑定自定义域名**：服务 → 「自定义域名」→ 添加，填 `pet.jiangker.cn`，选择证书（第 1 节申请好的那张）。
5. **加解析**：控制台会给出一个**接入目标值**（通常要求 CNAME 指向平台分配的接入域名）。到你的 DNS 处：
   - 先**删掉**情形 A 那条指向自建服务器的 A 记录（同名的 A 与 CNAME 共存会导致解析随机落到旧服务器）；
   - 新增 **CNAME 记录**，主机记录 `pet`，记录值填控制台给的那个接入域名，TTL 先用最小值（便于回滚）。
6. **等生效**：DNS 生效通常几分钟，但 TTL 与运营商缓存可能拖到十几分钟。用 `nslookup pet.jiangker.cn` 确认已返回平台域名，再回控制台点「验证/完成」。
7. **验证**：`curl -v --tlsv1.2 https://pet.jiangker.cn/health` 返回 `status: ok`，且响应头里能看到云托管的网关标识。
8. **再回微信公众平台**核对合法域名：仍是 `https://pet.jiangker.cn`，**值不变**，所以第 2 节配好的白名单不需要动——这正是「绑自定义域名而不是用平台默认域名」的意义。

## 5. 切换与回滚

| 场景 | 做法 |
|---|---|
| 灰度切换 | 先只改 DNS（把 CNAME 指到云托管），保留自建 Nginx 站点不下线；出问题把记录改回 A 记录即可，回滚成本 = 一次 DNS 修改 |
| 数据不一致 | 切换期间**停写**（小游戏侧执行 `wx.setStorageSync('pet_api_base_v1','off')`，客户端回落云开发/本地模式；W24-4 后基址已进源码，**清掉覆盖位不再等于停写**），避免两套后端各自写库 |
| 完全回滚 | 删 CNAME、恢复原 A 记录；云托管服务可保留但不接流量 |
| 提审窗口 | 建议提审前 48 小时冻结域名与后端切换，避免审核期间访问域名变更导致体验版打不开 |

## 6. 常见故障对照

| 现象 | 大概率原因 | 处理 |
|---|---|---|
| 控制台「验证域名」一直不过 | CNAME 未生效 / 记录值抄错 / 主机记录写成了 `pet.jiangker.cn` 而非 `pet` | `nslookup` 确认后再点验证 |
| 浏览器正常、小游戏报 `ssl hand shake error` | 证书链缺中间证书，或 TLS 只放到 1.1 | 换 fullchain；`ssl_protocols TLSv1.2 TLSv1.3` |
| 请求 502 / 504 | 容器端口与网关监听端口不一致（本项目容器固定 `3000`） | 核对服务设置的端口与镜像 `EXPOSE` |
| `/health` 200 但 `/api/login` 401 | 环境变量没注入（`WX_APPID` / `WX_SECRET` 缺失时后端走开发 openid，不接真实登录） | 控制台补环境变量并重启服务 |
| 微信后台保存域名提示未备案 | 备案接入商不含当前机房 | 在新服务器/云托管所在商做「新增接入」，不是重新备案 |

## 7. 交付检查

- [ ] 明确本次走情形 A（自建）还是情形 B（云托管），两者不同时做
- [ ] `jiangker.cn` 备案接入商与当前后端所在机房一致
- [ ] 证书为 fullchain、TLS ≥ 1.2、到期时间已记入备忘
- [ ] `https://pet.jiangker.cn/health` 与 `/api/login` 均可用
- [ ] 微信公众平台 request 合法域名与该地址完全一致（无路径、无端口、无尾斜杠）
- [ ] 环境变量只在控制台存在，仓库与截图内无密钥
- [ ] 回滚路径（DNS 改回 / 覆盖位写 `off` 停写）已演练过一次
