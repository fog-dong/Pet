> **说明**：本文设计激励视频、插屏、Banner 的场景、奖励与频控。广告位 ID 与平台参数为**建议占位**，上线前需在微信后台创建并以配置下发。原则：广告是加速器，不是通行证；不卡流程、不诱导点击、奖励可对账。

## 1. 目标与范围

- 用广告补足资源缺口，保证免费玩家可完整体验。
- 控制广告频次，避免破坏治愈系体验与留存。
- 建立可对账的广告奖励链路（客户端 → 服务端 → 平台报表）。
- 输出广告位表、频控、兜底、埋点、伪代码与验收清单。

不包含：内购 SKU（见 12）、变现模型测算（见 13）、合规总表（见 15）。

### 1.1 输入依赖

- 05 资源不足时的免费路径与优先级。
- 08 弱网重试与状态恢复约定。
- 10 `ad_events` 字段与索引。
- 缺失时：广告位未创建时先用测试广告位联调，不发正式奖励。

## 2. 广告形式与原则

| 形式 | 用途 | 原则 |
|---|---|---|
| 激励视频 | 主动换取资源/加速 | 必须用户主动点击，奖励明确 |
| 插屏 | 结算后过渡 | 仅在结算完成、无操作时展示 |
| Banner | 大厅底部常驻 | 不遮挡按钮，不诱导点击 |

**硬规则：**

- 任何核心流程不得以“看完广告才能继续”为唯一路径（见 05 第 6 节）。
- 不自动播放、不模拟点击、不设置虚假关闭按钮。
- 广告入口需有“广告”标识，奖励内容在看前可见。

## 3. 广告位表（建议）

| 广告位 | 形式 | 场景键 | 奖励 | 单日上限 | 触发点 |
|---|---|---|---|---|---|
| 结算双倍 | 激励视频 | `case_result_double` | 金币 ×2（上限 500） | 8 | 结算页 |
| 缺药补给 | 激励视频 | `treatment_lack_medicine` | 对症药品 ×1 | 4 | 治疗缺药 |
| 临时加床 | 激励视频 | `treatment_no_bed` | 临时床位 ×1（本局） | 4 | 床位不足 |
| 诊断线索 | 激励视频 | `diagnosis_hint` | 高亮 1 个异常点 | 5 | 诊断卡住 15s |
| 康复加速 | 激励视频 | `recovery_speedup` | 减少 50% 等待 | 4 | 康复页 |
| 免费爱心 | 激励视频 | `lobby_heart` | 爱心 ×5 | 6 | 大厅资源栏 |
| 结算插屏 | 插屏 | `result_interstitial` | 无 | 3（间隔 ≥120s） | 结算关闭后 |
| 大厅 Banner | Banner | `lobby_banner` | 无 | 常驻 | 大厅底部 |

**全局上限：** 激励视频单日 **6-10 次**（目标均值 6，硬上限 10），跨广告位统一计数，由服务端判定。插屏单日 ≤3，间隔 ≥120 秒。

## 4. 频控与优先级

| 规则 | 值 | 说明 |
|---|---|---|
| 全局激励视频上限 | 10 次/日 | 硬上限，服务端计数 |
| 单广告位上限 | 见上表 | 与全局取小 |
| 最小间隔 | 30 秒 | 防止连点 |
| 新用户保护 | 注册 <24h 上限 5 次 | 避免首日过度商业化 |
| 插屏间隔 | ≥120 秒 | 且仅在结算后 |
| 失败重试 | 同一广告位 3 次失败后当日隐藏 | 防止空转 |

**优先级（资源不足时）：** 免费等待 > 好友助力 > 广告 > 商店。广告不是第一推荐，避免“逼看”。

## 5. 加载与播放兜底

| 情况 | 处理 |
|---|---|
| 广告未加载 | 提前预加载；点击时未就绪则显示“广告准备中”，3 秒超时走兜底 |
| 加载失败 | 隐藏该入口或置灰，展示等待/好友替代路径 |
| 播放中断 | 不发放奖励，提示“完整观看才能获得奖励” |
| `isEnded=false` | 不发奖，记录 `ad_abandon` |
| SDK 异常 | 捕获异常，不影响主流程，上报 `ad_error` |
| 无广告填充 | 降级为直接发放小额保底（仅限关键路径，需配置开关） |

**要求：** 广告失败不得阻塞页面跳转；用户可随时关闭并继续游戏。

## 6. 客户端接入伪代码（建议）

```text
preloadAd(scene):
  ad = wx.createRewardedVideoAd({ adUnitId: config.adUnitId })
  ad.onError(e => analytics.track("ad_error", { scene, code: e.errCode }))
  ad.load()

showRewarded(scene):
  if !isAdReady(scene): return fallback(scene)   // 等待/好友/提示
  sessionId = uuid()
  ad.onClose(res => {
    if (res && res.isEnded) {
      callCloud("adEvent", { adSessionId: sessionId, scene, isEnded: true })
        .then(r => applyReward(r.data))          // 以服务端返回为准
        .catch(() => retryQueue.push(...))
    } else {
      analytics.track("ad_abandon", { scene, sessionId })
      toast("完整观看才能获得奖励")
    }
  })
  ad.show().catch(() => { ad.load().then(() => ad.show()).catch(() => fallback(scene)) })
```

**注意：** 不同基础库版本 `onClose` 返回值可能为 `undefined`，需按“非 true 即不发奖”处理。

## 7. 服务端频控与对账

```text
adEvent({ adSessionId, adUnitId, scene, isEnded }):
  1. 会话校验，openid 从上下文取
  2. idempotencyKey（openid:adSessionId）唯一索引，重复返回上次结果
  3. 校验 adUnitId 与 scene 在配置白名单且匹配
  4. isEnded == true 才发奖
  5. 校验全局与单广告位当日次数（按服务器时区自然日）
  6. 奖励从服务端配置读取，不信客户端
  7. 写 ad_events（含 platformDate），发奖，返回最新资源
```

**对账：**

- 每日按 `adUnitId + platformDate` 汇总服务端发放次数与平台报表展示次数。
- 差异 >5% 触发告警，抽样核查 `adSessionId`。
- `isEnded=false` 的记录保留用于漏斗，不参与发奖对账。

## 8. 埋点字段

| 字段 | 说明 |
|---|---|
| `scene` | 场景键，与配置一致 |
| `adUnitId` | 广告位 ID |
| `adSessionId` | 单次广告会话 ID |
| `isEnded` | 是否完整观看 |
| `reward` | 实际发放奖励（服务端回填） |
| `durationMs` | 播放时长 |
| `errorCode` | 失败错误码 |
| `dailyCount` | 当日累计次数 |

## 9. 合规要求

- 广告入口明确标识“广告”或“看视频”，不伪装成普通按钮。
- 不诱导点击（如“点击广告领大奖”“不看就亏了”）。
- 不在未成年用户场景做付费/广告诱导。
- Banner 不与功能按钮重叠，不遮挡关闭按钮。
- 广告内容与游戏调性冲突时，可在后台屏蔽敏感类目（以平台能力为准）。

## 12. 验收标准

- 激励视频完整观看才发奖，`isEnded` 非 true 时 100% 不发奖。
- 重复 `adSessionId` 不重复发奖（单测覆盖）。
- 达到单日上限后入口置灰并提示，不再请求广告。
- 广告加载失败、播放中断、无填充三种情况下均可继续游戏，不卡死。
- 插屏仅在结算后出现，间隔 ≥120 秒。
- 服务端发放次数与平台报表可按日对账，差异可定位。
- 全部广告入口均有非广告替代路径。

## 13. 风险与待验证假设

| 风险/假设 | 说明 | 验证方式 |
|---|---|---|
| 6-10 次上限不伤害留存 | 频次是否过高 | A/B 对比 D7 |
| eCPM 达到预期 | 受季节与行业影响 | 首月实测 |
| 广告失败率可控 | 填充率不稳定 | 监控 `ad_error` |
| 对账差异可解释 | 统计口径不同 | 抽样核查 |
| 无填充降级不滥用 | 保底可能被刷 | 服务端频控 + 开关 |

> **数据说明：** 本文不含真实 eCPM 与填充率；相关数值需上线后按平台报表复核，并用于 13 号模型校准。
