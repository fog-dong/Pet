## 4. 手动安装与工程生成步骤

> 安装已完成。以下步骤中第 1–2 步可跳过；当前只需在 Dashboard 中“打开项目”选择仓库根目录，完成首次导入并生成 `.meta`/`temp/`。

1. 打开 Cocos 官网下载页，下载并安装 **Cocos Dashboard**（Windows 版）。
2. 启动 Dashboard，登录 Cocos 账号；在“安装”页选择 **Cocos Creator 3.8 LTS**（与团队统一版本，后续不得随意升级）。
3. 等待安装完成，确认 Dashboard 能启动 Creator，记录 `CocosCreator.exe` 的实际路径与版本号。
4. 在 Dashboard 新建 **空项目**，模板选 TypeScript，项目名 `Pet`，位置先放临时目录（例如 `C:\Users\MSI\Desktop\programe\cocos-tmp\Pet`）。
5. 关闭 Creator；备份仓库现有 `assets/scripts` 到仓库外临时目录。
6. 把临时工程的 `settings/`、`package.json`、`tsconfig.json` 复制到仓库根目录；把临时工程的 `assets/` 与现有 `assets/scripts` 合并，冲突时保留现有 `.ts`。
7. 用 Dashboard 打开仓库根目录，等待编辑器首次导入完成；确认 `assets/scripts/**/*.ts` 均生成同名 `.meta`，且根目录出现 `library/`、`temp/`。
8. 运行第 5 节的验证命令；全部通过后提交 `chore: init Cocos Creator project and generate meta/settings` 并推送。

> 若第 2 步没有 3.8 LTS 选项，选择团队约定的 3.x 稳定版并在本报告追加版本号；不得使用 2.x。

## 5. 验证命令

```bash
# 1. 每个 .ts 都有同名 .meta
find assets -name '*.ts' | while read f; do [ -f "$f.meta" ] || echo "MISSING $f.meta"; done

# 2. 根 tsconfig 含 cocos 类型
grep -n '"types"' tsconfig.json
grep -n '"cocos"' tsconfig.json

# 3. settings 存在且未被忽略
test -d settings && echo SETTINGS_OK
git check-ignore settings/v2/packages/project.json || echo SETTINGS_TRACKABLE

# 4. 生成物未被 Git 跟踪
git ls-files | grep -E '^(library|temp|build|local)/' || echo NO_GENERATED_TRACKED
```

## 9. 风险与待验证假设

| 风险/假设 | 说明 | 应对 |
|---|---|---|
| Creator 版本不统一 | 不同成员安装不同 3.x 版本，`.meta` 与序列化格式可能不一致 | W1 内统一版本号并写入本报告；升级需制作人确认 |
| Dashboard 登录受限 | 无账号或网络不可达，安装无法完成 | 由用户提供可用账号；不采用第三方镜像 |
| 合并覆盖现有脚本 | 复制临时工程时误删 `assets/scripts` | 合并前必须备份；逐文件比对，不整目录覆盖 |
| 伪造 `.meta` | 手工写 UUID 导致引用错乱 | 禁止手工生成 `.meta`，只接受编辑器产物 |
| 安装拖延阻塞排期 | W1 验收无法完成 | `.ts` 与云函数开发继续；Cocos 相关验收标记“等待二次验证” |
