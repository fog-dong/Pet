## 0. 结论摘要

现状闭环已经跑通（接诊 → 诊断 → 治疗 → 康复 → 领养 → 结算 → 回大厅），但**领养是终点**：存档里领养完只剩一个 petId 字符串（`assets/scripts/cache/SaveCodec.ts:6`），大厅 5 个入口全是信息/合规类（`assets/scripts/ui/LobbyChrome.ts:18-24`），状态机白名单里没有任何"回到宠物身边"的状态（`docs/plan/08-客户端架构与状态机.md` §5.2）。这就是"长线目标缺失"的技术真相——不是数值不够，而是**没有承接对象**。

四个模块的推荐施工顺序：**模块一（大厅）→ 模块三（内容）→ 模块二（小屋）→ 模块四（QA）**。理由：大厅重构和小屋入口是同一处代码，先改能避免二次返工；内容扩充（配置表）是小屋的前置——小屋只有 1 只宠物时看不出价值。

## 2. 模块二：Habitat 小屋系统

### 2.1 数据结构（本地先行，云侧走 G2）

```ts
// cache/SaveCodec.ts 新增（本地存档，不受冻结清单约束，但必须能兜旧档）
interface HabitatPet {
  petId: string;
  hunger: number;        // 0-100
  cleanliness: number;   // 0-100
  mood: number;          // 0-100
  lastSettledAt: number; // 上次结算时间戳（ms）
}
interface SaveData {
  // …既有 17 字段不动
  habitat: HabitatPet[];        // 由 markAdopted 时 push 一条初值
  habitatLastSeenAt: number;    // 离线收益起算点
  habitatPendingCoins: number;  // 待领取（只读展示，不代表已入账）
  habitatClaimDay: string;      // DayKey，今日已领次数
  pettedDay: string;            // 抚摸每日 3 次上限
  pettedCount: number;
}
```

`decodeSave` 按现有 `toNumber/toNumberMap` 风格补兜底：旧档无 `habitat` → 由 `petsAdopted` 反推生成，三项属性给 70/75/60，`lastSettledAt = now`（**不给历史时间，避免旧档一上线就白拿一大笔**）。

### 2.2 数值节奏（对齐 07 §2 产消曲线）

| 参数 | 取值 | 依据 |
|---|---|---|
| 起始值 | hunger 70 / cleanliness 75 / mood 60 | 领养时照料分 `careScore` 高则 +10（复用 `pets.careScore`） |
| 衰减 | hunger -6/h、cleanliness -4/h、mood -5/h；hunger<30 或 cleanliness<30 时 mood 额外 -10/h（W22-4 已落地，阶段倍率见 §2.2.1） | 一天 2–3 次互动即可维持，不做"必须准点上线" |

| 喂食 | 30 金币 → hunger +30 | 单局奖励 200–450，一次病例可喂 6–15 次 |
| 高级粮 | 8 爱心 → hunger +70 | 爱心保持稀缺用途（05 §9：爱心 5–20/单局消耗） |
| 洗澡 | 20 金币 **+ 5 爱心** → cleanliness +35 | 2026-11-03 决策-4：在原口径「20 金币」上追加 5 爱心，让洗澡与高级粮共用爱心这条稀缺通道，避免金币单币过暖；**代码已按此实现**。 |
| 抚摸 | **免费**，mood +10，每日 3 次 | 留一条零成本回访理由；次数是**全局**计数（§2.1 `pettedDay` / `pettedCount`），不是每只宠物各 3 次 |
| 离线产出 | 每只 4 金币/h × mood 系数（≥70:1.2 / 40-69:1.0 / <40:0.5），单次上限 6h | 3 只满配 = 86 金币/次，日 2 次 ≈ 172，占 D1-D3 产出（1000-1400）约 **15%**，不破坏 `07` §5 曲线 |
| 硬约束 | **宠物不会死、不会离开**，最差只是 mood<40 → 动画降级 + 产出减半 | `07` §5 原话：回收点必须"可延迟"，不能卡住核心循环 |

### 2.2.1 生命周期阶段倍率（W22，2026-11-03 决策-3 增补）

年龄是本方案的**展示 + 体感层**，不是第二套经济系统：阶段只改互动数值与 UI 标签，不改离线收益计价（红线 G4），不触发死亡或离开（沿用 §2.2 硬约束）。

| 参数 | 取值 | 说明 |
|---|---|---|
| 时间口径 | **现实自然日**，不引入加速倍率 | 2026-11-03 拍板。`expectedLifespanDays` / `maturityAgeDays` / `seniorAgeDays` 三个字段单位一律是"自然日"。 |
| 展示换算 | 1 现实日 = 1 宠物月（12 宠物月 = 1 宠物岁） | **纯展示换算，不改变任何推进速度**；目的是让"300 天寿命"读起来是"陪伴了 25 年"而不是"25 天"。 |
| 阶段判定 | 年龄日 < `maturityAgeDays` → 幼年；< `seniorAgeDays` → 成年；否则 → 老年 | 三个阈值全部来自 `config/pets.json`（v4），禁止 `if (petId === 'pet_corgi')` 式硬编码；缺省由 `AgeSystem.DEFAULT_LIFESPAN`（500/120/400）兜底。 |
| 幼年倍率 | hunger 衰减 ×1.5、mood 衰减 ×1.2、cleanliness ×1.0 | 需要更频繁喂食与逗弄。 |
| 成年倍率 | 全 ×1.0（即 §2.2 基准线） | 基准档。 |
| 老年倍率 | 衰减 ×1.0，但互动产生的 mood 收益 ×0.5（抚摸 +10 → +5，四舍五入且不低于 1） | "跑不动了"只削收益、不增加消耗频次；飘字按实际收益显示，不写死 +10。 |
| 老年小毛病 | 每日按 `hash(petId + dayKey)` 确定性抽取，命中时该次互动额外消耗 3 爱心安抚 | 用确定性 hash 而非 `Math.random`，保证同一天重进小屋表现一致、截图可复验。 |
| 寿命进度条 | `clamp(年龄日 / expectedLifespanDays, 0, 1)`，满格后**停在 1.0 不再增长** | 语义是"陪伴了多久"，不是"还剩多久"；不老不死，所以进度条永远不指向终止。 |
| 补算时机 | 进小屋 + 每次互动前，按 `lastDecayAt` 与当前时间一次性补算，**单次最多补 24 小时**（`MAX_SETTLE_HOURS`） | **不挂 `setInterval`**：小游戏切后台会被挂起，定时器不可靠。水位只按整小时前移，零头留到下次；老档回填 `lastDecayAt = now`，不追溯扣属性。 |
| 存储 | `birthTimestamp` / `lastDecayAt` / `soothedDay` 进本地存档 `habitat` 条目（偏差 D19） | 本地时间戳可被改机时操纵，已接受：年龄不进经济，不作权威依据。老档按 `adoptedAt` 回填生日，回填不到取 `now`。 |

## 7. 动效规范（motion-apply 交付，供模块二实施直接消费）

> 路径说明：本工程是 Cocos Creator 3.8 + TypeScript，运行在 wechatgame，**没有 DOM / React**，
> React Bits 组件安装路径（`npx shadcn add @react-bits/*`）与 CSS keyframes 全部不可用。
> 因此本节按动效开发 Skill 的「直接写」分支产出**引擎原生 tween 规格**，
> 全部落在已有的 `PetBehavior` / `UIButton` / `Tokens.DURATION` 体系内，不新增动画库。

**调性锚点**：Playful（治愈系养成），但受两条既有纪律压制——
① 角色动效不能抢过页面主操作（`PetBehavior.ts` 头部自述预算：缩放 ≤1.06、旋转 ≤4°、位移 ≤12px）；
② 菜单/资源条这类"操作外壳"禁止持续循环动效（走查 audit-11：视觉焦点分散），只用状态变化触发的一次性过渡。

**签名缓动**：`sineOut` 用于反馈收尾，`backOut(1.4)` 只用于宠物互动（有肉感），UI 外壳一律 `quadOut`；
所有时长从 `Tokens.DURATION` 取值，不在动效代码里写魔法数字。

| # | 目标 | 触发 | 属性曲线 | 时长 | 落地位置 |

| M1 | 宠物立绘（点选） | touch-start | scale 1.00→0.96 | `press` 0.12 quadOut | `Habitat.ts` 命中区，复用 `UIButton` 的按压约定 |

**降级与合规**：
- `Quality.low` 为真时 M1–M9 全部只保留 opacity 与 scale 端值（不跑 backOut、不跑数字滚动），与 `PetBehavior.ts:78`、`PetVisualChrome.ts:16` 的既有低档分支同构。
- 减量偏好（微信端等价于低端机/省电模式）：不引入常驻 `repeatForever`；当前工程里唯一的常驻循环是宠物呼吸与阴影呼吸，它们是"内容"而非"外壳"，且已被 `Quality.low` 关闭——本节不新增任何常驻循环。
